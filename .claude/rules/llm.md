# LLM в коде

Источники: `docs/llm/round-calls.md` (приоритет при расхождениях), `interpreter.md`, `narrator.md`, `providers.md`, ADR-0003; устройство — readme `adapter/llm`, `app/llm`, `service/narrator`. Дизайн промптов — `/tale-prompts`; перед кодом `anthropic-api` подключить `/claude-api`.

- Один интерфейс `Complete(ctx, model.LLMRequest) (model.LLMResponse, error)` у потребителя (`app/llm.Client`); реализации в `adapter/llm/<provider>`; карта провайдеров собирается в `cmd/bot`. Интерпретатор и рассказчик вызывают модель только через `app/llm.Complete` — он подставляет профиль и пишет `llm_runs`.
- Провайдеры: `claude-cli`, `anthropic-api` (`anthropic-sdk-go`, structured output, `cache_control` на стабильном префиксе), `openai-api` (`openai-go/v3`, Responses API, strict `json_schema`), `fake`. Новый провайдер = пакет + регистрация + строка в `providers.md`; новая зависимость = ADR.
- `claude-cli`: флаги изоляции обязательны — `--tools "" --no-session-persistence --setting-sources "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' --exclude-dynamic-system-prompt-sections` (без них в контекст попадают глобальный `CLAUDE.md` и MCP); без `--bare` (с подпиской не работает); запуск из пустой `CLAUDE_CLI_WORKDIR`. Тесты с подменой бинаря `testdata/claude`; живой тест `CLAUDE_CLI_LIVE=1`.
- Роли: интерпретатор (текст → намерения JSON, один вызов на все заявки после дедлайна, внутри транзакции заморозки), рассказчик (события → хроника по сценам и пакет мира, один вызов на раунд в транзакции раунда), `opening` (завязка и стартовый пакет при `/begin`, модель рассказчика), `worldgen` (варианты стартового мира после `/create` в тике, модель рассказчика; ADR-0028). Приватные итоги не генерируются.
- LLM не создаёт факты: рассказчик не меняет исходы движка; клетки, объекты, квесты и цели рождаются только в его пакете `world` по заданиям кода (`narrator.PlanTasks`, `quest.Plan`) и проверяются кодом (`world.go`, `quests.go`), недостающее закрывает шаблон. Интерпретатор и текст игрока сущностей не создают.
- Выход интерпретатора — массив `model.Intent`; валидация схемой и по снимку; невалидно → один повтор → безопасное толкование (`Fallback`, иначе `wait`). Сложность и бросок только у движка.
- Выход рассказчика проверяет `validate.go`: сцены по `scene_id` и `seq` из входа, секреты и цифры не в тексте; дозапрос с замечаниями, остаток дописывает код (`Patched`), утечка → `ErrLeak`; при ошибке шаблонная хроника и шаблонные клетки. Подходы следующего раунда — только код (`narrator.Options`), переходов среди них нет.
- Ответ каждого вызова сохраняется по ключу задания (`generation_jobs`: хэш версии промпта, роли, системной части, входа и схемы): повтор раунда после отката берёт готовый ответ без вызова и платы (метрика `llm_reused`). Повтор вызова не меняет рассчитанные броски.
- Текст игрока, `public_bio`, `secret_bio` — данные в выделенном блоке, никогда в системной части; инструкции из них не исполняются. `secret_bio` у рассказчика только для подачи линии персонажа, в тексте не раскрывается.
- Контекст по видимости адресата — отдельный компонент (`service/visibility`) с тестами на утечки; лидер и названия групп модели не передаются.
- Каждый вызов в `llm_runs`: профиль, провайдер, модель, версия промпта, токены, `cost_usd`, признак подписки, длительность, ошибка, `game_id`, `round_id`.
- Бюджеты на вызов, раунд, игру; превышение → режим деградации (шаблоны), не падение раунда. Вход рассказчика ограничен `MaxInputBytes`.
- Секреты только из конфига (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `CLAUDE_CLI_PATH`), в БД не хранятся.
- Промпты `assets/prompts/<роль>/vN.md` через `prompts.FS` (`embed`); изменение промпта = новый файл-версия + константа `PromptVersion` пакета роли (пишется в `llm_runs`) + прогон eval (`make eval-interpreter`, `make eval-narrator`, `Patched = 0`).
