# LLM в коде

- Источник: `docs/llm/round-calls.md` (приоритет при расхождениях: два вызова на раунд, входы и выходы), `docs/llm/providers.md` (интерфейс `llm.Client`, провайдеры, профили), ADR-0003. Дизайн промптов: `/tale-prompts`.
- Один интерфейс `Complete(ctx, model.LLMRequest) (model.LLMResponse, error)` у потребителя (`app/llm.Client`); реализации в `internal/adapter/llm/<provider>`; карта провайдеров по ключу собирается в `cmd/bot`; выбор профиля `app/llm.Resolve`: игра → `app_settings.default_llm_profile`; интерпретатор и рассказчик вызывают модель только через `app/llm.Complete(ctx, Call, req)` — он подставляет модель и параметры профиля и пишет `llm_runs`.
- Провайдеры: `claude-cli`, `anthropic-api`, `openai-api`, `fake`. Новый провайдер = пакет + регистрация + строка в `providers.md`; новая зависимость = ADR.
- `claude-cli`: `claude -p --output-format json --json-schema … --system-prompt … --tools "" --no-session-persistence --setting-sources "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' --exclude-dynamic-system-prompt-sections` (флаги изоляции проверены: без них в контекст попадают глобальный CLAUDE.md и MCP); без `--bare` (с подпиской не работает); запуск из `CLAUDE_CLI_WORKDIR` (пустая папка); таймаут и параллелизм из профиля; `structured_output`, `usage`, `modelUsage`, `total_cost_usd` из ответа; `subscription=true` в `llm_runs`. Тесты с подменой бинаря `testdata/claude`; живой тест `CLAUDE_CLI_LIVE=1`.
- `anthropic-api`: перед кодом подключить `/claude-api`; `anthropic-sdk-go`, structured output через `output_config.format`, `cache_control` на стабильном префиксе. `openai-api`: `openai-go/v3`, Responses API, `json_schema` strict.
- Две роли, два промпта, две схемы: интерпретатор (текст → намерение JSON) и рассказчик (события → хроника в группу и пакет мира по заданиям кода, один вызов на раунд; приватные итоги исключены решением руководителя 2026-10-10). Рассказчик не меняет факты движка; новые клетки и объекты рождаются только в его пакете `world` по заданиям (`narrator.PlanTasks`), проверяются кодом (`world.go`: клетки и соседи из заданий, лимиты, подходы по модели персонажа), остаток закрывает шаблон (ADR-0019; интерпретатор и текст игрока сущностей не создают). Квесты (пункт 28, ADR-0020): задания `service/quest.Plan` идут в `generate.quests` (новые квесты, размещения этапов, цели) и блок `quests` (активные для подсказок), ответ `world.quests`, `world.stages`, `world.goals` проверяет `narrator/quests.go` (фракция из задания, этапы по типу, каталог условий, условие этапа только достижимое подходом клетки; шаблон: сюжетный из `genres.template.story_quest`, этап «след», побочный ждёт). Плюс один вызов на игру вне раунда — завязка и стартовый пакет при `/begin` (роль `opening` на модели рассказчика, `narrator.Opening`, промпт `narrator/opening-v4.md`, схема `{text, factions[{code, goal, quest}], start, neighbors}` (соседи с `visible`, `distant_view`), вход только с открытыми данными персонажей; сбой → сцена и клетка шаблона жанра, соседи «Неизведанные земли», цели и квесты из шаблона; текст в `games.opening_scene` и первой строкой выжимки хроник; ADR-0018, ADR-0019, ADR-0020).
- Ответ каждого вызова сохраняется по ключу задания (`app/round.complete` → `generation_jobs`: хэш версии промпта, роли, системной части, входа и схемы; запись через пул вне транзакции): повтор раунда после отката берёт готовый ответ без `llm_runs` и платы (метрика `llm_reused`).
- Выход интерпретатора — массив намерений по `model.Intent` (`submission_id`, `action_type`, `target`, `approach_idx` либо `attribute`/`skill`/`risk`/`on_success`/`on_fail`, `push`, `ambiguities`, `fallback`), один вызов на все заявки раунда после дедлайна; валидация схемой и по снимку; невалидно → один повтор → безопасное толкование (`fallback`, иначе `wait`; G3). Сложность и бросок только у движка.
- Текст игрока — данные в выделенном блоке, никогда в системной части; инструкции из него не исполняются. Это же для `public_bio` и `secret_bio` персонажа; `secret_bio` в контексте рассказчика только как данные для подачи линии персонажа и в тексте не раскрывается.
- Контекст по видимости адресата отдельным компонентом с тестами на утечки.
- Каждый вызов в `llm_runs`: профиль, провайдер, модель, версия промпта, токены, `cost_usd`, признак подписки, длительность, ошибка, `game_id`, `round_id`.
- Бюджеты на вызов, раунд, игру; превышение → режим деградации (шаблоны), не падение раунда. Повтор вызова не меняет рассчитанные броски.
- Секреты только из конфига (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `CLAUDE_CLI_PATH`), в БД не хранятся.
- Промпты `assets/prompts/<роль>/vN.md` через пакет `assets/prompts` (`prompts.FS`, `embed`); версия — константа пакета роли (`interpreter.PromptVersion`, `narrator.PromptVersion`), пишется в `llm_runs`. Интерпретатор: `service/interpreter` (`BuildInput`: выходы по направлениям `to` = `north`/`south`/`west`/`east` с подписью «на север: Лес»; `Schema`, `validate.go`: `move` нормализуется в направление; `Fallback`), промпт `interpreter/v3` (переход в скрытого соседа по направлению или примете, имя не угадывается; ADR-0025), вызов из `app/round.interpret` внутри транзакции заморозки (ADR-0010); eval `make eval-interpreter`.
- Рассказчик (ADR-0011, ADR-0016, ADR-0019): `service/narrator` (`BuildInput` из состояния после свёртки и `visibility.Public`: сцена — группа в локации или персонажи без группы в локации, `scene_id`, координаты, стадия, выходы по направлениям с карточками соседей, лидер не передаётся; блок `generate` с заданиями, лимитами и ключами модели персонажа при наличии заданий; `Schema` `{chronicle, scenes[{scene_id, text, event_seqs}], world{cells, neighbors, quests, stages, goals}}` (промпт `narrator/v7`: названия групп модели не передаются и в хронике не показываются, решение руководителя 2026-10-13; скрытый сосед в `exits` — `hidden` и `distant_view` без имени, карточки соседей с `visible` и `distant_view`, ADR-0025), код подставляет локацию и внутреннюю подпись «Группа (Локация)» в `NarrationScene.Party`; `validate.go`: сцены по `scene_id` и `seq` из входа, пара перехода — одно упоминание, секреты не в тексте, без цифр в «повествовании»; дозапрос с замечаниями, остаток дописывает код в `Narration.Patched`, утечка → `ErrLeak`; бюджет `MaxInputBytes`; `world.go`: `validateWorld` по заданиям без дозапроса, `TemplateWorld`), вызов из `app/round.narrate` в той же транзакции; при ошибке шаблонная хроника `chronicleText` и шаблонные клетки; принятый пакет пишет `app/round.applyWorld` событиями `cell_generated`, `object_created`, квесты — `applyQuests` приватными событиями фракции. Подходы следующего раунда — только код (`narrator.Options`, `OptionsText`; переходов среди вариантов нет, B36), модель их не меняет. Ответ хранится в `rounds.narration`, последние 3 — выжимкой в следующий вызов. Eval `make eval-narrator` (`Patched = 0`, запрещённые подстроки, никнеймы, ожидания к пакету мира).
