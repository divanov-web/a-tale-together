# Telegram

- Библиотека `github.com/go-telegram/bot` (ADR-0004). Long polling в разработке; webhook позже.
- Каждый update сначала дедуплицируется по `update_id`, затем обрабатывается.
- Бот не пишет пользователю первым: приватный канал появляется после `/start` или deep link; без него игрок к игре не допускается.
- Контекст команды: групповой чат → `chats` по `telegram_chat_id` → незавершённая игра чата; приватный чат → активная игра пользователя, при нескольких явный выбор. `chat_id` лички равен `telegram_id` пользователя.
- Update `my_chat_member` обрабатывается: добавление бота в группу регистрирует чат и владельца, удаление помечает `bot_status` (ADR-0007). Права на команды чата и игры в группе (`/mod /owner /create /begin /pause /finish /season`): владелец и модераторы чата.
- Ответы на команды синхронно через `Sender` (ADR-0006). Игровые тексты (хроника, уведомления о заявке и игре, личное «раунд открыт» с вариантами) только через `messages_outbox`: запись в транзакции, отправка воркером, хранение `message_id`, повтор при неопределённом исходе без дублей.
- Длинные тексты делятся по лимиту Telegram при постановке в outbox (`app/round.splitParts`, часть = строка `messages_outbox` с `part`, подпись «(продолжение)»; ADR-0011), адаптер текст не делит; в сообщениях группы подпись «Раунд N» без названия мира (B9), название остаётся в стартовой сцене, финальной хронике, `/status` и личных уведомлениях.
- Лимит частоты и длины входящих: спам не доходит до LLM.
- Ошибки отправки классифицирует адаптер (ADR-0013): окончательный отказ Telegram → `model.ErrSendRejected` (outbox `failed` сразу), 429 → `model.RetryAfterError` (отсрочка прохода), остальное временная ошибка с повторами; `app/delivery` SDK не импортирует.
- Входящие приходят как `model.Incoming` (команда без `@bot`, чужие `/cmd@other_bot` отброшены адаптером).
- Игровые сообщения только при событии (стартовая сцена, открытие и закрытие раунда, пауза, в том числе автопауза после `pause_after_skipped` пропусков, B11) через outbox; каждое с номером раунда. Формат текстов (B16): заголовок отдельной строкой, пустая строка между заголовком, телом, списками и подсказкой, списки через «•», в карточках одно поле на строку; эталоны в `app/round/texts_test.go` и `app/bot/templates/templates_test.go`; разметка Telegram (`parse_mode`) не используется. Пропущенный без кворума раунд в prod не анонсируется, причина простоя видна в `/status`; в `APP_ENV=dev` в группу уходит «Недостаточное количество участников. Раунд пропущен» (решение руководителя 2026-10-10, ADR-0009).
- Команды MVP: `/ping /help /status` везде; группа `/chat /mod /owner /create /begin /pause /finish /season /act` и `/next`, `/replay`, `/round`, `/reset` только в dev; личка `/start /me /join /games /set /character /create /bio /secret /cancel /party /act /journal`; текст без команды в личке вне диалога — заявка, как `/act` (B17). Реестр `docs/architecture/telegram-commands.md` обновляется вместе с кодом; новая команда — запись в `app/bot/router.go` с контекстами и `needsChat` и строка в руководстве игрока `guide/commands.md` (группа или личка, по правилу `rules/guide.md`).
- Имя команды — одно слово (решение руководителя 2026-10-10): действие уточняется первым аргументом (`/mod add @user`, `/party join <имя>`), не подчёркиванием; одно имя в группе и личке допустимо, если действие в каждом контексте очевидно (`/create`: мир в группе, персонаж в личке; `groupDesc` в реестре). `/start` занят Telegram, поэтому запуск кампании — `/begin`.
- Inline-кнопки только как дубликаты команд (ADR-0015): данные кнопки `model.CallbackCommand` (`/команда аргументы`, тот же маршрут `Handle`) или `model.CallbackAnswer` (`@шаг ответ` диалога, только на этом шаге); адаптер разбирает в `Incoming.Callback` и отвечает `answerCallbackQuery` без текста; после нажатия клавиатура снимается, кроме отказа в правах; вариант сцены на кнопке — `round.OptionRef` (`/act #раунд:локация:объект:подход`); клавиатура игровых сообщений в `messages_outbox.keyboard`; reply-клавиатура не используется; новая кнопка без команды в реестре не добавляется. У команды объявлены контексты (группа, личка, оба); в чужом контексте — подсказка. Меню `setMyCommands` из реестра (B20): личка — все команды без `hidden`; группа для всех — без `adminOnly` (`/help /status /act`); владелец и модераторы чата — полное групповое меню областью `chat_member` (`Service.Menu`, `syncMemberMenu` при старте, `my_chat_member`, регистрации чата командой, `/mod`, `/owner`; снятие `deleteMyCommands`); `/help` показывает всё (`Service.Commands`); ошибки меню только в лог.
- Обработчики в `internal/app/bot` тонкие: разбор команды → сценарий → ответ; игровой логики нет. Ошибки для игрока — сентинелы сценариев в `userErrors`; диалоги в личке хранят шаг и черновик в таблице `dialogs` (ADR-0008); тесты сценариев на `adapter/postgres/fake`.
