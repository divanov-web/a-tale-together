# Telegram

- Библиотека `github.com/go-telegram/bot` (ADR-0004). Long polling в разработке; webhook позже.
- Каждый update сначала дедуплицируется по `update_id`, затем обрабатывается.
- Бот не пишет пользователю первым: приватный канал появляется после `/start` или deep link; без него игрок к игре не допускается.
- Контекст команды: групповой чат → `chats` по `telegram_chat_id` → незавершённая игра чата; приватный чат → активная игра пользователя, при нескольких явный выбор. `chat_id` лички равен `telegram_id` пользователя.
- Update `my_chat_member` обрабатывается: добавление бота в группу регистрирует чат и владельца, удаление помечает `bot_status` (ADR-0007). Права на `/game_*` и `/chat_*`: владелец и модераторы чата.
- Ответы на команды синхронно через `Sender` (ADR-0006). Игровые тексты (хроника, приватные итоги, уведомления игры) только через `messages_outbox`: запись в транзакции, отправка воркером, хранение `message_id`, повтор при неопределённом исходе без дублей.
- Длинные тексты делятся по лимиту Telegram; название мира и номер раунда в каждом игровом сообщении.
- Лимит частоты и длины входящих: спам не доходит до LLM.
- Входящие приходят как `model.Incoming` (команда без `@bot`, чужие `/cmd@other_bot` отброшены адаптером).
- Команды MVP: `/ping` везде; группа `/chat /chat_mod /chat_owner /game_create /game_start /game_pause /game_status`; личка `/join /character /act /journal /games`. Реестр `docs/architecture/telegram-commands.md` обновляется вместе с кодом.
- Только слеш-команды; кнопки и callback-запросы не реализуются до пункта плана 14. У команды объявлены контексты (группа, личка, оба); в чужом контексте — подсказка. Меню `setMyCommands` по контекстам из реестра.
- Обработчики в `internal/app/bot` тонкие: разбор команды → сценарий → ответ; игровой логики нет.
