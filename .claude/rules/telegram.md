# Telegram

Источники: реестр команд, кнопок и меню `docs/architecture/telegram-commands.md` (обновляется вместе с кодом), руководство `guide/commands.md`; устройство — readme `adapter/telegram`, `app/bot`, `app/delivery`, `app/round`.

- Библиотека `github.com/go-telegram/bot` (ADR-0004); long polling, webhook позже.
- Каждый update сначала дедуплицируется по `update_id`, затем обрабатывается. Входящие приходят как `model.Incoming` (команда без `@bot`, чужие `/cmd@other_bot` отброшены адаптером). Лимит частоты и длины входящих: спам не доходит до LLM.
- Бот не пишет пользователю первым: приватный канал появляется после `/start` или deep link; без него игрок к игре не допускается.
- Контекст команды: групповой чат → `chats` по `telegram_chat_id` → незавершённая игра чата; личка → активная игра пользователя, при нескольких явный выбор. `chat_id` лички равен `telegram_id` пользователя.
- `my_chat_member`: добавление бота в группу регистрирует чат и владельца, удаление помечает `bot_status` (ADR-0007). Команды чата и игры в группе — владельцу и модераторам чата; права проверяет код, меню лишь подсказка.
- Ответ на команду — синхронно через `Sender` (ADR-0006); долгую работу команда не ждёт: `/begin yes` и `/finish yes` только меняют статус, работу делает тик планировщика (ADR-0024). Игровые тексты (хроника, уведомления, «раунд открыт») — только через `messages_outbox`: запись в транзакции, отправка воркером, хранение `message_id`, повтор без дублей.
- Игровые сообщения только по событию игры, каждое с номером раунда; в группе подпись «Раунд N» без названия мира. Пропуск раунда без кворума анонсируется только в `APP_ENV=dev` (ADR-0009).
- Длинный текст делится по лимиту Telegram при постановке в outbox (`app/round.splitParts`, подпись «(продолжение)»), адаптер не делит.
- Формат текстов: заголовок отдельной строкой, пустые строки между блоками, списки через «•», в карточках одно поле на строку, `parse_mode` не используется; эталоны — `app/round/texts_test.go`, `app/bot/templates/templates_test.go`.
- Ошибки отправки классифицирует адаптер (ADR-0013): окончательный отказ → `model.ErrSendRejected` (outbox `failed`), 429 → `model.RetryAfterError`, остальное — временная ошибка с повторами; `app/delivery` SDK не импортирует.
- Имя команды — одно слово, действие уточняется первым аргументом (`/mod add @user`), не подчёркиванием; одно имя в группе и личке допустимо, если действие очевидно в каждом контексте. `/start` занят Telegram, запуск кампании — `/begin`.
- Новая команда: запись в `app/bot/router.go` с контекстами и `needsChat`, строка в реестре и в `guide/commands.md`; меню `setMyCommands` строится из реестра (личка без `hidden`, группа без `adminOnly`, полное меню владельцу и модераторам областью `chat_member`). В чужом контексте — подсказка; текст без команды в личке вне диалога — заявка.
- Inline-кнопки только дублируют команды (ADR-0015): `model.CallbackCommand` (`/команда аргументы`, тот же маршрут) или `model.CallbackAnswer` (ответ шага диалога); адаптер отвечает `answerCallbackQuery` без текста; после нажатия клавиатура снимается. Кнопка без команды в реестре не добавляется, кроме кнопок-ссылок (ADR-0022).
- Кнопки сцены — только подходы объектов (`round.OptionRef`); кнопок и строк переходов нет (ADR-0025): переход пишется текстом, соседей показывает `/scout`. Reply-клавиатура только в личке, набор по статусу игрока (`app/bot/keyboard.go`, ADR-0021); 4–6 кнопок на ситуацию, больше — с обоснованием.
- Игрокам не показываются названия групп (`/party`, `/character`, `/status`, хроника) и лидер группы (ADR-0016, ADR-0017); `/party` — только карточка без кнопок, группы назначает код.
- Обработчики в `app/bot` тонкие: разбор → сценарий → ответ; игровой логики нет. Ошибки игроку — сентинелы сценариев в `userErrors`. Диалоги лички хранят шаг и черновик в `dialogs` (ADR-0008), другие команды диалог не сбрасывают; настройка мира — статус `setup` до конца диалога (ADR-0023). Тесты сценариев на `adapter/postgres/fake`.
