# Документация

- Язык русский; термины по глоссариям: игровые в `docs/game/glossary.md`, технические в `docs/glossary.md`; термин, встретившийся в двух файлах, добавляется в глоссарий. Неудачный термин руководителя Claude заменяет на общепринятый везде и фиксирует замену в колонке «Было» и в отчёте.
- Строгий Markdown: заголовки и краткие тезисы, таблицы вместо абзацев, без вводных слов. Один файл — одна тема.
- Относительные ссылки `[Название](путь.md)`; индекс `docs/README.md` обновляется при добавлении файла.
- Readme пакета (`readme.md` строчными): назначение, зависимости, публичный вход, связи. Обновляется в той же задаче, что и код.
- ADR в `docs/decisions/NNNN-<тема>.md` по `_template.md`; статусы `предложено | принято | заменено`. Принятое решение не правится задним числом: новый ADR со ссылкой на старый.
- `docs/concept/` не источник правды (решение руководителя 2026-10-10): источник — `docs/` и код. В концепт смотрят только за нереализованными механиками; при реализации механика адаптируется под реальный проект, переносится в профильный документ и удаляется из концепта. Ссылки на номера разделов концепта не используются; расхождения с реализацией — в `docs/game/open-questions.md`.
- План `docs/plan/`: главный файл с крупными пунктами, файл-скелет на пункт по `_template.md`; шаги и статусы правятся по ходу работы, новый пункт — строка в главном файле + файл. Большая стори — подпапка `docs/plan/<стори>/` со своим `README.md` и префиксом номеров (`i-`, `w-`), в главном файле только ссылка.
- Устаревшее удаляется, не помечается; история в git.
