# Игровой движок

- Чистые функции: вход — снимок состояния, разобранные намерения, источник случайности; выход — события и результаты заявок. Без I/O, времени и LLM.
- Детерминизм: один seed на раунд; каждый бросок записывается в событие (`param`, `roll`, `difficulty`, `chance_pct`, `pushed`, `outcome`); повтор с тем же снимком даёт тот же результат.
- Каждая заявка получает ровно один статус: `resolved | rejected | deferred | ambiguous`, и ссылки на события. Полнота проверяется кодом и тестом.
- Порядок разрешения задают правила (фазы, инициатива), не порядок приёма сообщений.
- Конфликтные группы: действия над одной сущностью или ресурсом разрешаются вместе; единственная запись результата. Совместные действия и `help` только внутри `party_id` (`sameParty`, отказ с объяснением); между группами — встречные проверки.
- Группы (пункт 19, ADR-0016, S14): переходы участников сверяются после фазы перемещения (`settleMoves`, заявки копятся в `proposals`); расхождение → большинство остаётся исходной группой, остальные становятся новыми группами `party_split` (id из `snapshot.new_party_ids`, имя `party.NextName`, лидер по наибольшей Воле) в пределах `max_parties` (он же лимит занятых локаций: группа обязательна и держит одну локацию, ADR-0017); блокировка лимитом → одно `party_held` на группу: все идут за лидером (без лидера — за большинством), заявки на другое направление получают исход `held`, участники без заявки уходят с группой. Персонаж без группы — запасной путь (перемещается свободно). Лидер скрыт: `Describe` его не называет. Чистые правила групп — `service/party`.
- Сетка (пункт 27, ADR-0019, S16): клетка — `x`, `y`, `stage` (`card` | `detailed`), `visited`, `start`, `discovered_by`; выходы считает код по соседям (`RoundSnapshot.Exits`, `ExitTo`: направление словом `model.ParseDirection` или имя соседа; движок добавляет сопоставление по основе слов `matches`); `move` только к существующему соседу, отказ с перечнем выходов по сторонам света. Первый вход персонажа фракции в клетку (кроме стартовой) — приватное `cell_discovered` с фракцией, свёртка добавляет фракцию в `discovered_by`; `Apply` понимает события пакета мира `cell_generated` (создать или детализировать клетку) и `object_created` — их создаёт сценарий раунда после вызова рассказчика, движок их не порождает. Снимок v4 содержит только занятые клетки и их соседей.
- Квесты (пункт 28, ADR-0020, S17): чистые правила в `service/quest` — `Plan` (новый квест по счётчику открытий и лимитам, привязка первого незакрытого этапа по расстоянию, пересмотр цели), `Check` (условия `object_state` / `fact` / `visited` по снимку после свёртки), шаблоны; квесты не входят в снимок, события пишет сценарий раунда (`app/round.checkQuests`, `applyQuests`), `engine.Apply` сворачивает `quest_stage_done` (награда `reward.fact` в знания адресатов). Движок квестов не знает; объекты этапа — обычные объекты клетки.
- Знания персонажа фиксируются на начало раунда; условные действия ограничены каталогом.
- Сложность назначает код: подход объекта или таблица риска (`normal / hard / extreme` → 4 / 7 / 9) плюс `locations.difficulty`; LLM только классифицирует риск. Шанс = 50 + 10 × (параметр − сложность) в границах 5–95, один бросок d100 («Прямой шанс», ADR-0014); показывается игроку.
- Каталог действий и таблицы проверок — данные (`docs/game/actions.md`, `checks.md`, `character.md`); у игры есть `rules_version`.
- У каждого события видимость: `public | location | private(character_ids)`; рассказчик получает только `public` и `location`. `check_rolled`, `party_split`, `party_held` видны в локации (попытка и исход; ADR-0011, ADR-0016), `fact_learned`, `condition_added`, `hp_changed`, `character_waited`, `help_given`, `action_rejected`, `cell_discovered` — приватны; `cell_generated`, `object_created` видны в клетке; события квестов `quest_issued`, `quest_stage_placed`, `quest_stage_done`, `quest_done`, `goal_revised` — private персонажам фракции (пункт 28).
- HP 0 — «выведен из строя»; дальнейшее по `settings.death_mode` (`docs/game/death.md`): реализуется только `fake` — статус `dead`, счётчик `death_rounds_left`, события `character_died` / `character_returned`; движок персонажа не удаляет.
- Новое правило: сначала сценарий в `docs/game/scenarios.md`, затем тест, затем код.
