# Игровой движок

- Чистые функции: вход — снимок состояния, разобранные намерения, источник случайности; выход — события и результаты заявок. Без I/O, времени и LLM.
- Детерминизм: один seed на раунд; каждый бросок записывается в событие (`roll`, `modifier`, `difficulty`, `outcome`); повтор с тем же снимком даёт тот же результат.
- Каждая заявка получает ровно один статус: `resolved | rejected | deferred | ambiguous`, и ссылки на события. Полнота проверяется кодом и тестом.
- Порядок разрешения задают правила (фазы, инициатива), не порядок приёма сообщений.
- Конфликтные группы: действия над одной сущностью или ресурсом разрешаются вместе; единственная запись результата.
- Знания персонажа фиксируются на начало раунда; условные действия ограничены каталогом.
- Каталог действий и таблицы проверок — данные (`docs/game/actions.md`, `rules.md`); у игры есть `rules_version`.
- У каждого события видимость: `public | location | private(character_ids)`; рассказчик получает только отфильтрованные события.
- Новое правило: сначала сценарий в `docs/game/scenarios.md`, затем тест, затем код.
