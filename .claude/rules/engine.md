# Игровой движок

- Чистые функции: вход — снимок состояния, разобранные намерения, источник случайности; выход — события и результаты заявок. Без I/O, времени и LLM.
- Детерминизм: один seed на раунд; каждый бросок записывается в событие (`param`, `roll`, `difficulty`, `chance_pct`, `pushed`, `outcome`); повтор с тем же снимком даёт тот же результат.
- Каждая заявка получает ровно один статус: `resolved | rejected | deferred | ambiguous`, и ссылки на события. Полнота проверяется кодом и тестом.
- Порядок разрешения задают правила (фазы, инициатива), не порядок приёма сообщений.
- Конфликтные группы: действия над одной сущностью или ресурсом разрешаются вместе; единственная запись результата. Совместные действия и `help` только внутри `party_id`; между группами — встречные проверки.
- Знания персонажа фиксируются на начало раунда; условные действия ограничены каталогом.
- Сложность назначает код: подход объекта или таблица риска (`normal / hard / extreme` → 5 / 7 / 9) плюс `locations.difficulty`; LLM только классифицирует риск. Шанс = 50 + 10 × (параметр − сложность) в границах 5–95, один бросок d100 («Прямой шанс», ADR-0014); показывается игроку.
- Каталог действий и таблицы проверок — данные (`docs/game/actions.md`, `checks.md`, `character.md`); у игры есть `rules_version`.
- У каждого события видимость: `public | location | private(character_ids)`; рассказчик получает только `public` и `location`. `check_rolled` видно в локации (попытка и исход; ADR-0011), `fact_learned`, `condition_added`, `hp_changed`, `character_waited`, `help_given`, `action_rejected` — приватны.
- HP 0 — «выведен из строя»; дальнейшее по `settings.death_mode` (`docs/game/death.md`): реализуется только `fake` — статус `dead`, счётчик `death_rounds_left`, события `character_died` / `character_returned`; движок персонажа не удаляет.
- Новое правило: сначала сценарий в `docs/game/scenarios.md`, затем тест, затем код.
