# Игровой движок

Источники: правила игры `docs/game/` (`rules.md`, `checks.md`, `actions.md`, `parties.md`, `world.md`, `story-goals.md`, `death.md`), сценарии `docs/game/scenarios.md`, перечень событий `docs/architecture/data-model.md` (`world_events`); устройство — readme пакетов `service/engine`, `party`, `quest`, `visibility`.

- Чистые функции: вход — снимок состояния, намерения, источник случайности; выход — события и результаты заявок. Без I/O, времени и LLM.
- Детерминизм: один seed на раунд; каждый бросок записан в событие (`param`, `roll`, `difficulty`, `chance_pct`, `pushed`, `outcome`); повтор с тем же снимком даёт тот же результат (`/replay`).
- Каждая заявка получает ровно один статус `resolved | rejected | deferred | ambiguous` и ссылки на события; полнота проверяется кодом и тестом.
- Порядок разрешения задают правила (фазы, инициатива), не порядок приёма сообщений.
- Конфликтные группы: действия над одной сущностью или ресурсом разрешаются вместе, одна запись результата. Совместные действия и `help` только внутри `party_id`, отказ с объяснением; между группами — встречные проверки.
- Группы (ADR-0016, ADR-0017, S14): группа обязательна, назначается кодом, держит одну локацию; разделение и удержание по лимиту `max_parties` решает движок после фазы перемещения; чистые правила — `service/party`. Лидер скрыт: `Describe` и контекст рассказчика его не называют.
- Сетка (ADR-0019, ADR-0025, S16, S19): `move` только к существующему соседу — по направлению словом или имени видимого соседа, имя скрытого соседа не сопоставляется; отказ перечисляет выходы по сторонам света. Клетки и объекты порождает сценарий раунда после вызова рассказчика (`cell_generated`, `object_created`), движок их только сворачивает в `Apply`. Снимок содержит только занятые клетки и их соседей. Логово сил зла (ADR-0031, S22): координаты у фракции `evil` (`Faction.Lair`, один из `model.LairCorners`), клетка — обычная скрытая карточка с `/begin`; движок и интерпретатор о логове не знают, `quest.Plan` этап там не размещает.
- Квесты (ADR-0020, S17): чистые правила в `service/quest` (`Plan`, `Check`), события пишет сценарий раунда; движок квестов не знает — объекты этапа обычные объекты клетки, `Apply` лишь кладёт награду `quest_stage_done` в знания адресатов.
- Знания персонажа фиксируются на начало раунда; условные действия ограничены каталогом.
- Сложность назначает код: подход объекта или таблица риска (`normal / hard / extreme` → 4 / 7 / 9) плюс `locations.difficulty`; LLM только классифицирует риск. Шанс = 50 + 10 × (параметр − сложность) в границах 5–95, один бросок d100 (ADR-0014); показывается игроку.
- Каталог действий и таблицы проверок — данные (`docs/game/actions.md`, `checks.md`, `character.md`); у игры есть `rules_version`.
- У каждого события видимость `public | location | private(character_ids)`; рассказчик получает только `public` и `location`. Локации видны попытки и исходы проверок, разделение и удержание группы, рождение клеток и объектов; приватны личные факты, состояния, HP, ожидание, помощь, отказы, открытие клетки и события квестов (персонажам фракции).
- HP 0 — «выведен из строя»; дальнейшее по `settings.death_mode` (`docs/game/death.md`); движок персонажа не удаляет.
- Новое правило: сначала сценарий в `docs/game/scenarios.md`, затем тест, затем код.
