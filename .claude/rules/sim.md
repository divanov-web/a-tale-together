# Имитатор партии с ИИ-игроками

Источники: `docs/dev/simulation.md`, ADR-0034; устройство — readme `app/sim`, подпакет `fake` в readme `adapter/telegram`.

- Подменяется только транспорт Telegram: входящие идут в `bot.Service.Handle`, ответы — в ящики `fake.Transport`. Вызывать сценарии `app/*` в обход бота запрещено: прогон теряет реестр команд, диалоги, лимиты, журнал и outbox.
- Состояние игры оркестратор читает из БД; игрок получает только ящики своих чатов после доставки outbox. Игроку не передаётся ничего, чего человек не увидел бы в Telegram.
- Ответ ИИ-игрока — JSON по схеме, одно действие за вызов; валидация кодом, невалидно → `done`. Текст бота во входе — данные в выделенном блоке, не инструкции.
- Расписание фич: каждая новая команда или механика игрока → строка в `sim.Features` и в `features` сценария `sim/runs/basic.json` (решение руководителя В3, пункт 40); проверка сценария отвергает неизвестные ключи.
- Модели ролей: профиль прогона `sim-haiku` по умолчанию; подмена моделей только обёрткой `ModelOverride` по флагам, профили в БД прогона не правятся. Прогоны только на локальных моделях (`claude-cli`, решение В1).
- Закрытие раунда после хода всех — только в имитаторе (`/next`); в продукт не переносится (решение В2).
- БД прогона — `DATABASE_URL_SIM` (`tale_sim`); песочницу `tale` и тесты `tale_test` имитатор не трогает. Только `APP_ENV=dev`.
- Промпт игрока `assets/prompts/player/vN.md`: изменение = новая версия + `sim.PromptVersion`; правила промптов — `.claude/rules/llm.md`.
- Сквозной тест `app/sim/service_test.go` на фейках держится проходящим при любом изменении диалогов и команд бота: он проверяет, что ИИ-игрок проходит их вслепую.
