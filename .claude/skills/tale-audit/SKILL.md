# Ревизия системы промптов

Цель: промпты не теряют важное из-за объёма (жёстких лимитов нет, `rules/meta.md`) и не копят ненужное. Запуск — только по команде руководителя; Claude сам ревизию не начинает и не предлагает её в отчётах по другим задачам.

Объём по аргументу: без аргумента или `all` — все файлы системы промптов; путь или имя скилла — один файл и его `references/`. Файлы системы: `CLAUDE.md`, `.claude/skills/*/SKILL.md`, `.claude/skills/*/references/*`, `.claude/rules/*.md`. Игровые промпты `assets/prompts/**` сюда не входят — это `/tale-prompts`.

## Этапы

1. **Инвентаризация.** Команды из [references/checks.md](references/checks.md): строки и символы каждого файла, объём «всегда в контексте» (`CLAUDE.md` + `tale-team`), дата последней правки по git, файлы без правок дольше трёх месяцев. Результат — таблица в отчёте.
2. **Проверки целостности** (там же): ссылки на файлы, команды `make`, ADR и пункты плана существуют; `paths` правил указывают на существующие каталоги; карта в `tale-team/SKILL.md` и таблица в `docs/README.md` совпадают с реальным набором файлов; нижний уровень не ссылается на верхний; `description` скиллов не пересекаются по ключевым словам.
3. **Разбор содержания.** Каждый пункт файла отнести к одному классу по таблице ниже. Устаревание проверять по коду, `docs/` и `git log`, а не по памяти: пункт про команду — есть ли команда; про поле или функцию — есть ли в коде; про пункт плана — закрыт ли он (`docs/plan/telegram-done.md`, `backlog-done.md`).
4. **План правок.** Таблица «файл → пункт → класс → действие → куда переносится». Показать руководителю и ждать подтверждения. Решение руководителя (пометки «решение руководителя», ссылки на ADR, open-questions) удаляется или ослабляется только по его явному слову в этой сессии; без слова — остаётся, в плане помечается «спорное».
5. **Применение.** Правки по плану; перенос всегда раньше удаления: сначала текст появляется в `docs/`, readme пакета или `references/`, потом исчезает из промпта, со ссылкой на новое место. После правок повторить этап 2, обновить карту `tale-team` и `docs/README.md`, если менялся набор файлов.
6. **Отчёт и коммит.** Отчёт: таблица «было → стало» по размерам, что удалено и почему, что перенесено и куда, что оставлено как спорное. Коммит файлов ревизии по правилу Git главного скилла.

## Классы пунктов и действия

| Класс | Признак | Действие |
|---|---|---|
| Инвариант | принцип продукта, запрет, решение руководителя с датой или ADR | Оставить; сжать формулировку без потери смысла |
| Процесс | шаги цикла, когда и что подключать | Оставить; свернуть повторы в одно место, остальные — ссылкой |
| Реализация | имена функций, полей, схем, версии промптов, перечни команд, номера пунктов | Перенести в readme пакета или `docs/`, в промпте оставить ссылку |
| Устаревшее | команда, файл, пункт плана или механика уже не существуют или заменены | Удалить; если за ним стояло решение — проверить, что оно отражено в `docs/` или ADR |
| Дубль | один тезис в двух и более файлах | Оставить в файле верхнего уровня или в правиле области, остальное — ссылкой |
| Противоречие | два файла требуют разного | Побеждает более позднее решение (дата, ADR); другое исправить, в отчёте показать оба |
| Балласт | вводные слова, пояснения очевидного, история без текущего требования | Удалить |

## Сигналы разрастания

- Пункт длиннее ~300 символов или содержит перечень из пяти и более элементов — это документ, не правило.
- В промпте упоминаются даты, хеши коммитов, номера закрытых пунктов плана или бэклога.
- Пункт описывает, как устроено, а не что требуется.
- Файл не правился дольше трёх месяцев при активной работе над его областью — проверить на устаревание целиком.
- Объём «всегда в контексте» растёт от ревизии к ревизии без новых принципов — искать перемещаемое в скиллы-процессы.

## Чего не делать

- Не сокращать ради размера: ориентиры в `rules/meta.md` — повод для переноса в `references/`, не для удаления требований.
- Не менять смысл принципов продукта и правил работы Claude из `tale-team` без явного слова руководителя.
- Не трогать `docs/`, код и `assets/prompts/**` сверх переноса текста из промптов; находки по ним — строкой в `docs/plan/backlog.md`.
- Не удалять без следа: каждое удаление названо в отчёте с причиной, каждый перенос — с новым адресом.
