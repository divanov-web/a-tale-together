# Имитатор партии с ИИ-игроками

Прогон партии без людей на живой модели (пункт 40, [ADR-0034](../decisions/0034-simulation.md)): три ИИ-игрока проходят мир от создания до финальной хроники, а по журналу, транскрипту и сводке видно качество текста рассказчика, работу карты и квестов, слабые места и утечки токенов в промптах. Для Claude: скилл `/tale-sim`.

## Как устроено
Реальным остаётся всё, кроме провода Telegram: Postgres, планировщик, outbox, журнал чатов, живой LLM по профилю прогона. Транспорт подменяется в процессе (`adapter/telegram/fake`): имитатор подаёт входящие в обработчик бота и получает ответы в ящики чатов. Для бота игрок неотличим от человека: реестр команд, диалоги, кнопки, дедупликация, лимит частоты, журнал, outbox работают как в бою. Не проверяются лимиты и разметка Telegram API, права реальной группы, ссылки-приглашения.

Игроки (`app/sim`): у каждого фальшивый Telegram ID, личка и персона из сценария. На ход игрок получает непрочитанные сообщения группы и лички с кнопками, персону, фазу и задания раунда; модель отвечает одним действием JSON (команда, кнопка, текст, конец хода), код проверяет ответ и подаёт его боту. Фазы ведёт оркестратор: первый игрок — владелец группы и администратор мира (`/create`, диалог настройки с выбором варианта мира, параметры `/set`, персонаж, `/begin`), остальные входят по коду в свой раунд. Раунд закрывается командой `/next` администратора, как только все присутствующие сделали ход; `round_minutes` — страховочный дедлайн. Стоп — финальная хроника (`max_rounds`), ошибка стека или бюджет.

## Запуск
```bash
make migrate-sim                                   # один раз и после новых миграций
make sim                                           # sim/runs/basic.json: 10 раундов, haiku
make sim SIM_ARGS="-rounds 2"                      # дымовой прогон
make sim SIM_ARGS="-model-narrator sonnet"         # рассказчик, завязка и мир на sonnet, остальное по профилю
make sim SIM_ARGS="-run sim/runs/<имя>.json -profile local-claude -model-player haiku"
```
Флаги `cmd/simulate`: `-run` сценарий, `-profile` профиль LLM вместо сценария, `-model-narrator`, `-model-interpreter`, `-model-player` — модель роли поверх профиля (любая локальная модель по подписке, решение руководителя В1), `-rounds` число раундов, `-out` корень папок (`logs/sim`), `-db` DSN вместо `DATABASE_URL_SIM`. Только `APP_ENV=dev`.

Папка прогона `logs/sim/<метка>/`: `chats/` — журнал чатов прогона ([chat-logs.md](chat-logs.md)), `transcript.md` — партия по раундам глазами группы и каждого игрока (сообщения бота, действия и мысли игроков, заметки оркестратора), `summary.md` — сводка, `sim.log` — лог процесса. База `tale_sim` между прогонами не чистится: у каждого прогона своя группа и свои пользователи.

## Сценарий `sim/runs/*.json`
| Поле | Смысл |
|---|---|
| `rounds`, `round_minutes` | граница рассказа `max_rounds` и страховочный дедлайн (dev: от 2 минут) |
| `profile`, `player_model` | профиль LLM прогона (ставится глобальным по умолчанию в БД прогона) и модель ИИ-игрока |
| `players[]` | `name`, `username`, `joins_round` (0 или 1 у администратора — первого в списке), `persona` (характер и стиль), `character` (замысел персонажа) |
| `features` | раунд → фичи, которые игроки обязаны попробовать; `фича@username` — только этот игрок; каталог `sim.Features` (`scout`, `say`, `quests`, `party`, `character`, `knowledge`, `journal`, `status`, `bio`, `secret`, `appearance`, `away`, `back`, `group_act`, `hint`) |
| `setup` | параметры мира после диалога (`/set ключ значение`); `round_minutes`, `max_rounds` и `min_answers 1` (игроки входят по расписанию) ставятся всегда |
| `budget` | `max_calls`, `max_usd` по игре, включая игроков; при превышении игра завершается `/finish yes` |
| `max_actions`, `auto_faction` | действий игрока за ход раунда (4); фракция без вопроса (`good`, как в песочнице; пусто — выбор игрока) |

Правило расписания (решение руководителя В3): каждая новая команда или механика игрока добавляется в каталог `sim.Features` и в расписание сценария при закрытии пункта или строки бэклога.

## Что смотреть в отчёте
- `summary.md`, «Раунды»: заявки, запасной разбор интерпретатора и шаблон хроники (должны быть «нет»), замечания к ответам рассказчика, время раунда.
- «Вызовы по ролям» и «Рост контекста»: токены входа по ролям от раунда к раунду; рост входа интерпретатора или рассказчика без роста числа заявок и клеток — кандидат в утечки (`docs/llm/round-calls.md`, пункт 31).
- «Карта и квесты»: число клеток и посещённых, этапы квестов, цели фракций — проверка, что достройка мира и квесты срабатывают.
- `transcript.md`: интересность текста — решение руководителя; Claude готовит чек-лист: повторы и штампы, противоречия с фактами движка, упоминания квестов и целей, реакция на заявки каждого персонажа, ответы на реплики.
- Находки → строки `docs/plan/backlog.md`; результат прогона → таблица измерений в `docs/llm/README.md`.

Юнит-прогон без сети: `go test ./internal/app/sim/` — три игрока, три раунда на `postgres/fake` и сценарном фейке игрока (`SIM_DUMP=1` печатает отчёт).
