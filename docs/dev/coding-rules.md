# Стартовые правила программирования

Единый свод для кода проекта. Составлен один раз на старте; меняется через ADR или правку этого файла с обновлением `.claude/rules/go.md`. Архитектура слоёв: [layers.md](../architecture/layers.md).

## Цели
- Маленькое приложение с ясными слоями и минимумом абстракций; код читается сверху вниз.
- Детерминизм там, где решаются правила игры; воспроизводимость раунда без LLM.
- Каждое изменение проверяемо: тесты логики, `vet`, форматирование.

## Структура
- `cmd/<app>/main.go`: только сборка зависимостей и запуск; `run() error` вместо логики в `main`.
- `internal/` для всего кода приложения; `pkg/` не используется.
- Пакет = одна ответственность; имя короткое, строчными, без `util`, `common`, `helpers`.
- `readme.md` у каждого пакета-области в `internal/` (назначение, зависимости, публичный вход, связи; обновляется вместе с кодом). Подпакеты (провайдеры `adapter/llm/*`, `fake`, `templates`) описывает readme родителя; `cmd/*` — таблица слоёв `docs/architecture/layers.md`.
- Файлы по теме внутри пакета (`store.go`, `rounds.go`), не по типу (`types.go`, `interfaces.go`).

## Именование
- Экспортируемые имена без повтора имени пакета: `round.Run`, не `round.RunRound`.
- Конструктор `New(...)`; при нескольких типах `NewStore`, `NewClient`.
- Идентификаторы сущностей — именованные типы: `type GameID int64`.
- Статусы и типы действий — строковые константы с типом: `type RoundStatus string`.
- Имена тестов на английском: `TestResolve_SameItem_OneWinner`.

## Конфигурация
- Дефолты в `config.Defaults()`; `.env` и переменные окружения поверх (`caarlos0/env`, `godotenv`); приложение стартует без `.env`.
- Секреты без дефолтов; `Validate() error` на старте; `panic` в конфиге запрещён.
- Пакет получает собственную структуру настроек, а не `config.Config` целиком.
- Флаги командной строки не используются.

## Ошибки
- Оборачивать с контекстом: `fmt.Errorf("round.Run: freeze: %w", err)`.
- Сентинелы `var ErrNotFound = errors.New("...")`; проверка `errors.Is`, `errors.As`.
- Ошибку либо вернуть, либо обработать и залогировать; не оба.
- Ошибки пользовательского ввода отделены от сбоев: отдельные типы или сентинелы, из них формируются ответы игроку.

## Логирование
- `log/slog`, логгер в конструктор, глобальный не используется.
- Структурные поля: `game_id`, `round_id`, `character_id`, `update_id`; текст сообщения короткий, на английском.
- Уровни: Debug — трассировка раунда; Info — события жизненного цикла; Warn — восстановимое; Error — сбой с контекстом.

## Контекст, горутины, время
- `context.Context` первым аргументом во всём с I/O или ожиданием; отмена только через ctx.
- Фоновые циклы запускает владелец через `errgroup`; каждый завершается по ctx; `main` ждёт всех.
- Время через `Clock` интерфейс там, где от него зависит логика; `time.Now()` напрямую только в адаптерах.
- Случайность: `math/rand/v2` с явным источником и seed; в движке бросок записывается в событие.
- `time.Sleep` в логике и тестах запрещён.

## Интерфейсы и зависимости
- Интерфейс объявляет потребитель, 1–5 методов; вводится при второй реализации или тест-дубле.
- Зависимости собираются вручную в `cmd`; DI-фреймворки, глобальные синглтоны и `init()` с побочными эффектами запрещены.
- Новая внешняя библиотека — только через ADR со строкой «почему не stdlib».

## Данные
- Состояние мира меняется только событиями; прямые правки таблиц состояния вне фиксации раунда запрещены.
- Все запросы к игровым данным с `game_id`.
- Границы транзакций в сценариях (`app`), не в сервисах и не в репозиториях.
- JSONB-поля с `schema_version`; разбор в типизированные структуры в `model`.

## Комментарии и документация
- Краткий комментарий на русском к каждому экспортируемому типу, функции, полю конфига; начинается с имени: `// Resolve разрешает ...`.
- Комментарии объясняют «почему», не пересказывают код. `TODO(этап N): ...` с привязкой к roadmap.
- Документы в `docs/` обновляются в той же задаче, что и код.

## Тесты
- Обязательны для `internal/service/**` и валидации ответов LLM; адаптеры — интеграционные с тегом `integration`.
- Табличные, `t.Run`, `t.Parallel()` без общего состояния; stdlib `testing`.
- Эталонные сценарии `docs/game/scenarios.md` → тесты движка один к одному.
- LLM и Telegram в тестах не вызываются: фейки с записанными ответами в `testdata/`.

## Инструменты
- Перед завершением задачи: `make fmt`, `make lint` (`gofmt`, `go vet`, `golangci-lint` при наличии), `make test`.
- Go 1.27; версии зависимостей закреплены в `go.mod`; `go mod tidy` после изменения зависимостей.
