# i-02. Иллюстрация локации

- Статус: план
- Этап концепта: 5
- Зависит от: i-01 (конвейер художника), T3

## Цель
Группа, впервые вошедшая в локацию, получает в чат иллюстрацию по описанию локации и тону мира; картинка одна на локацию и переиспользуется.

## Критерий готовности
При первом входе группы в локацию с `images_enabled` воркер ставит задание `location`, фото приходит в группу после хроники раунда; второй вход в ту же локацию отправляет сохранённый `telegram_file_id` без нового вызова провайдера; раунд при сбое художника проходит без картинки.

## Шаги
| № | Шаг | Слой / пакеты | Артефакты | Статус |
|---|---|---|---|---|
| 1 | Триггер: событие `character_moved` первой группы в локацию → `app/image.Enqueue(kind=location, subject=location_id)`; ключ идемпотентности по локации | `app/round`, `app/image` | тест: два входа — одно задание | план |
| 2 | Промпт художника для локации: название, описание, тон мира, стиль профиля; скрытые объекты и `hidden` выходы не упоминаются | `service/artist` | тест: скрытое не утекает | план |
| 3 | Доставка: фото в группу игры подписью «Локация: название»; повтор — по `file_id` | `app/delivery` | | план |
| 4 | Команда админа `/image location <имя>` — перегенерация с новым ключом | `app/bot` | | план |
| 5 | Документы: `docs/game/models/location.md`, реестр команд, `guide/` | docs | | план |

## Проверка
Песочница с профилем `fake`: вход группы в новую локацию → заглушка в группе; повторный вход → без нового задания в `image_jobs`.

## Открытые вопросы
Картинка в группу или в личку каждому участнику группы; лимит заданий на игру в сутки (i-01, шаг 1).
