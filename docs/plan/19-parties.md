# 19. Группы персонажей

- Статус: план
- Этап концепта: 1–3
- Зависит от: 18, [группы](../game/parties.md), сценарий S14, [испытания](../game/checks.md); продолжение — пункт [23](23-party-leader-vote.md) (выбор лидера голосованием)

## Цель
Персонажи объединяются в группы с общей сюжетной линией: группа по умолчанию с первого раунда, вход новых персонажей по локации, разделение и удержание по лимиту, испытания с помощью только внутри группы. У группы есть скрытый от игроков лидер: при расхождении заявок на перемещение, когда лимит групп или локаций не даёт разделиться, движок засчитывает направление лидера, рассказчик обыгрывает выбор.

## Критерий готовности
У каждого персонажа в игре не более одной группы; в сезоне не более `max_parties` (3) активных групп; при `/begin` все персонажи в одной группе; новый персонаж попадает в группу своей локации или в новую в пределах лимита; `party_split` и `party_held` проходят сценарий S14 тестами; при `party_held` группа идёт туда, куда заявил лидер (или остаётся, если лидер не двигался), участники с другим направлением получают исход «удержан» с объяснением в хронике; лидер ни в одном сообщении игрокам не называется; `help` вне группы отклоняется с объяснением; рассказчик пишет блок на группу; `/party` показывает состав.

## Проверка
Песочница: 3 персонажа стартуют одной группой, четвёртый входит позже в локацию группы; двое уходят в другую локацию → новая группа; при трёх группах попытка разделения удерживается с объяснением в хронике; `make test`.

## Открытые вопросы
Вход в группу по согласию участников — не на этом этапе ([группы](../game/parties.md)). Что делать с группой, все участники которой `inactive` — закрывать при заморозке или держать до возврата. Начальный лидер назначается кодом (персонаж администратора, иначе первый созданный) — допущение Claude, руководитель может заменить правило; выбор лидера игроками — пункт [23](23-party-leader-vote.md).
