# 26. Имена характеристик по миру

- Статус: план (дальний)
- Этап концепта: 5
- Зависит от: 15 (шаблоны миров), 22 (прямой шанс)

## Цель
Администратор игры задаёт названия характеристик и навыков своего мира, чтобы интерпретатор подбирал свободные испытания в каноне жанра («Хладнокровие», «Связь с Силой», «Репутация»), а рассказчик описывал их теми же словами. Механика проверок не меняется.

## Что уже так (разбор кода 2026-10-12)
Характеристики — данные модели персонажа (`character_models.definition`: ключ, название, границы), движок считает параметр проверки единообразно по ключу (`rules.Param`: значение характеристики + навык + помощь); ни одна характеристика кодом не выделена. Исключения: формула HP ссылается на ключ (`4 + strength`), архетипы и подходы объектов шаблона жанра ссылаются на ключи характеристик и навыков. Название (`title`) используется только в текстах: карточка персонажа, диалог создания, контекст интерпретатора (`character_model.attributes[].title`), варианты подходов. Значит, переименование — замена названий при неизменных ключах, без правок движка; вторая модель `noir` уже показывает другой набор (`docs/game/models/character-noir.md`).

## Критерий готовности
`/set attributes` (диалог) меняет названия характеристик и навыков текущей игры до `/begin`; `/character`, диалог создания, варианты подходов и уведомления показывают новые названия; интерпретатор получает новые названия и выбирает их для свободных испытаний; ключи, границы, сумма очков, формула HP и подходы шаблона не меняются; персонажи, созданные до переименования, читаются без миграции данных.

## Шаги
| № | Шаг | Слой / пакеты | Артефакты | Статус |
|---|---|---|---|---|
| 1 | ADR: названия хранятся как переопределение у игры (`games.settings.attribute_titles`, `skill_titles`: ключ → название), модель жанра не копируется; HP и ключи неизменны | docs | ADR | план |
| 2 | Модель: `model.CharacterModelDef.WithTitles(overrides)` применяется при загрузке модели игры (`characterDef`), дальше код работает с подменёнными названиями | `model`, `app/round`, `app/bot` | тесты | план |
| 3 | Диалог `/set attributes` и команда `/set attribute <ключ> <название>` для админа; ограничения: 2–20 символов, уникальность, до `/begin` (после — только по решению руководителя) | `app/bot` | тесты | план |
| 4 | Промпты: интерпретатору названия уже передаются; добавить в системную часть правило «названия характеристик заданы миром, подбирай испытания по их смыслу»; рассказчику — те же названия в `OptionsText`; eval-случаи с нуарными названиями | `assets/prompts`, `service/narrator` | eval | план |
| 5 | Документы: `docs/game/character.md`, `docs/game/models/README.md`, реестр команд, `guide/character/` | docs, guide | | план |

## Проверка
Песочница: переименовать «Разум» в «Интуиция», создать персонажа, заявка «присматриваюсь к следам» → свободное испытание по ключу `wits` с названием «Интуиция» в уведомлении.

## Открытые вопросы
Нужен ли полностью свой набор характеристик (другие ключи и число) — это уже отдельная модель персонажа по жанру (`character_models`), не переименование; переименование после `/begin`; перевод названий навыков в подходах шаблона жанра (они строятся по ключам, названия берутся из модели — проверить при реализации).
