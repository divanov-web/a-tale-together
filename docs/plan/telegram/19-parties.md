# 19. Группы персонажей

- Статус: готово (2026-10-11)
- Этап концепта: 1–3
- Зависит от: 18, [группы](../../game/parties.md), сценарий S14, [испытания](../../game/checks.md); продолжение — пункт [23](23-party-leader-vote.md) (выбор лидера голосованием)
- Решения: [ADR-0016](../../decisions/0016-parties.md), [ADR-0017](../../decisions/0017-party-mandatory.md) (решение руководителя 2026-10-11: группа обязательна и назначается кодом, команд управления нет, один лимит `max_parties`)

## Цель
Персонажи объединяются в группы с общей сюжетной линией: группа по умолчанию с первого раунда, вход новых персонажей по локации, разделение и удержание по лимиту, испытания с помощью только внутри группы. У группы есть скрытый от игроков лидер: при расхождении заявок на перемещение, когда лимит групп или локаций не даёт разделиться, движок засчитывает направление лидера, рассказчик обыгрывает выбор.

## Критерий готовности
У каждого персонажа в игре не более одной группы; в сезоне не более `max_parties` (4, решение руководителя 2026-10-11; в разработке было 3) активных групп; при `/begin` все персонажи в одной группе; новый персонаж попадает в группу своей локации или в новую в пределах лимита; `party_split` и `party_held` проходят сценарий S14 тестами; при `party_held` группа идёт туда, куда заявил лидер (или остаётся, если лидер не двигался), участники с другим направлением получают исход «удержан» с объяснением в хронике; лидер ни в одном сообщении игрокам не называется; `help` вне группы отклоняется с объяснением; рассказчик пишет блок на группу; `/party` показывает состав.

## Проверка
`make test`, `make test-integration` (группы в `TestGameFlow`), миграции `00019` и `00020` на `tale` и `tale_test` (запущенная игра получила группу по умолчанию). Песочница (прогон условием готовности не является, решение руководителя 2026-10-11): 3 персонажа стартуют одной группой, четвёртый входит позже в локацию группы; двое уходят в другую локацию → новая группа; при трёх группах попытка разделения удерживается с объяснением в хронике.

## Решения по ходу (ADR-0016)
- Большинство остаётся исходной группой при разделении; лидер решает только при удержании (его направление); лидер, ушедший с отделившимися, заменяется преемником.
- Идентификаторы новых групп резервируются в снимке при заморозке, чтобы `party_split` был воспроизводим (`/replay`).
- Сцена рассказчика — группа в локации; персонажи без группы одной локации — одна сцена без имени; ответ модели по `scene_id` (`narrator/v3`).
- Новичок при занятом лимите входит в историю в локации ближайшей группы.
- ADR-0017 (решение руководителя после отчёта): группа обязательна, игрок её не выбирает; `max_active_locations` удалён — лимит групп и есть лимит занятых локаций; группа без присутствующих распускается, при заморозке присутствующие без группы получают её по правилу входа.

## Открытые вопросы
Вход в группу по согласию участников — не на этом этапе ([группы](../../game/parties.md)). Группа, все участники которой `inactive`, сохраняется до их возврата (лидер остаётся прежним за отсутствием присутствующих). Начальный лидер назначается кодом (персонаж администратора, иначе первый созданный) — допущение Claude, руководитель может заменить правило; выбор лидера игроками — пункт [23](23-party-leader-vote.md). Имя новой группы даёт код из шаблона жанра, а не рассказчик (принцип 1); имя от рассказчика — возможное расширение пункта 13.
