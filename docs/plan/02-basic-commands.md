# 02. Запуск бота и базовые команды

- Статус: план
- Этап концепта: 1
- Зависит от: 01

## Цель
Каркас обработки команд: маршрутизация по контексту (группа/личка), дедупликация update, регистрация пользователя, команды «обо мне» и справка.

## Критерий готовности
`/start`, `/help`, `/me`, `/ping` работают в личке; `/help`, `/ping` в группе; повторная доставка update не создаёт дублей; неизвестная команда даёт подсказку.

## Шаги
| № | Шаг | Слой / пакеты | Артефакты | Статус |
|---|---|---|---|---|
| 1 | Таблица `users` (telegram_user_id, username, first_seen, last_seen, private_chat_id) | `migrations/`, `model` | миграция | план |
| 2 | Дедупликация update: `telegram_updates` с `ON CONFLICT DO NOTHING` до обработки | `adapter/postgres`, `app/bot` | тест с повтором | план |
| 3 | Роутер команд: контекст чата, аргументы, middleware логирования и восстановления после panic | `app/bot` | `Register`, readme | план |
| 4 | `/start`: регистрация пользователя, сохранение `private_chat_id`, приветствие; deep link парсится (игра — пункт 03) | `app/bot`, `app/game` | | план |
| 5 | `/me`: кто я (id, username), в каких играх (пока пусто), активная игра | `app/bot` | шаблон ответа | план |
| 6 | `/help`: список команд по контексту; `/ping`: версия, время, задержка | `app/bot` | | план |
| 7 | Шаблоны ответов: пакет текстов с `text/template`, русский язык, без логики | `app/bot/templates` | | план |
| 8 | Лимит частоты и длины входящих сообщений (простой token bucket на пользователя) | `app/bot` | тест | план |

## Проверка
Ручной прогон команд в личке и группе; юнит-тесты роутера и дедупликации; `make test`.

## Открытые вопросы
Нужен ли отдельный `/settings` для языка и уведомлений уже сейчас (предположительно нет).
