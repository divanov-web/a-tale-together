# 06. Локальные токены: LLM через подписку Claude Code

- Статус: план
- Этап концепта: 2
- Зависит от: 05, [providers.md](../llm/providers.md), T1, T2

## Цель
Бот обращается к ИИ через единый интерфейс, первая реализация — провайдер `claude-cli` на локальной подписке Claude Max без оплаты токенов API. Профили провайдеров в БД, переключение командами владельца.

## Критерий готовности
Команда владельца `/llm test` получает структурированный JSON-ответ от `claude -p` по схеме; вызов записан в `llm_runs` с признаком подписки; профиль переключается для бота и для игры без перезапуска; при недоступном CLI бот отвечает понятной ошибкой, не падает.

| № | Шаг | Слой / пакеты | Артефакты | Статус |
|---|---|---|---|---|

| 3 | Таблицы `llm_profiles`, `app_settings`, поле `games.llm_profile_id`, таблица `llm_runs`; стартовый профиль `local-claude` в миграции | `migrations/`, `model`, `adapter/postgres` | | план |
| 4 | Выбор профиля: игра → `default_llm_profile` → ошибка конфигурации; кэш профилей с перечитыванием при изменении | `app/game`, `adapter/llm` | тесты | план |
| 5 | Команды владельца в личке: `/llm` (список и текущий), `/llm use <profile> [game_id]`, `/llm add <name> <provider> …`, `/llm test [profile]` | `app/bot` | шаблоны ответов | план |
| 6 | Запись каждого вызова в `llm_runs` (профиль, провайдер, модель, токены, `cost_usd`, `subscription`, длительность, ошибка) | `adapter/postgres`, `app/*` | | план |

## Проверка
`/llm test` в личке владельца с живым CLI; подмена бинаря в тестах; переключение профиля игры и возврат к глобальному; `make test`.
