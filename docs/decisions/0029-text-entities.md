# ADR-0029: Разметка сообщений бота через entities Telegram

- Статус: принято
- Дата: 2026-10-14
- Область: `internal/model` (`text.go`), `internal/adapter/telegram`, `internal/app/bot`, `internal/app/round` (`scout.go`); дополняет [ADR-0006](0006-command-replies.md) (ответы на команды) и [ADR-0025](0025-cell-visibility-scout.md) (`/scout`)

## Контекст
Решение руководителя 2026-10-14 (B39): в ответе `/scout` направления («на север», «на юг»…) должны быть выделены жирным, иначе список сливается. До сих пор бот отправлял только простой текст (`parse_mode` не использовался, правило `rules/telegram.md`). Ограничения: в текстах бота есть символы `<`, `&`, `*`, `_` (подсказки `/act <текст>`, названия клеток и описания от модели, текст игрока), журнал чатов и тесты сравнивают текст как есть, игровые тексты outbox хранятся в БД.

## Варианты
| Вариант | За | Против |
|---|---|---|
| `parse_mode=HTML` на всех сообщениях | привычная разметка в строках | каждая подстановка (имя клетки, текст игрока, ответ модели) требует экранирования; одна забытая — отказ Telegram на всё сообщение |
| `parse_mode=HTML` только у размеченных сообщений | экранирование локально | два режима сборки текста; текст в журнале и тестах с тегами |
| Маркеры в строке (`**жирный**`), адаптер снимает их | строится как обычный текст | те же маркеры в тексте игрока или модели меняют вид сообщения; журнал с маркерами |
| Entities Telegram отдельно от текста (выбран) | текст остаётся простым везде (журнал, тесты, БД), экранирования нет, разметка в модели без знания Telegram | смещения считаются в рунах и переводятся в UTF-16 адаптером; добавление в outbox потребует колонки |

## Решение
- **Модель.** `model.FormattedText{Text, Entities}`; `model.TextEntity{Kind, Offset, Length}` — смещение и длина в рунах; пока один вид `EntityBold`. `model.TextBuilder` собирает текст: `WriteString`, `Printf`, `Bold`; `model.Plain(text)` — текст без разметки.
- **Адаптер.** `Messenger` бота принимает `model.FormattedText` (`SendText`, `SendKeyboard`, `SendReplyKeyboard`); `Client.SendFormatted` отправляет текст с `entities`, пересчитав смещения из рун в единицы UTF-16 (эмодзи — две); отрезок за границами текста пропускается. `Client.Send` для воркера outbox остаётся с простым текстом.
- **Бот.** `send` принимает `model.FormattedText`, в журнал чата идёт только текст; `reply` и `replyPrivate` оборачивают строку в `Plain`, для размеченных ответов — `replyFormatted`. `/scout` собирает ответ `TextBuilder`'ом: направления жирным, остальное как было.
- **Правило.** `parse_mode` по-прежнему не используется; выделение — только через `TextBuilder`, экранирование не нужно.

## Последствия
- Код: `model/text.go` (+ тест), `adapter/telegram.entities` (+ тест на UTF-16), `bot.replyFormatted`, `round.ScoutText` возвращает `model.FormattedText`.
- Документы: readme `model`, `adapter/telegram`, `app/bot`, `app/round`; `rules/telegram.md` (строка о формате текстов); реестр команд и руководство (`/scout`).
- Не входит: разметка игровых текстов из outbox (хроника, «раунд открыт») — потребует колонки `entities` в `messages_outbox` и расширения `Sender`; делается при первом запросе на выделение в них.
