# ADR-0018: Завязка истории от рассказчика при `/begin`

- Статус: принято
- Дата: 2026-10-11
- Область: `internal/service/narrator`, `internal/app/round`, `assets/prompts/narrator`, миграция `00022`

## Контекст
Стартовая сцена при `/begin` бралась из шаблона жанра: один и тот же текст с подставленными названием мира и именами фракций, при одном жанре — одинаковое начало у каждой игры. Решение руководителя 2026-10-11: начало истории должен придумывать рассказчик по параметрам жанра, тем же конвейером, что и хроники раундов; сейчас самое простое решение, доработки позже. Ограничения: модель не создаёт фактов движка (локации, объекты, предметы), скрытые описания персонажей не раскрываются, сбой модели не ломает старт.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Несколько завязок в шаблоне жанра, случайный выбор | без вызова модели | ограниченный набор, не учитывает персонажей и названия мира |
| Вызов рассказчика при `/begin` с отдельным промптом и схемой `{text}` (выбран) | новая история под мир, фракции и состав персонажей; один вызов на игру; тот же `app/llm.Complete` с учётом в `llm_runs` | ожидание ответа модели при `/begin`; новый промпт и проверка |
| Генерация при `/create` | раньше видна администратору | персонажей ещё нет, завязка не может их представить |

## Решение
- Роль `opening` (`model.RoleOpening`): модель рассказчика профиля (`LLMProfile.Model`), запись в `llm_runs` с `prompt_version = narrator/opening-v1`, без раунда.
- `service/narrator.Opening` (`opening.go`): вход `OpeningParams` — название, жанр, тон, режим, фракции с отношениями, активные локации (описание, признак стартовой, видимые выходы), персонажи только с открытыми данными (никнейм, пол, фракция, архетип, `public_bio`); системный промпт `assets/prompts/narrator/opening-v1.md`; схема `OpeningSchema` `{text}`. Проверка кодом: объём 80–3000 символов, цифры вне режима `mechanics`, каждый персонаж упомянут по никнейму → один дозапрос с замечаниями; после него объём вне границ → `ErrOpening`, остальное только в `Issues`.
- `app/round.Begin` вызывает `opening` внутри транзакции старта (как вызовы раунда, ADR-0011): текст уходит сообщением `scene` в группу и хранится в `games.opening_scene` (миграция `00022`); без провайдера или при ошибке — стартовая сцена шаблона жанра (`openingTemplate`), тоже сохраняется. Событие журнала чата `opening` (источник, замечания, текст или ошибка).
- Хроники получают завязку первой строкой `world.previous` (выжимка до 1200 символов) без изменения промпта `narrator/v3`: модель держит связность с началом истории.
- Живая проверка промпта: `make eval-narrator EVAL_ARGS="-opening"` по миру первого случая набора.

## Последствия
- `/begin` отвечает после ответа модели (таймаут профиля); игра под блокировкой на это время.
- Уже запущенные игры: `opening_scene` пуст, их хроники идут без завязки в выжимке.
- Документы: `docs/llm/narrator.md`, `docs/llm/README.md`, `docs/llm/round-calls.md`, `docs/game/round.md`, реестр команд, руководство, `.claude/rules/llm.md`. Дальнейшие доработки (несколько завязок, эпилог G13, завязка сезона в пункте 16) — отдельными решениями.
