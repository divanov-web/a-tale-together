# ADR-0017: Группа обязательна и управляется кодом; один лимит — `max_parties`

- Статус: принято (уточняет [ADR-0016](0016-parties.md))
- Дата: 2026-10-11
- Область: `internal/model`, `internal/service/party`, `internal/service/engine`, `internal/app/game`, `internal/app/round`, `internal/app/bot`, `migrations/00020`

## Контекст
Решение руководителя 2026-10-11 по итогам пункта 19: группа задумана как обязательное поле персонажа, чтобы рассказчику не приходилось вести 20 одиночных линий; новичков при достигнутом лимите рассказчик сразу добавляет в существующую группу; лимит групп одновременно задаёт лимит занятых локаций; команды создания, входа и выхода у игроков не нужны — группы скрытое действие рассказчика (здесь — кода). ADR-0016 допускал одиночек, `/party create|join|leave` и отдельный `max_active_locations`.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Группа по желанию, `/party create|join|leave`, два лимита (ADR-0016) | свобода игрока | одиночки не ограничены лимитом локаций, до 20 сцен у рассказчика, два несвязанных лимита |
| Группа обязательна, назначает код; один лимит `max_parties` | не больше `max_parties` сцен и занятых локаций без второго правила; одна форма контекста рассказчика; меньше кода | игрок не выбирает группу — это единица повествования, а не социальный выбор |

## Решение
- У каждого присутствующего персонажа есть активная группа. При `/begin` все в одной группе; новичок в идущей игре — в группу своей стартовой локации, иначе в новую в пределах `max_parties` (он лидер), иначе в ближайшую по выходам и входит в историю в её локации (`service/party.Assign`). При заморозке раунда то же правило применяется к присутствующим без активной группы (`app/round.ensureParties`).
- Группа без присутствующих участников (все `inactive` или `dead`) распускается после раунда (`syncParties`) или при входе новичка (`party.Stale`): место в лимите освобождается, вернувшийся персонаж получает группу по правилу входа.
- Один лимит: `settings.max_parties` (3). Группа держит одну локацию, поэтому занятых локаций не больше, чем групп; `max_active_locations` удалён из настроек (миграция `00020`), снимка и движка (`party_held` только с причиной `party_limit`). Карта мира может быть больше лимита — группам нужно куда идти; две группы могут сойтись в одной локации.
- Команд управления группой нет: `/party` — карточка (своя группа, состав, остальные группы, без кнопок и лидера). Разделение и удержание — движок (ADR-0016), остальное код; имена из шаблона жанра.
- Персонаж без группы остаётся допустимым состоянием данных (черновик до `/begin`, выбывший после роспуска); движок и рассказчик обрабатывают его как запасной путь (свободный переход, сцена без имени группы), в идущей игре он не возникает у присутствующих.

## Последствия
- Удалены `game.CreateParty`, `JoinParty`, `LeaveParty` и их ошибки, кнопки `/party`; `model.GameSettings.MaxActiveLocations`, `RoundSnapshot.MaxActiveLocations`, `HeldLocationLimit`.
- Добавлены `party.Assign`, `party.Stale`, `round.ensureParties`; `syncParties` распускает группы без присутствующих.
- Документы: [группы](../game/parties.md), [модель группы](../game/models/party.md), [раунд](../game/round.md) (раздел о лимите локаций), реестр команд, руководство игрока; правила `.claude/rules/engine.md`, `telegram.md`.
