# ADR-0021: Reply-клавиатура в личке и лимит кнопок

- Статус: принято
- Дата: 2026-10-13
- Область: `internal/model`, `internal/adapter/telegram`, `internal/app/bot`, `internal/app/round`, `.claude/rules/telegram.md`; дополняет [ADR-0015](0015-telegram-buttons.md)

## Контекст
- ADR-0015 разрешил только inline-кнопки, reply-клавиатуру отклонил.
- Ручное тестирование (B29): в личке во время игры игрок не видит, какие команды ему доступны.
- Решение руководителя 2026-10-13: кнопки использовать можно; цель — не больше 4–6 кнопок на ситуацию, в особых случаях можно больше.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Только inline-кнопки (ADR-0015) | кнопки привязаны к сообщению, не занимают экран | уезжают вверх с перепиской, постоянного набора нет |
| Reply-клавиатура в личке по статусу игрока + inline-кнопки как прежде | набор всегда под рукой, меняется вместе со статусом | занимает экран; кнопка отправляет текст сразу, без аргументов |

## Решение
- Reply-клавиатура разрешена в личке; набор кнопок задаёт статус игрока в игре (в игре, вне игры), ставится и снимается вместе со сменой статуса (`ReplyKeyboardRemove`).
- Кнопка reply-клавиатуры отправляет команду из реестра без аргументов; кнопка без команды в реестре не добавляется (как в ADR-0015).
- Лимит для любых клавиатур (inline и reply): цель 4–6 кнопок на ситуацию; больше — только в особом случае с обоснованием в коде или документе пункта (например, список вариантов сцены).
- Остальное в ADR-0015 без изменений: inline-кнопки, формат `callback_data`, снятие после нажатия, клавиатура в outbox.

## Последствия
- `model`: тип reply-клавиатуры и её снятия; `adapter/telegram`: `ReplyKeyboardMarkup`, `ReplyKeyboardRemove`, `input_field_placeholder`.
- `app/bot`, `app/round`: выбор набора по статусу игрока, установка в итогах и личных уведомлениях — реализация в B29 (`docs/plan/backlog.md`).
- Реализация B29 (2026-10-13): набор считается при каждом ответе бота в личку без inline-кнопок (`app/bot/keyboard.go`, `statusKeyboard`), отдельного хранения состояния клавиатуры нет; статус «в игре» — персонаж в незавершённой игре. Нажатие приходит подписью, `dispatch` сопоставляет её с командой до диалога и заявки текстом. Итог создания персонажа с inline-кнопками предваряется подсказкой с клавиатурой; inline «Мой персонаж» убран как дубль. Снятие при завершении игры — следующим ответом бота: личного сообщения о завершении нет.
- Правило `.claude/rules/telegram.md`, реестр `docs/architecture/telegram-commands.md` (раздел «Кнопки»), `guide/commands.md` — при реализации B29.
