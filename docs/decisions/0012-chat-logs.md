# ADR-0012: Журнал чатов для разбора ошибок ИИ

- Статус: принято
- Дата: 2026-10-10
- Область: `internal/adapter/chatlog`, `internal/model/chatlog.go`, `app/bot`, `app/delivery`, `app/llm`, `app/round`, `config`, `docs/dev/chat-logs.md`

## Контекст
Для поиска багов алгоритма раунда и промптов ИИ нужно восстановить весь обмен по чату без доступа к БД: что написал игрок, что ответил бот, что ушло в модель и что вернулось, какие события раунда произошли и почему. `logs/bot.log` хранит структурные записи без текстов, `llm_runs` — метрики без промптов и ответов. Журнал читает ИИ, поэтому важны построчный поиск по `round_no` и `update_id` и полнота, а не компактность.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Таблицы в PostgreSQL (`chat_log`, промпты в `llm_runs`) | SQL-запросы, транзакционность | ИИ нужен доступ к БД; большие тексты раздувают базу; не читается как файл |
| Обёртка над `adapter/telegram` и провайдерами LLM | одна точка на направление | адаптер зависит от адаптера; нет `outbox_id`, раунда и причин — их знают только сценарии |
| Записи из сценариев `app/*` через узкий интерфейс `Journal`, файловый адаптер JSONL (выбрано) | сценарий знает контекст (игра, раунд, `outbox_id`, причина); файл читается `grep`/`jq`; выключается одним полем конфига | точки записи разбросаны по четырём пакетам |

## Решение
- Формат: `logs/chats/<telegram_chat_id>/<ГГГГ-ММ-ДД>.jsonl`, одна запись `model.ChatLogRecord` в строке (`ts`, `kind`, `chat_id`, `update_id`, `game_id`, `round_id`, `round_no`, `user`, `command`, `text`, `event`, `error`, поля outbox, блок `llm`, `data`). Многострочный текст экранируется JSON, строка остаётся одной.
- Виды: `in` (входящее, дубль с `duplicate: true`, `my_chat_member`, `rate_limited`), `out` (ответ на команду или попытка отправки outbox с `outbox_id`, `part`, `attempt`, `telegram_message_id` или `error`), `llm` (роль, версия промпта, профиль, модель, системный промпт, вход, выход, токены, ошибка), `round` (`opened`, `submission`, `skipped`, `frozen`, `interpreted`, `narrated`, `resolved`, `published` с подробностями в `data`), `error` (сбой сценария, показанный игроку общим сообщением).
- Адресация: записи игры (`llm`, `round`, outbox группы) — в папку группы игры (`games.chat_id` → `chats.telegram_chat_id`); личные сообщения и уведомления — в папку лички, у входящих в личке `game_id` текущей игры игрока. Вызовы LLM без игры (`/llm test`) в журнал не пишутся.
- Писатель `adapter/chatlog.Writer`: папка создаётся лениво, запись под мьютексом с `O_APPEND` без `fsync`; ошибка записи — предупреждение в `slog`, сценарий не ломается; `Cleanup` при старте удаляет файлы старше `CHAT_LOG_RETENTION_DAYS`. Интерфейс `Journal{Write(ctx, rec)}` объявляет каждый сценарий; `cmd/bot` подставляет писатель в поле `Journal`, nil — выключено (`CHAT_LOG_DIR=`).
- Приватность: журнал содержит тексты игроков и `secret_bio` во входе рассказчика; `logs/` в `.gitignore`, токен и ключи не пишутся; включение на проде и срок — пункт плана 11.

## Последствия
- Конфиг `CHAT_LOG_DIR` (по умолчанию `logs/chats`) и `CHAT_LOG_RETENTION_DAYS` (30); `.env.example`.
- Порядок разбора сбоя по журналу: [docs/dev/chat-logs.md](../dev/chat-logs.md), скилл `/tale-debug`.
- Правило `rules/go.md`: события сценариев пишутся через `Journal`, новые точки записи — вместе с новым шагом сценария.
