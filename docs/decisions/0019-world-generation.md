# ADR-0019: Генерация мира в контракте рассказчика, стартовый пакет вместо завязки, сохранение ответа по ключу задания

- Статус: принято
- Дата: 2026-10-12
- Область: `internal/model`, `internal/service/{engine,narrator,interpreter,party}`, `internal/app/round`, `internal/adapter/postgres` (и `fake`), `assets/prompts/narrator`, миграция `00023`; уточняет [ADR-0011](0011-narrator-call.md) и [ADR-0013](0013-round-resilience.md), заменяет [ADR-0018](0018-opening-scene.md) в части стартового мира

## Контекст
Решение руководителя 2026-10-12 ([динамический мир](../game/world.md)): мир генерируется по ходу игры, игроки задают направление генерации, приоритет генерации над точностью, в раунде по-прежнему не больше двух вызовов модели. Карта из шаблона жанра (четыре локации с выходами по имени) и контракт рассказчика `v3` (новые сущности запрещены) этого не дают. Нужно решить: как код хранит сетку, где рождаются новые клетки и объекты, как сбой или откат раунда не порождает второй мир и не платит дважды, что остаётся от завязки при `/begin`.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Отдельный вызов «картограф» для геометрии и соседей | модель решает, где что | третий вызов на раунд; геометрия и так тривиальна |
| Геометрия в коде, содержимое в вызове рассказчика (выбран) | два вызова на раунд сохраняются; код знает координаты и задания; описание прибытия и содержимое клетки из одного ответа согласованы | ответ рассказчика тяжелее: схема и валидация пакета мира |
| Новые сущности из интерпретатора по тексту игрока | быстрее реакция | текст игрока управляет созданием фактов (инъекции, пункт 25) |
| Выходы по имени в JSONB (как было) | без миграции | имя не ключ в растущем мире; сосед должен существовать заранее |
| Клетки `(x, y)`, выходы считает код, строки только для `card` и `detailed` (выбран) | уникальность и достижимость в коде; стадия `none` — отсутствие строки | миграция данных и правка всех мест с выходами |
| Объекты в `locations.objects` JSONB | без таблицы | объекты по id нужны квестам и предметам (пункты 28, 30) |
| Таблицы `world_objects`, `items`, `npcs` сразу (выбран; решение руководителя) | ключи и владельцы для поздних пунктов; `items` и `npcs` без поведения до пункта 30 | две пустые таблицы в первом срезе |
| Повтор раунда заново вызывает модель (ADR-0013) | без хранилища | второй вызов даёт другой мир и вторую плату |
| Ответ модели сохраняется по ключу задания вне транзакции (выбран) | повтор берёт готовый ответ: мир один, плата одна, воспроизводимость | таблица без внешних ключей (`FOR UPDATE` на игре блокировал бы проверку ключа); ключ по хэшу входа |
| Полный снимок карты в раунде | как было | снимок растёт с картой |
| Локальный снимок: занятые клетки и соседи (выбран; SQL-выборка — пункт 31) | размер снимка зависит от числа групп | сосед вне снимка проверяется по карте при планировании заданий |
| Завязка как текст, мир из шаблона (ADR-0018) | проще | стартовый мир одинаков у всех игр |
| Стартовый пакет: центр, четыре карточки соседей, текст (выбран) | мир свой у каждой игры с первого сообщения; тот же вызов `opening` | схема и валидация пакета; при сбое шаблонный центр и карточки |

## Решение
- **Сетка.** `locations` получает `x`, `y` (старт `(0,0)`), `stage` (`card` | `detailed`; «none» — строки нет), `terrain`, `visited_at`; уникальность `(game_id, x, y)`, имя — подпись; `links` и `active` удалены. Выходы по четырём направлениям считает код по существующим соседям (`RoundSnapshot.Exits`, `ExitTo`: направление словом или имя соседа; `model.ParseDirection`); движок дополнительно сопоставляет имя по основе слов (`matches`) для запасного разбора кодом. Инвариант: у каждой занятой клетки к концу раунда есть четыре соседа хотя бы в стадии `card` (стартовый пакет, достройка, миграция для старых игр).
- **Сущности.** Объекты клеток в `world_objects` (`(location_id, key)` уникален, поле `searched`); `items` и `npcs` созданы с ключами и владельцами для пункта 30. Шаблон жанра содержит только стартовую клетку.
- **Открытия.** Первый вход персонажа фракции в клетку (кроме стартовой) — приватное событие `cell_discovered` с фракцией; свёртка добавляет фракцию в `discovered_by` клетки; `saveState` пишет `location_discoveries` и увеличивает `factions.explored_since_reset` (счётчик пункта 28). Две группы одной фракции в одной клетке — одно открытие.
- **Снимок v4.** Клетки с координатами, стадией, посещением и открывшими фракциями; в снимок входят только занятые клетки и их соседи (`relevant`); сохранение по id: посещение, состояние объектов, открытия.
- **Генерация.** Код планирует задания (`narrator.PlanTasks`): занятые карточки → детализация (до 4 за раунд, остальные шаблон), недостающие соседи занятых клеток → карточки. Контракт рассказчика `narrator/v4`: во входе `generate` (задания, лимиты, ключи модели персонажа), в ответе `world: {cells[], neighbors[]}` рядом с хроникой. Код проверяет пакет по заданиям, лимитам и модели персонажа (ключи в snake_case, подходы по `docs/game/models/location.md`, `reveal` только на скрытый объект клетки), лишнее отбрасывает, пропущенное закрывает шаблоном («Дорога», «Неизведанные земли»); замечания к пакету дозапроса не вызывают. Принятый пакет пишется в той же транзакции: строки клеток и объектов, события `cell_generated` и `object_created` за событиями движка, свёртка в состояние, чтобы варианты следующего раунда видели новые объекты; подписи сцен обновляются по новым именам. Сбой модели — шаблонная хроника и шаблонные клетки, раунд не откатывается. Новые сущности рождаются только здесь: интерпретатор получает выходы по направлениям и объекты по ключам, текст игрока сущностей не создаёт.
- **Сохранение ответа.** `generation_jobs (game_id, round_id, role, input_hash, response)`: `app/round.complete` перед вызовом ищет ответ по хэшу (версия промпта, роль, системная часть, вход, схема), после вызова пишет его через пул вне транзакции (`SaveGenerationJob`); повтор раунда после отката берёт готовый ответ без `llm_runs` и платы (метрика `llm_reused`). Распространяется на интерпретатор, рассказчика и завязку. `/replay` сравнивает только события движка (`model.GenerationEvents` исключены).
- **Стартовый пакет.** Роль `opening`, промпт `narrator/opening-v2`, схема `{text, start, neighbors}`: модель переписывает стартовую клетку шаблона (описание, объекты; без валидных объектов остаются объекты шаблона) и даёт карточки недостающих соседей; код обновляет клетку, заменяет объекты и создаёт соседей без событий (игра ещё без раундов). Сбой — сцена и клетка шаблона, соседи «Неизведанные земли». Текст завязки по-прежнему в `games.opening_scene` и первой строкой выжимки хроник.
- **Интерфейс.** «Варианты» сцены и личные варианты дополняются переходами «идти на север: Лес» (`narrator.Options` с `Move`, кнопка `#раунд:локация:move:направление`); `/status`, `/party`, `/character` показывают координаты клетки.
- **Сброс.** `/reset` (`ResetWorld`) оставляет стартовую клетку шаблона без объектов и посещения, удаляет остальные клетки, открытия, счётчики и сохранённые ответы.

## Последствия
- Миграция `00023`: координаты существующих локаций по кольцу от стартовой, карточки-соседи «Неизведанные земли» для детализированных клеток, объекты в `world_objects`, таблицы `items`, `npcs`, `location_discoveries`, `generation_jobs`, счётчик фракций, шаблон жанра из одной клетки. Уже запущенные игры песочницы продолжают играть по сетке.
- Промпты `narrator/v4`, `narrator/opening-v2`, `interpreter/v2` (выходы по направлениям, `target` — ключ направления); eval-наборы на сетке, у рассказчика случай с пакетом мира; живой прогон eval по решению руководителя.
- Метрики раунда: `llm_reused`, `world_cells`, `world_templated`; журнал `narrated` и `resolved` несут пакет мира.
