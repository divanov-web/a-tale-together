# ADR-0028: Нулевой вызов «генерация мира»: варианты стартового мира при создании игры

- Статус: принято
- Дата: 2026-10-14
- Область: `internal/model`, `internal/service/narrator`, `internal/app/{round,game,bot}`, `internal/adapter/postgres` (и `fake`), `assets/prompts/narrator`, миграция `00032`; дополняет [ADR-0019](0019-world-generation.md) (стартовый пакет), [ADR-0023](0023-game-setup-status.md) (настройка) и [ADR-0024](0024-async-begin-finish.md) (работа в тике)

## Контекст
Решение руководителя 2026-10-14: стартовый мир прибит в шаблоне жанра (тон, две фракции с описанием и целями, стартовая клетка, сюжет про гонца), поэтому каждая игра начинается с одной и той же истории, а завязка `opening` в песочнице воспроизводит шаблонный квест. Нужен нулевой запрос к модели: по описанию жанра получить четыре разных сценария с заголовками, коротко показать их администратору в личке и дать выбрать один кнопкой на самом первом шаге настройки. Ограничения: ответ на команду не ждёт модели (`rules/telegram.md`), повтор не должен создавать второй мир и вторую плату (принцип 5), факты мира по-прежнему рождаются только структурой через код (принцип 2).

## Варианты
| Вариант | За | Против |
|---|---|---|
| Вызов синхронно в обработчике `/create` | меньше кода | администратор ждёт модель без ответа; перезапуск бота теряет вызов; нарушает правило «долгую работу команда не ждёт» |
| Вызов в тике планировщика для игры `setup` (выбран) | как старт по ADR-0024: перезапуск не теряет, повтор по ключу задания, сообщение через outbox | шаг настройки должен уметь ждать: варианты приходят отдельным сообщением |
| Расширить шаблон жанра несколькими готовыми сценариями | без модели | ровно та же жёсткость, только в четырёх экземплярах |
| Хранить выбранный вариант, переписывая шаблон жанра игры | единый источник | у игры нет своей копии шаблона; правка справочника ломает другие игры |
| Варианты и выбор в `games.world_setups` (jsonb), применение в строки фракций и стартовой клетки (выбран) | фракции и клетка меняются там, где их уже читают персонаж, снимок и `/status`; остальные поля (тон, крючок, цели) читает завязка из варианта | ещё одно jsonb-поле у игры |

## Решение
- **Вызов.** Роль `worldgen` на модели рассказчика, промпт `narrator/worldgen-v1`, схема `{options[{title, world, summary, tone, premise, factions[{code, title, description, tone, goal}], start{name, terrain, description}}]}`. Вход — описание жанра как образец формы (название, тон, фракции с кодами и отношениями, стартовая клетка шаблона), лимиты длин, `seed` (игра и номер попытки) и `avoid` (заголовки, которые нельзя повторять). Промпт содержит три удачных примера формы и требует четыре варианта, разных по месту, событию, масштабу и настроению, и «правду против правды» вместо злодеев. Код (`narrator.Worldgen`) принимает до четырёх вариантов: отбрасывает без заголовка, названия, завязки, стартовой клетки или без фракции по кодам жанра, режет длинные тексты, нормализует местность; меньше двух пригодных — `ErrWorldgen`. Дозапроса нет.
- **Когда.** `game.Create` ставит `next_round_at = now`; `DueGameIDs` отдаёт и игры `setup`; тик (`round.worldgen`) делает вызов в транзакции игры через `complete` (ответ по ключу задания в `generation_jobs`, откат второй вызов не делает), пишет варианты в `games.world_setups` (`attempts`, `options`, `chosen_no`), снимает `next_round_at` и ставит администратору личное сообщение с вариантами и кнопками через outbox. Сбой — следующая попытка через минуту с новым `seed`; после `model.MaxWorldgenAttempts` (3) варианты пусты, администратор получает «мир по шаблону жанра». Без подключённой модели варианты не генерируются и шаг пропускается.
- **Выбор.** Параметр настройки `scenario` — первый в `game.Params`: кнопки «1. Заголовок» … и «Оставить как есть»; пока варианты ожидаются — только «Оставить как есть», номер в ответ даёт `ErrSetupsPending`. Кнопки сообщения из outbox несут ответ шага `@scenario N`: на шаге применяются как ответ, на другом шаге — «кнопка устарела» и подсказка `/set scenario <номер>`. `game.setScenario` в одной транзакции пишет название мира из варианта (шаг «Название мира» затем предлагает его как текущее), фракции (имя, описание, характер) и стартовую клетку (имя, местность, описание; объекты шаблона остаются подсказкой для завязки); `-` или `0` возвращает шаблон жанра; менять можно до запуска игры (`setup`, `draft`). Смена жанра в `setup` сбрасывает варианты и зовёт генерацию заново.
- **Завязка.** `opening` берёт из выбранного варианта тон, крючок `premise` (вход `world.premise`, промпт `narrator/opening-v5`: завязка, цели и квесты строятся на нём) и запасные цели фракций; при сбое завязки стартовой сценой становится `premise`. Шаблон жанра остаётся запасным путём и единственным путём без модели.

## Последствия
- Миграция `00032`: `games.world_setups jsonb`; существующие игры не меняются.
- Код: `model.WorldSetup`, `WorldSetups`, `Game.Setup()`, `RoleWorldgen`; `narrator/worldgen.go`; `round/worldgen.go` (`WorldgenEnabled`, `SetupOptionsText`, `SetupOptionsKeyboard`, `ScenarioStep`), ветка `setup` в `tickGame`; `game.ScenarioParam`, `setScenario`, `ErrSetupsPending`, `Store.UpdateLocation`; `bot.scenarioQuestion`, `nextParam` с пропуском шага; `cmd/eval-narrator -worldgen`.
- Документы: `docs/llm/README.md`, `narrator.md`, `round-calls.md`, `docs/game/world.md`, `models/genre.md`, `architecture/telegram-commands.md`, `data-model.md`, `guide/commands.md`, план [37](../plan/telegram/37-worldgen.md), readme пакетов, правила `llm.md`, `telegram.md`.
- Не входит: кнопка «ещё варианты» (повторная генерация по запросу; вход `avoid` уже готов), прогон промпта на живой модели (`make eval-narrator EVAL_ARGS="-worldgen"`, по решению руководителя), второй жанр.
