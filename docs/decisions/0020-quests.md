# ADR-0020: Квесты и цели фракций в контракте рассказчика, проверка этапов кодом

- Статус: принято
- Дата: 2026-10-12
- Область: `internal/model`, `internal/service/{quest,narrator,engine}`, `internal/app/round`, `internal/app/bot`, `internal/adapter/postgres` (и `fake`), `assets/prompts/narrator`, миграция `00024`; развивает [ADR-0019](0019-world-generation.md)

## Контекст
Правила [динамического мира](../game/world.md) требуют у каждой фракции цель и сюжетный квест с первого сообщения, выдачу квестов по счётчику открытых клеток с лимитом 2 сюжетных + 1 побочный, ленивую привязку этапов к клеткам и завершение только кодом. В раунде по-прежнему два вызова модели (ADR-0011), ответ сохраняется по ключу задания (ADR-0019). Нужно решить: где живёт состояние квестов, кто и когда проверяет этапы, как этап получает клетку и достижимое условие, что происходит при сбое модели.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Отдельный вызов «квестодатель» | изолированный промпт | третий вызов на раунд |
| Задания квестов в вызове рассказчика и завязки (выбран) | два вызова на раунд, стартовый пакет остаётся одним вызовом; квест и клетка этапа согласованы с хроникой | схема ответа тяжелее |
| Условия этапа выражениями от модели | гибко | исполнение текста модели кодом; проверить достижимость нельзя |
| Каталог условий `object_state`, `fact`, `visited` (выбран; `item_owned`, `npc_state` — пункт 30) | код проверяет и достижимость, и выполнение | квест ограничен тем, что умеет движок |
| Этапы привязаны к клеткам при создании квеста | маршрут известен | клеток ещё нет: мир растёт по ходу игры |
| Ленивая привязка по расстоянию при входе группы (выбран) | этап появляется там, куда игроки пошли; объекты этапа — обычные объекты клетки | этап не выдаётся, пока группа не отошла на расстояние |
| Квесты в снимке раунда, проверка в `engine.Resolve` | воспроизводимо `/replay` | привязка зависит от модели и идёт после движка; снимок растёт |
| Квесты вне снимка, проверка чистой функцией `quest.Check` в сценарии раунда (выбран) | привязанный этап проверяется в том же раунде; движок не знает о квестах | события квестов создаёт сценарий, `/replay` их не сравнивает (как пакет мира) |
| Счётчик обнуляется при выдаче | просто | открытия раунда выдачи теряются |
| Счётчик уменьшается на порог при выдаче, обнуляется при завершении (выбран) | лишние открытия раунда переходят в следующий интервал (правило `world.md`) | два правила вместо одного |

## Решение
- **Данные.** `faction_goals` (строка на версию: `faction_id`, `version`, `text`, `stage`, `quest_id` — сюжетный квест, по закрытию которого цель пересмотрена), `quests` (`faction_id`, `kind` story/side, `status` active/done, `title`, `summary`, `created_round_id`, `done_round_id`), `quest_stages` (`quest_id`, `stage_no`, `key`, `title`, `summary`, `distance`, `condition jsonb` `{kind, object, state, fact}`, `reward jsonb` `{fact}`, `location_id` после привязки, `status` pending/bound/done, `done_round_id`). Настройки игры `max_story_quests` = 2, `max_side_quests` = 1. Шаблон жанра получает `goal` у фракции и `story_quest` на случай сбоя модели.
- **Планирование (`service/quest.Plan`, чистая функция).** По фракциям, активным квестам и счётчику `explored_since_reset`: нет активного сюжетного → задание «сюжетный» вне счётчика; иначе порог по числу активных (1 → 1 клетка, 2 → 4, 3 → выдача закрыта), тип по свободным слотам с чередованием сюжетный → побочный → сюжетный; не больше одного задания на фракцию за раунд. Привязка: первый незакрытый этап без клетки получает клетку, где стоит персонаж фракции и расстояние от клетки предыдущего этапа (или стартовой) не меньше `distance`; одна клетка на этап. Пересмотр цели: сюжетный квест закрыт, а текущая версия цели ссылается на другой квест.
- **Генерация.** Контракт рассказчика `narrator/v5`: во входе `generate.quests`, `generate.stages`, `generate.goals` и блок `quests` (активные квесты фракций одной строкой, ближайший этап подробно, закрытые этапы фразой — подсказки игрокам без кнопок); в ответе `world.quests[]`, `world.stages[]`, `world.goals[]`. Завязка `narrator/opening-v3`: `factions[{code, goal{text, stage}, quest{...}}]`. Код проверяет квесты (фракция из задания, число этапов по типу, вид условия из каталога, лимиты длин), размещение этапа (объекты по правилам пакета мира, ключи не повторяют объекты клетки; условие принимается, только если достижимо подходом клетки: `object_state` — подход ставит объекту это состояние, `fact` — подход даёт этот факт; иначе первое достижимое, иначе `visited`). Сбой модели: сюжетный квест и цель из шаблона жанра, побочный ждёт следующего раунда, этап размещается шаблонным объектом «след» с подходом без броска и условием `fact`.
- **Запись.** В транзакции раунда после пакета мира: `quest_issued`, `quest_stage_placed` (объекты этапа — `object_created` в клетке), `goal_revised` — private персонажам фракции. Проверка этапов `service/quest.Check` по состоянию после свёртки: до вызова рассказчика (этапы, привязанные раньше) и после привязки (этап `visited` закрывается в раунде входа) → `quest_stage_done` с наградой (`fact` сворачивается в знания адресатов в `engine.Apply`), `quest_done`; счётчик фракции: минус порог при выдаче, ноль при завершении. Квесты не входят в снимок раунда; `model.GenerationEvents` расширяется событиями квестов, `/replay` их не сравнивает.
- **Интерфейс.** `/quests` в личке: квесты фракции персонажа, этапы со статусами и клеткой; хроника намекает на ближайший этап без кнопок. `/reset` удаляет квесты и цели; `/begin` создаёт их заново.

## Последствия
- Миграция `00024`: таблицы `faction_goals`, `quests`, `quest_stages`, настройки `max_story_quests`, `max_side_quests` в `games.settings` существующих игр, `goal` фракций и `story_quest` в шаблоне жанра. Уже запущенная игра песочницы цели и квеста не получает: они создаются при `/begin` (после `/reset`), а обязательный сюжетный — первым раундом из шаблона.
- Промпты `narrator/v5`, `narrator/opening-v3`; eval рассказчика — случай с заданиями квестов; живой прогон по решению руководителя.
- Метрики раунда: `quests_issued`, `stages_placed`, `stages_done`.
- Документы: `docs/game/world.md`, `scenarios.md` (S17), `glossary.md`, `architecture/data-model.md`, `round-pipeline.md`, `telegram-commands.md`, `llm/round-calls.md`, `narrator.md`, правила `engine.md`, `llm.md`, `postgres.md`, readme пакетов, руководство игрока. Предметы и NPC в условиях и наградах — пункт 30; восстановление пути к этапу — пункт 29.

## Дополнение 2026-10-17 (B54)
- Расстояние этапа `distance` допускает 0 — этап ложится в клетку, где группа стоит сейчас (для первого — в стартовую): квест о предмете, который уже перед персонажами (срез каната на площади), раньше был вынужден ждать перехода и ложился в соседнюю клетку без этого предмета. Промпты `narrator/v13`, `narrator/opening-v9`.
- Размещение без достижимого условия у этапа не `visited` закрывает шаблонный «след» с подходом и фактом (`quest.TemplateStage`) и считается невыполненным заданием (дозапрос), а не `visited`: иначе этап закрывался простым входом в клетку.
