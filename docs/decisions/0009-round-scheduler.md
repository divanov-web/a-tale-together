# ADR-0009: Непрерывные раунды, планировщик по `next_round_at`, минимальный outbox

- Статус: принято
- Дата: 2026-10-10
- Область: `internal/app/round`, `internal/app/scheduler`, `internal/app/delivery`, `migrations/00008`, `.claude/rules/telegram.md`

## Контекст
Пункт плана 05 вводит жизненный цикл раунда без разрешения: открытие по расписанию, заявки, заморозка или пропуск, пауза. Нужно решить, как раунды следуют друг за другом, что делает планировщик после перезапуска бота и как отправлять игровые тексты до появления рассказчика (пункт 09).

## Варианты
| Вариант | За | Против |
|---|---|---|
| Раунды по фиксированной сетке (каждые N минут от начала окна) | предсказуемое расписание | пропуски догоняются или сдвигаются; сложнее при паузе и ручном шаге |
| Непрерывные раунды: следующий открывается сразу после дедлайна предыдущего, пока момент внутри игрового окна | простая модель: один `next_round_at` на игру; пауза и `/next` естественны | дедлайны «плавают» после паузы |
| Планировщик в памяти (таймеры на игру) | без опроса БД | теряется при перезапуске, не масштабируется |
| Планировщик опрашивает БД: `games.next_round_at <= now`, строка под `FOR UPDATE SKIP LOCKED` | состояние только в БД; перезапуск ничего не теряет; второй экземпляр не дублирует | опрос раз в N секунд |
| Игровые тексты синхронно | проще | дубли при повторе, нет `message_id` (противоречит ADR-0006) |
| Минимальный outbox сейчас: таблица, воркер с повторами, дедуп по `(round_id, chat, kind, part)` | путь ADR-0006 с первого игрового сообщения | ещё один фоновый цикл |

## Решение
- Непрерывные раунды. Дедлайн раунда = открытие + `round_minutes`. По дедлайну раунд замораживается (снимок, seed) или пропускается без кворума, и тут же открывается следующий, если момент внутри игрового окна; иначе `next_round_at` = ближайшее начало окна. `/begin` открывает первый раунд по тому же правилу.
- Планировщик (`app/scheduler`) раз в `SCHEDULER_TICK` вызывает `round.Tick`: выбор игр с `next_round_at <= now`, каждая в своей транзакции под `LockGame` (`FOR UPDATE SKIP LOCKED`). Состояние только в БД: перезапуск не теряет и не дублирует раунды, `(game_id, round_no)` и частичный уникальный индекс «один открытый раунд» это гарантируют.
- Пауза: `next_round_at = NULL`, открытый раунд ждёт; возобновление даёт ему новый дедлайн от момента возобновления. Пропущенные раунды не догоняются.
- Пропуск без кворума: заявки остаются `pending` в пропущенном раунде и переносятся в следующий при его открытии (цепочка пропусков переносит дальше). Персонажи за пропущенный раунд не наказываются.
- Заморозка: снимок персонажей и заявок в `rounds.snapshot`, `seed` из `math/rand/v2`; статусы персонажей по пропускам (`waiting`, `leaving` на один раунд, `inactive`, возврат заявкой) обновляются здесь; уход из сюжета описывается рассказчиком по статусу `leaving` в снимке, отдельного события нет (B13, 2026-10-11); `character_returned` появился с журналом событий (пункт 07) для ненастоящей смерти. Замороженный раунд остаётся `frozen` до конвейера разрешения (пункты 07–09).
- Outbox (`app/delivery`): таблица `messages_outbox`, воркер раз в `OUTBOX_TICK` берёт `pending` под `SKIP LOCKED`, отправляет, хранит `telegram_message_id`; ошибка — повтор с экспоненциальной паузой до 5 попыток; застрявшее `sending` дольше 5 минут помечается `unknown` и не переотправляется.
- Сообщение о пропуске раунда «Недостаточное количество участников. Раунд пропущен» (с 2026-10-10 в одном сообщении с анонсом следующего раунда, B4) отправляется в группу только в `APP_ENV=dev` (решение руководителя 2026-10-10: на время разработки); в prod пропуск молчаливый, причина видна в `/status`.
- Ручной шаг `/next` (группа, только dev): закрывает открытый раунд сейчас и открывает следующий независимо от окна.

## Последствия
- Новые пакеты `app/round`, `app/scheduler`, `app/delivery`; `cmd/bot` запускает оба цикла в `errgroup`; конфиг `SCHEDULER_TICK` (10с), `OUTBOX_TICK` (3с).
- `adapter/telegram.Send` возвращает `message_id`; `SendText` остаётся для ответов на команды.
- Миграция `00008`: `rounds`, `action_submissions`, `messages_outbox`.
- `docs/game/round.md`, `docs/architecture/layers.md`, `data-model.md`, `.claude/rules/telegram.md` обновлены; границы рассказа (`ends_at`, `max_rounds`) и `/finish` — пункт 10 (шаг 6а).
