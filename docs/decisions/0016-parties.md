# ADR-0016: Группы персонажей: разделение и удержание в движке, скрытый лидер, сцены рассказчика по группам

- Статус: принято
- Дата: 2026-10-11
- Область: `internal/model`, `internal/service/engine`, `internal/service/party`, `internal/service/narrator`, `internal/app/round`, `internal/app/game`, `internal/app/bot`, `migrations/00019`, `assets/prompts/narrator/v3.md`

## Контекст
Пункт 19: персонажи объединяются в группы с общей сюжетной линией ([группы](../game/parties.md)), число групп в сезоне ограничено `settings.max_parties`, участники держатся одной локации. Решения руководителя: при расхождении заявок на перемещение группа делится только в пределах лимита, иначе удерживается вместе (2026-10-10); у группы есть скрытый лидер, чьё направление движок засчитывает при удержании (2026-10-11). Ограничения: факты считает код, не LLM (принцип 1); раунд воспроизводим по снимку и seed (S06); рассказчик пишет блок на группу, а в одной локации может быть несколько групп.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Разделение и удержание решает движок после фазы перемещения, рассказчик получает событие | детерминизм, повтор раунда, один источник истины | рассказчику остаётся только объяснение сюжетом |
| Рассказчик сам решает, делиться ли группе, и задаёт имя | гибкий сюжет | факт создаётся текстом модели; невоспроизводимо |
| Идентификатор новой группы выдаёт БД при записи, события правятся после | обычный `INSERT` | повтор раунда по снимку даёт другие идентификаторы, `/replay` ломается |
| Идентификаторы для новых групп резервируются при заморозке и хранятся в снимке | события детерминированы, повтор совпадает | пропуски в последовательности `parties.id` (безвредны) |
| Сцена рассказчика = локация (как раньше) | ничего не менять | две группы в одной локации сливаются в один блок |
| Сцена = группа в локации, одиночки локации — отдельная сцена; ответ модели ссылается на `scene_id` | блок на группу по концепту, проверка кодом однозначна | новая версия промпта и схемы (`narrator/v3`) |

## Решение
- Таблица `parties` (миграция `00019`, `id` `GENERATED BY DEFAULT`), внешний ключ `characters.party_id`; имена групп по умолчанию в шаблоне жанра (`party_names`). Уже запущенные игры получают группу по умолчанию миграцией.
- Группа по умолчанию при `/begin`: все персонажи без группы входят в одну группу (имя из шаблона), лидер — персонаж администратора игры, иначе первый созданный (`service/party.Leader`). Новичок в идущей игре: группа его стартовой локации, иначе новая в пределах лимита (он лидер), иначе ближайшая по выходам (`party.Nearest`), и он входит в историю в её локации.
- Движок (`engine.settleMoves`, S14): переходы участников группы сверяются после фазы перемещения. Расхождение локаций → большинство остаётся исходной группой (при равенстве — те, кто остался на месте, затем группа лидера); остальные по локациям назначения становятся новыми группами `party_split` (идентификатор из `snapshot.new_party_ids`, имя `party.NextName`, лидер — наибольшая Воля), пока свободны `max_parties` и `max_active_locations`. Первая блокировка лимитом удерживает группу `party_held`: все, кто в ней, идут туда, куда заявил лидер (без лидера — большинство); заявки на другое направление получают исход `held` с объяснением, участники без заявки на переход уходят вместе с группой. Одно событие `party_held` на группу за раунд с причиной `party_limit` или `location_limit`. Персонаж без группы перемещается свободно.
- `help` только внутри группы (`sameParty`), иначе отказ с объяснением; совместные действия — пункт 12 по тому же правилу.
- Лидер скрыт от игроков: нет в `/party`, `/status`, `/character`, хронике и контексте рассказчика; в событии `party_split` `leader_id` хранится для свёртки состояния, `Describe` его не называет. Смена лидера после раунда и при выходе из группы — `app/round.syncParties` и `app/game.leaveParty` по правилу `party.Leader`; пустая группа распускается.
- Рассказчик: сцена = группа в локации (`party` — имя) или персонажи без группы в локации (`party` пустой), `scene_id` во входе и в ответе (`narrator/v3`, `Schema`); код подставляет локацию и подпись «Группа (Локация)». Промпт запрещает называть лидера и лимиты, `party_held` объясняется сюжетом.
- Команды: `/party`, `/party create <имя>`, `/party join <имя|#id>`, `/party leave` в личке; кнопки «Вступить: …» (`/party join #id`) и «Покинуть группу» (ADR-0015). Вступить в группу другой локации в идущей игре нельзя (`ErrPartyFar`); выход единственного участника распускает группу и освобождает место в лимите.
