# ADR-0032: Учёт стоимости вызовов LLM — тарифы моделей в БД, токены по видам

- Статус: принято
- Дата: 2026-10-15
- Область: `migrations/00036`, `model` (`LLMUsage`, `LLMPrice`, `LLMPriceTable`), `app/llm`, `adapter/postgres`, `adapter/llm/claudecli`, `cmd/internal/evalcost`, `docs/llm/providers.md`

## Контекст
- Пункт 33: каждый вызов модели оставляет токены по видам и цену в USD по собственной таблице тарифов; руководитель будет фильтровать расходы по модели, роли (интерпретатор, рассказчик, в будущем художник и другие), датам и игре (решение 2026-10-15: тарифы в БД, использовать то, что уже есть).
- `llm_runs` хранил `tokens_in` одним числом и `cost_usd` как оценку `claude -p` (`total_cost_usd`); адаптеры API такой оценки не дадут.
- Консольные `cmd/eval-*` вызывают провайдер напрямую, мимо `app/llm`, и в `llm_runs` не пишут.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Файл тарифов в репозитории (`assets/llm/prices.json`, `embed`) | консоль без БД; история в git | второй источник настроек рядом с профилями в БД; правка требует сборки |
| Таблица `llm_prices` в БД, сид и обновления миграциями данных | один источник рядом с `llm_profiles` и `llm_runs`; отчёты чистым SQL; история в git через миграции; правка без сборки | консоль подключается к БД (есть `DATABASE_URL`) |
| Тарифы с историей (`valid_from`) | пересчёт старых строк по тарифам того времени | лишнее: цена считается в момент вызова и хранится в `llm_runs`, токены по видам позволяют пересчитать и так |

## Решение
- Таблица `llm_prices`: `model` (полное имя или префикс датированных снимков) → USD за 1M токенов входа без кэша, записи кэша (пятиминутный тариф), чтения кэша, выхода; `source`, `priced_at`. Одна строка на модель. Сид и обновления — миграциями данных (как `00011`): Claude сверяет с официальной страницей цен (скилл `/claude-api`), пишет миграцию, `make migrate` на `tale` и `tale_test`, перезапуск бота (кэш тарифов в `app/llm` читается вместе с профилями, сбрасывается с ними).
- Поиск тарифа: точное имя, иначе самый длинный префикс до дефиса (`claude-opus-5-5-2026…` → `claude-opus-5-5`). Неизвестная модель → `cost_usd = 0` и одно предупреждение `llm price unknown` на модель за время работы бота.
- `llm_runs`: `tokens_in` остаётся суммой (вход + запись + чтение кэша), добавлены `tokens_cache_write`, `tokens_cache_read`, `cost_provider_usd`; `cost_usd` — по таблице. Прежние строки: оценка провайдера скопирована в `cost_provider_usd`, `cost_usd` оставлена (разбивки по видам нет).
- `model.LLMResponse`: `Usage LLMUsage` вместо `TokensIn`/`TokensOut`; `CostUSD` по таблице заполняет `app/llm` (или консоль через `evalcost`), адаптер оставляет 0; `ProviderCostUSD` — оценка провайдера. Ответ, взятый из `generation_jobs`, бесплатен (`CostUSD = 0`), токены в нём хранятся по видам.
- Роль — значение `llm_runs.role`; новая роль (художник) схему не меняет. Модели изображений с ценой за запрос получат отдельную колонку тарифа, когда появятся.
- Haiku 5.5 — тариф запросов до 100K токенов (запросы бота меньше). Запись кэша считается по пятиминутному тарифу; `claude -p` может держать часовой кэш, расхождение видно рядом в `cost_provider_usd`.
- Индексы под отчёты не добавляются до пункта 13: есть `llm_runs_game_idx` и `llm_runs_created_idx`.
- Команды бота не добавляются (решение руководителя 2026-10-15); `/llm test` показывает токены по видам и обе оценки.

## Последствия
- Миграция `00036`; обновлены `data-model.md`, `providers.md` («Учёт»: колонки, тарифы, обновление, примеры SQL), `chat-logs.md`, readme пакетов, `rules/llm.md`, `rules/postgres.md` (`llm_prices` без `game_id`), `/tale-debug`.
- Пакет `cmd/internal/evalcost` — общий для консольных eval: тарифы из БД, цена по вызову при `-v`, итог набора.
- Метрика раунда `cost_usd` в `rounds.metrics`, логе `round metrics` и карточке `/round`; завязка и генерация мира — `cost_usd` в своих строках лога и журнале.
