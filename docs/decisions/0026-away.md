# ADR-0026: Уход персонажа по слову игрока (`/away`, `/back`)

- Статус: принято
- Дата: 2026-10-13
- Область: `internal/model`, `internal/app/{round,bot}`, `internal/adapter/postgres`, `migrations/00030`, `docs/game/character.md`; дополняет B13 (статусы по пропускам) и [ADR-0015](0015-telegram-buttons.md) (кнопки-подтверждения)

## Контекст
- По B13 персонаж выходит из истории за три пропуска подряд: `leaving` на один раунд (рассказчик выводит его), затем `inactive`. Игрок, уезжающий на неделю, хочет уйти сам, не ожидая трёх раундов, и вернуться одной командой (пункт 20).
- Статусы считает `app/round.activity` при заморозке; смерть — отдельный статус со счётчиком возврата, с уходом не смешивается. Рассказчик описывает уход только по статусу `leaving` в снимке, отдельного события нет.
- G15 (мгновенный уход в текущем раунде или с ближайшей заморозки) открыт; допущение — с ближайшей заморозки.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Сразу поставить `leaving` и `missed_rounds` = порог | без новых полей; `activity` сама даёт `inactive` дальше | пропуски подделываются; `/character` покажет три пропуска, которых не было; статус `leaving` до заморозки виден, но описан будет только в следующей хронике |
| Новый статус `away` | явно в карточке | ещё одна ветка в `Absent()`, снимке, словах статусов и промпте рассказчика, а рассказчику он не нужен: уход описывается по `leaving` |
| Флаг `characters.away`, статус по-прежнему считает `activity` при заморозке | один механизм ухода (`leaving` → `inactive`), пропуски и смерть не тронуты; снимок и рассказчик без изменений | нужна миграция и два метода хранилища |

## Решение
- Флаг `characters.away` (миграция `00030`, по умолчанию `false`), `model.Character.Away`, в снимке `away` с `omitempty` (для журнала заморозки и личных уведомлений).
- `/away` в личке: без аргумента — вопрос с кнопками «Уйти» / «Отмена» (`yes|no`, ADR-0015); `yes` ставит флаг, удаляет заявку открытого раунда (`DeleteSubmission`), ответ с кнопкой «Вернуться» (`/back`). Выбывший по смерти — отказ `ErrDead`; уже помеченный — `ErrAlreadyAway`. Игра в `draft` или на паузе — флаг ставится и ждёт заморозки.
- Заморозка: `activity` при флаге и без заявки даёт `leaving` (если статус ещё не `leaving` / `inactive`), затем `inactive`; пропуски продолжают считаться, чтобы возврат обнулял их как обычно. Заявка снимает флаг (`Submit`) и возвращает `active`; после `leaving` / `inactive` снимок несёт `entry = returned` — как по B13.
- Помеченный игрок не получает личное «раунд открыт» (`notifyOpen`), хроника и анонсы его не называют: рассказчик выводит персонажа в раунде `leaving`, дальше его нет в сценах. Тегов по никнейму у бота нет.
- `/back` в личке: снимает флаг; если статус `leaving` / `inactive` и раунд открыт — заявка `wait` текстом «жду» (`BackSubmission`) с ответом о возвращении; без открытого раунда — только флаг, вернёт первая заявка; до заморозки (статус `active` / `waiting`) — уход отменён без заявки. Любая заявка `/act` делает то же, что `/back`. Персонаж в истории без флага — `ErrNotAway`.
- Reply-кнопки не добавляются (лимит ADR-0021 исчерпан «Разведкой»); `/character` показывает «уходит из истории; вернуться — /back».
