# ADR-0034: Имитатор партии с ИИ-игроками

- Статус: принято
- Дата: 2026-10-16
- Область: `cmd/simulate`, `cmd/internal/stack`, `internal/app/sim`, `internal/adapter/telegram/fake`, `assets/prompts/player`, `sim/runs`

## Контекст
Пункт 40: сыграть партию без людей на живой модели и получить по ней журнал, транскрипт и сводку токенов (цель — качество текста, работа карты и квестов, утечки токенов в промптах). Бот общается с игроками только через Telegram: бот не может писать боту, а живые аккаунты под управлением ИИ нарушают правила Telegram и требуют ручной работы. Прогон должен быть повторяемым, дешёвым (haiku по умолчанию, любая локальная модель по флагу — решение руководителя В1) и не задевать песочницу `tale` и тесты `tale_test`.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Живые аккаунты Telegram под ИИ (MTProto) | проверяется и провод Telegram | нарушение правил Telegram, номера и ручная работа, невоспроизводимо |
| Вызовы сценариев `app/*` напрямую из имитатора | просто | обходит реестр команд, диалоги, лимиты, журнал и outbox — не «реальные условия» |
| Подмена транспорта в процессе: `adapter/telegram/fake` реализует интерфейсы `bot.Telegram` и `delivery.Sender`, имитатор подаёт `model.Incoming` в `bot.Service.Handle` | бот неотличим от боевого: реестр, диалоги, кнопки, дедупликация, лимит частоты, журнал, outbox; без сети | не проверяет лимиты и разметку самого Telegram API |

## Решение
Подмена транспорта в процессе (третий вариант).

- `adapter/telegram/fake.Transport`: ящики сообщений по чатам (`model.SentMessage`: id, текст, кнопки, reply-клавиатура), растущие `message_id` и `update_id`, админы групп, ссылка-приглашение-заглушка. Сборка входящих — методами `Text`, `Press`, `ChatMember` (те же структуры, что строит боевой клиент из update).
- `cmd/internal/stack.Build` — общая сборка стека для `cmd/bot` и `cmd/simulate`: хранилище, журнал, сценарии, провайдеры LLM, команды, outbox, планировщик. `main.go` бота остаётся сборкой зависимостей.
- `app/sim.Runner` — оркестратор: сценарий прогона из JSON (`sim/runs/*.json`: персоны, раунд входа, параметры мира, расписание фич по раундам, бюджет), фазы игрока (личка открыта → вход по коду → диалог персонажа → ходы в раундах), очередь ходов (один вызов модели за раз), закрытие раунда командой `/next` админа после хода всех присутствующих, страховочный дедлайн `round_minutes`, стоп по финальной хронике, ошибке стека или бюджету. Состояние игры оркестратор читает из БД (статусы игры, раунда, заявки), а игроку отдаёт только ящики его чатов — как человек видит Telegram.
- ИИ-игрок: роль LLM `player`, промпт `assets/prompts/player/v1.md`; вход — персона, фаза, непрочитанные сообщения с кнопками как данные, задание фичи на раунд; выход — JSON `{action: command|button|text|done, …}` с валидацией кодом; невалидный ответ — запасной ход `/act жду` или `done`. Вызов через `app/llm.Service.Complete` (учёт в `llm_runs` и журнал); модель игрока — из сценария или флага, подменой `req.Model`.
- Модели ролей: профиль прогона (`sim-haiku`, миграция `00038`) ставится глобальным по умолчанию в БД прогона; флаги `-model-narrator`, `-model-interpreter`, `-model-player` подменяют модель роли обёрткой провайдера, не меняя профили.
- Отдельная БД `DATABASE_URL_SIM` (`tale_sim`), папка прогона `logs/sim/<метка>/` с журналом чатов `chats/`, `transcript.md` и `summary.md`. Отчёт: транскрипт из ящиков и действий игроков, сводка из `llm_runs`, раундов, локаций, квестов и outbox.
- Юнит-тест прогона на `postgres/fake` и фейке LLM по ролям: три раунда без сети.

Что имитатор не проверяет: лимиты, ошибки и разметку Telegram API, права реальной группы, ссылки-приглашения.

## Последствия
- Новые пакеты в таблице слоёв `docs/architecture/layers.md`; `docs/dev/simulation.md`; команды `make sim`, `make migrate-sim` в `docs/go_commands.md`.
- Роль `player` в `docs/llm/README.md`; промпт игрока версионируется как остальные (`PromptVersion` пакета `app/sim`).
- Правило `.claude/rules/sim.md` и скилл `/tale-sim`: расписание фич в сценарии пополняется с каждой новой командой или механикой игрока (решение руководителя В3).
- Пункт 13 шаг 9 (нагрузка) и пункт 25 (персоны-инъекторы) переиспользуют имитатор.
