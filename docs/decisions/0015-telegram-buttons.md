# ADR-0015: Inline-кнопки Telegram как дубликаты команд

- Статус: принято
- Дата: 2026-10-11
- Область: `internal/model`, `internal/adapter/telegram`, `internal/app/bot`, `internal/app/round`, `internal/app/delivery`, `migrations/00018`, `.claude/rules/telegram.md`

## Контекст
До пункта 18 всё управление — слеш-команды. Выбор из списка (фракция, архетип, игра), подтверждение (`/begin`, `/finish`) и типовой ход по варианту сцены короче и понятнее кнопкой. Ограничения: `callback_data` до 64 байт; клиент присылает нажатие как отдельный update с `update_id`; двойное нажатие не должно создавать второе действие; кнопки на старых сообщениях живут неограниченно долго.

## Варианты
| Вариант | За | Против |
|---|---|---|
| Inline-кнопки под сообщением, данные кнопки — та же команда с аргументами | один маршрут для текста и кнопки, реестр команд не дублируется, права и ошибки те же | длинный текст в 64 байта не входит: вариант сцены передаётся ссылкой |
| Reply-клавиатура с постоянными кнопками «Заявка», «Персонаж», «Статус» | всегда под рукой | занимает экран, кнопка отправляет только текст без аргументов, текст без команды в личке уже принимается как заявка (B17) |
| Отдельный обработчик callback со своей логикой | произвольный формат | вторая копия сценариев, расходится с командами |
| Состояние кнопок в памяти | просто | теряется при перезапуске; не нужно: всё, что требуется, есть в данных кнопки |

## Решение
- Только inline-кнопки под сообщениями; reply-клавиатура не используется.
- Данные кнопки (`callback_data`): `/команда аргументы` — нажатие проходит через `app/bot.Handle` как обычная команда того же пользователя в том же чате (права, ошибки, журнал те же); `@шаг ответ` — ответ на вопрос диалога в личке: применяется, только если диалог стоит на этом шаге, иначе «кнопка устарела» и повтор текущего вопроса. Адаптер разбирает данные в `model.Incoming` с полем `Callback` (идентификатор запроса, сообщение с кнопками, шаг); грамматика и сборка данных — функции `model`.
- Заявка по варианту сцены: `/act #<раунд>:<локация>:<объект>:<подход>` (`round.OptionRef`); сценарий `round.SubmitOption` принимает только открытый раунд с этим номером и существующий подход по текущему состоянию, иначе `ErrRoundClosed` / `ErrOptionGone`; текст заявки — название подхода, дальше как обычный `/act`.
- Идемпотентность: дедупликация по `update_id` как у сообщений; повтор нажатия — второй update, который упирается в правила сценария (`ErrAlreadyActed`, проверка шага диалога, закрытый раунд). После обработки нажатия бот снимает клавиатуру с сообщения (`editMessageReplyMarkup`), кроме отказа в правах: чужое нажатие не гасит кнопку владельца. Ответ на `callback_query` (`answerCallbackQuery`) без текста даёт адаптер после обработки; содержательный ответ — обычным сообщением.
- Подтверждения в группе: `/begin` и `/finish` без аргумента показывают кнопки «Начать» / «Завершить» и «Отмена» (`/begin yes|no`, `/finish yes|no`); права проверяются при нажатии в сценарии. `/pause` выполняется сразу, ответ о паузе несёт кнопку «Возобновить».
- Клавиатура игровых сообщений хранится в `messages_outbox.keyboard` (jsonb, миграция `00018`) и отправляется воркером вместе с текстом; ответы на команды с кнопками уходят синхронно (ADR-0006).
- Текстовые команды остаются полным путём: каждая кнопка дублирует команду из реестра, новая кнопка без команды не добавляется.

## Последствия
- `model.Keyboard`, `model.Button`, `model.Callback`, `model.CallbackCommand` / `CallbackAnswer` / `ParseCallbackData`; `OutboxMessage.Keyboard`.
- `adapter/telegram`: `callback_query` в allowed updates, `SendKeyboard`, `ClearKeyboard`, `Send` с клавиатурой; `app/delivery.Sender.Send` получает клавиатуру.
- `app/bot`: `Messenger` и `ChatAPI` вместо одного широкого интерфейса; диалоги возвращают вопрос с клавиатурой; `/games`, `/help` с кнопками; `/begin`, `/finish` с подтверждением.
- `app/round`: `optionsKeyboard` под личными «Варианты», `SubmitOption`, `OptionRef`.
- Правило `.claude/rules/telegram.md`, реестр `docs/architecture/telegram-commands.md` (раздел «Кнопки»), руководство `guide/commands.md`.
