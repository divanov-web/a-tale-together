# ADR-0008: Транзакция через контекст, состояние диалогов и текущая игра пользователя

- Статус: принято
- Дата: 2026-10-10
- Область: `internal/adapter/postgres`, `internal/app/*`, `migrations/00002`, `00003`

## Контекст
Сценарии `app/game` объявляют свой интерфейс `Store`; `InTx(ctx, func(tx Store) error)` из [layers.md](../architecture/layers.md) требует, чтобы адаптер знал интерфейс потребителя или нужен слой-переходник в `cmd`. Многошаговые диалоги в личке (настройка игры, создание персонажа) растягиваются на часы: состояние должно пережить перезапуск бота. Команды в личке нуждаются в «текущей игре», если пользователь участвует в нескольких.

## Варианты
| Вариант | За | Против |
|---|---|---|
| `InTx(ctx, func(tx Store))` в адаптере | явная передача транзакции | адаптер не может вернуть интерфейс потребителя без переходника или дженериков |
| Транзакция в `context.Context`: `InTx(ctx, func(ctx) error)`, методы берут `pgx.Tx` из ctx | один интерфейс для пула и транзакции; любой консьюмер объявляет `InTx` одинаково; вложенный вызов переиспользует транзакцию | неявность; метод, вызванный с «чужим» ctx, выполнится вне транзакции |
| Состояние диалога в памяти | просто | теряется при перезапуске, не масштабируется |
| Таблица `dialogs` (user_id PK, kind, step, data jsonb) | переживает перезапуск; один диалог на пользователя | ещё одна таблица уровня бота |
| Текущая игра: `users.current_game_id` | одно поле, меняется `/games <n>` и при входе | не в данных игры; при одной игре избыточно |

## Решение
- Транзакция через контекст: `postgres.Store.InTx(ctx, fn func(ctx context.Context) error)`; все методы репозиториев берут `Querier` из ctx (`db(ctx)`), иначе пул. Границу по-прежнему держит `app`.
- Диалоги в таблице `dialogs`; шаг и данные черновика в jsonb; команда `/cancel` удаляет запись; команда во время диалога выполняется, диалог остаётся.
- `users.current_game_id`: ставится при `/create`, `/join` и `/games <n>`; `app/game.Current` берёт его, иначе единственную незавершённую игру, иначе просит выбрать.
- Регистрация чата по первой команде: только для команд с `needsChat` (`/chat*`, `/create`, `/status`); `/help` и `/ping` работают без чата.

## Последствия
- `layers.md`: сигнатура `InTx` и таблица пакетов обновлены; `.claude/rules/postgres.md` дополнено.
- Модель данных: `dialogs`, `users.current_game_id`, `games.created_by_user_id`.
- Фейковое хранилище `adapter/postgres/fake` повторяет контракт и используется тестами `app/bot`.
