# Конвейер раунда

Источник: [раунд](../game/round.md), риски §5 «Возможный конвейер MVP». Исполнитель: `internal/app/round`.

| Шаг | Вход | Выход | Фиксация | Исполнитель |
|---|---|---|---|---|
| 1. Сбор | заявки до дедлайна | `rounds.status=frozen`, `snapshot`, `seed`; без кворума `skipped` и перенос заявок | транзакция | планировщик → `app/round` (готово, пункт 05, ADR-0009) |
| 2. Интерпретация | заявки снимка | намерения JSON одним вызовом на раунд для всех заявок (пункт 08); разбор кодом `rules.ParseTyped` (пункт 07) — до пункта 08 и запасной путь при сбое модели | `resolved_actions.intent`, `llm_runs` | интерпретатор (вызов 1 из 2, [round-calls.md](../llm/round-calls.md)) |
| 3. Разрешение | снимок + намерения + seed | статусы заявок, проверки, события | в памяти, детерминированно | движок `engine.Resolve` (готово, пункт 07: без конфликтов) |
| 4. Сюжетные предложения (позже) | рассчитанные итоги | события следующего раунда после валидации | | рассказчик + движок |
| 5. Фиксация | события, статусы | `world_events`, `resolved_actions`, состояние через `engine.Apply`, `rounds.status=published` | одна транзакция с заморозкой | `app/round.resolve` (готово, пункт 07) |
| 6. Описание | публичные и локационные события | хроника в группу (вызов 2 из 2), шаблонное уведомление игроку о статусе заявки | `messages_outbox` в той же транзакции | шаблоны без LLM (пункт 07), рассказчик — пункт 09; приватные итоги рассказчика исключены (решение 2026-10-10) |
| 7. Доставка | outbox | сообщения Telegram, `telegram_message_id` | воркер доставки, повторы | delivery |

## Правила

- Один раунд одного мира в один момент: блокировка строки `rounds` (`FOR UPDATE SKIP LOCKED`), запрет перекрытия.
- Повтор любого шага после сбоя безопасен: шаги 2 и 6 проверяют наличие результата, шаг 3 воспроизводится по снимку и seed.
- Сбой LLM на шаге 2: ограниченные повторы → запасной разбор кодом (`rules.ParseTyped`), остальное безопасное толкование; причина в уведомлении о заявке. Сбой на шаге 6: шаблонная хроника, мир не откатывается.
- Поздние заявки после заморозки относятся к следующему раунду.
- Пауза останавливает планировщик; пропущенные раунды не догоняются. Следующий раунд открывается сразу после дедлайна предыдущего внутри игрового окна (ADR-0009).
- Измеряется: длительность каждого шага, токены и стоимость, число `ambiguous`, пропущенные ID.
