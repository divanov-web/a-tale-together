# Архитектура: обзор

Цель: маленькое приложение с ясными слоями и минимумом абстракций. Один бинарник `cmd/bot`, PostgreSQL как хранилище и очередь, два вида вызовов LLM.

## Компоненты (концепт §8)

```text
Telegram groups + private chats
            |
       Bot gateway  (internal/adapter/telegram, internal/app/bot)
            |
   Сценарии игры (internal/app/*) ---- PostgreSQL (internal/adapter/postgres)
            |
   Round scheduler / worker (internal/app/round)
            +--> Интерпретатор LLM (service/interpreter)  --> намерения
            +--> Движок правил   (service/engine, rules)  --> броски + события
            +--> Рассказчик LLM  (service/narrator)       --> тексты по видимости
            |
       Outbox / sender (internal/app/delivery)
            |
     Telegram messages
```

## Разделение ответственности

| Компонент | Отвечает | Не отвечает |
|---|---|---|
| Bot gateway | маршрутизация update, команды, идентификация `user_id`/`chat_id`/`game_id`, права, дедупликация | игровая логика |
| Сценарии (app) | последовательность шагов: создать игру, принять заявку, провести раунд, доставить | правила, SQL, API |
| Интерпретатор | свободный текст → типизированный JSON по схеме | решения, броски |
| Движок | состояние, доступность целей, ресурсы, конфликты, броски, события; детерминизм, воспроизведение | тексты |
| Рассказчик | разрешённые события + видимость → хроника и приватные итоги | изменение фактов |
| Хранилище | состояние мира, журнал событий, снимки раундов, outbox, прогоны LLM; всё по `game_id` | |
| Планировщик | раунды по расписанию и паузам, защита от двойной обработки, лимиты | |

## Критические требования

Изоляция миров, идемпотентность, атомарное разрешение раунда, приватность контекста, наблюдаемость (журнал, токены, ошибки, время), бюджеты LLM. Проверяются тестами из [сценариев](../game/scenarios.md) и раздела «Что проверить первым» рисков.
