# Команды Telegram

Реестр команд MVP (готовые и планируемые); обновляется вместе с `internal/app/bot`. Описание реализованных команд для пользователей — [руководство игрока](../../guide/commands.md).

## Принципы

- Всё управление игрой — слеш-команды `/name [аргументы]` (решение руководителя). Inline-кнопки под сообщениями дублируют команды там, где кнопка короче и понятнее (пункт 18, [ADR-0015](../decisions/0015-telegram-buttons.md)): данные кнопки — та же команда с аргументами или ответ шага диалога, нажатие идёт тем же маршрутом, что текст; своей логики у кнопок нет. Раздел «Кнопки» ниже.
- У каждой команды объявлены контексты: группа, личка или оба; наборы в группе и личке пересекаются не полностью. Команда в чужом контексте получает подсказку, где её использовать.
- Меню команд Telegram (`setMyCommands`) регистрируется по этому реестру: личка; группа для всех участников — только команды игры здесь и сейчас (`/help`, `/status`, `/act`); владелец и модераторы чата получают в своём чате меню с административными командами (`/chat /mod /owner /create /begin /pause /finish`, в dev `/next /replay /round /reset`) через область `chat_member` — при старте бота, добавлении бота в группу, регистрации чата командой, `/mod add`, `/owner`; `/mod remove` и смена владельца снимают его (B20). `/ping` и `/llm` ни в одно меню не входят. `/help` перечисляет все команды контекста. Права проверяет код при выполнении, меню — только подсказка; клиент Telegram обновляет меню с задержкой.
- Многошаговые сценарии (настройка игры, создание персонажа) — диалог в личке: бот задаёт вопрос, игрок отвечает текстом или кнопкой под вопросом; состояние в таблице `dialogs` (ADR-0008); ответ «-» (кнопка «Оставить как есть» / «Пропустить») оставляет значение по умолчанию; каждый параметр также доступен отдельной командой (`/set <параметр> <значение>`).
- Лимиты входящих: 20 сообщений в минуту на пользователя, текст до 1000 символов. В группе неизвестные команды игнорируются (команды других ботов), в личке — подсказка `/help`.

| Группа, владелец или модератор | `/begin [yes\|no]` | без аргумента — вопрос с кнопками «Начать» и «Отмена»; `yes` — начать кампанию: статус `active`, завязка истории от рассказчика (при сбое — стартовая сцена жанра; [ADR-0018](../decisions/0018-opening-scene.md)) и первый раунд через outbox (вне игрового окна — время первого раунда); нужен хотя бы один персонаж | готово |

| Группа, владелец или модератор, только dev | `/replay <номер>` | воспроизвести разрешённый раунд по снимку, намерениям и seed и сравнить с журналом событий (S06) | готово |
| Группа, владелец или модератор, только dev | `/round [номер]` | карточка раунда для разбора: статус, попытки и причина сбоя, заявки с итогами, метрики шагов и модели; без номера — последний раунд | готово |
| Группа, владелец или модератор, только dev | `/reset` | сброс игры в черновик для повторного прогона: раунды, заявки, события, итоги, сообщения и сохранённые ответы модели удалены, мир свёрнут до стартовой клетки шаблона (пункт 27), персонажи на ней с полным HP; участники и персонажи остаются | готово |
| Оба | `/status` | состояние игры: формат, режим, сезон, настройки, кворум, участники, персонажи, фракции, группы с участниками и клеткой (имя и координаты), текущий раунд (дедлайн, заявок из кворума), предыдущий раунд (разрешён, пропущен или не разрешён с причиной), следующий раунд или причина простоя (не запущена, пауза, игровое окно, завершена); в личке — текущая игра | готово |
| Группа, администратор игры, владелец или модератор | `/finish [yes\|no]` | без аргумента — вопрос с кнопками «Завершить» и «Отмена»; `yes` — завершить игру: открытый раунд закрывается и разрешается при хотя бы одной заявке без кворума, финальная хроника шаблоном (причина, раунды, итог персонажей), статус `finished`; те же действия выполняет планировщик по границам `max_rounds` и `ends_at` | готово |

| Личка | `/start [deep link]` | открыть приватный канал (`users.started_at`); `join_<код>` — войти в игру и создать персонажа, `setup_<код>` — настройка игры админом | готово |
| Оба | `/help` | команды по контексту; под сообщением кнопки-ссылки на разделы руководства игрока (`GUIDE_URL`) | готово |
| Личка | `/me` | кто я, открыта ли личка, чаты с правами, игры и персонажи | готово |
| Личка | `/join <код>` | присоединиться к игре по коду; затем диалог создания персонажа (фракция → никнейм → пол → архетип → очки → описания), итог — карточка и что дальше по статусу игры (`round.Welcome`, B23) | готово |
| Личка | `/party` | карточка группы персонажа (пункт 19, [ADR-0016](../decisions/0016-parties.md), [ADR-0017](../decisions/0017-party-mandatory.md)): своя группа (имя, клетка с координатами, участники со статусами; лидер скрыт) и остальные группы; команд создания, входа и выхода нет — группы собирает код: при `/begin` все в одной, новичок в идущей игре — в группу своей локации, иначе в новую в пределах `max_parties`, иначе в ближайшую; разделение и удержание — движок в раунде (S14) | готово |

| Личка | `/create` | создать персонажа в текущей игре, если его нет | готово |
| Личка | `/cancel` | прервать диалог настройки или создания персонажа | готово |
| Личка | `/bio <текст>`, `/secret <текст>` | открытое и скрытое описание до 100 символов; без текста — показать оба описания (B28) | готово |
| Личка | `/knowledge` | полный список знаний персонажа, длинный — несколькими сообщениями до 3500 символов (B28) | готово |
| Личка, группа | `/act <текст>` | подать заявку открытого раунда (в личке — текущей игры пользователя, в группе — игры чата, текст виден всем участникам; текст без команды в личке вне диалога при активном персонаже и открытом раунде принимается так же, ответ «Принято как заявка на раунд N», журнал `implicit_act`; иначе подсказка про команды): до 500 символов, одна на раунд (повтор отклоняется; замена только при настройке разработчика `allow_resubmit`), ответ с номером раунда и дедлайном; вне раунда, на паузе или выбывшим персонажем — отказ с причиной. До пункта 08 разбираются типовые команды: `идти <выход>`, `осмотреть [объект]`, `открыть <объект> [force]`, `помочь <персонаж>`, `ждать`; свободный текст — итог «не понята». С пункта 08 все заявки через интерпретатор. Аргумент `#<раунд>:<локация>:<объект>:<подход>` — ссылка варианта с кнопки под личным сообщением (пункт 18): заявкой становится название подхода, принимается только для открытого раунда с этим номером и существующего подхода; переход — объект `move` и номер направления (пункт 27), заявкой становится «идти на север: Лес» | готово |
| Личка | `/journal` | последние хроники игры и прошлых сезонов (пункт 16); приватные итоги исключены из плана (решение 2026-10-10) | план |
| Личка | `/goal`, `/goal set <текст>`, `/goal drop` | личная сюжетная цель и её шаги (пункт 17, поздний этап) | план |
| Личка | `/games [номер]` | мои игры; с номером — выбрать текущую (`users.current_game_id`); при нескольких играх кнопки выбора | готово |
| Личка, владелец бота (`BOT_OWNER_ID`) | `/llm`, `/llm use <profile> [game_id]`, `/llm reset <game_id>`, `/llm add <name> <provider> <model_interpreter> <model_narrator> [effort]`, `/llm test [profile]` | профили LLM: показать (с провайдерами и профилем текущей игры), выбрать для бота или игры, вернуть игру к глобальному, добавить, проверить живым вызовом по схеме | готово |

## Кнопки

Inline-кнопки под сообщениями (пункт 18, [ADR-0015](../decisions/0015-telegram-buttons.md)). Данные кнопки: `/команда аргументы` → та же команда того же пользователя в том же чате; `@шаг ответ` → ответ на вопрос диалога, применяется только на этом шаге, иначе бот повторяет текущий вопрос. После нажатия кнопки снимаются с сообщения, кроме отказа в правах. Повтор нажатия — второй update, который упирается в правила сценария (заявка уже принята, шаг отвечен, раунд закрыт).

| Где | Кнопки | Что дублируют |
|---|---|---|
| Диалог создания персонажа (личка) | фракции; «Мужской», «Женский», «Не указывать»; архетипы; «Автоматически», «Вручную»; «Пропустить» у описаний; на шагах с вводом текстом кнопок нет; под итогом (B23) — варианты хода открытого раунда (`/act #…`); ссылка «Перейти в чат игры», если бот администратор с правом приглашать (B24, ADR-0022). Кнопки «Прервать» нет (B33): начать заново — повторный `/create`, `/cancel` остаётся запасным путём без кнопки | ответ текстом на шаг; действие своими словами |
| Диалог настройки игры (личка) | жанры; 10/20/30/60 минут; часовые пояса России; «Без окна»; кворум 1/2/3/5; «Оставить как есть» на каждом шаге; кнопки «Прервать» нет (B33): прерванная настройка оставляла бы игру полунастроенной, а неотвеченные параметры и так сохраняют значения по умолчанию | ответ текстом или `-` |
| Личное «раунд открыт» и уведомление о заявке | по кнопке на подход в локации персонажа | `/act #ссылка` = `/act <название подхода>` |
| Группа: `/begin`, `/finish` | «Начать» / «Завершить», «Отмена» | `/begin yes\|no`, `/finish yes\|no` |
| Группа: ответ о паузе | «Возобновить» | `/pause` |
| `/games` при нескольких играх | по кнопке на игру | `/games <номер>` |
| `/help` | ссылки на разделы руководства | — (`GUIDE_URL`, без него кнопок нет) |

Reply-клавиатура лички (B29, [ADR-0021](../decisions/0021-reply-keyboard.md)): постоянные кнопки под полем ввода по статусу пользователя. Нажатие отправляет подпись текстом, бот сопоставляет её с командой (`app/bot/keyboard.go`).

| Статус | Кнопки | Команды |
|---|---|---|
| Есть персонаж в незавершённой игре | «Персонаж», «Описание», «Знания»; «Группа», «Квесты»; в поле ввода подсказка «Опишите действие…» (во время диалога без неё) | `/character`, `/bio`, `/knowledge`, `/party`, `/quests` |
| Иначе | клавиатура снята (`ReplyKeyboardRemove`) | — |

Набор считается при каждом ответе бота в личку без inline-кнопок (у сообщения Telegram одна клавиатура), поэтому следует за статусом сам: перед итогом создания персонажа приходит подсказка с клавиатурой, после завершения игры её снимает следующий ответ бота. Кнопки `/act` нет: reply-кнопка отправляет текст сразу, а заявка и так пишется обычным сообщением (B17).

## Ограничения платформы

- Бот не пишет пользователю первым; доступ к игре после `/start`.
- Добавление и удаление бота в группе приходит как `my_chat_member`; команды в группе доступны и при включённом privacy mode.
- Лимит длины сообщения; длинные тексты делятся.
- Данные кнопки до 64 байт: вариант сцены передаётся ссылкой, не названием; клавиатура игрового сообщения хранится в `messages_outbox.keyboard`.
