# Команды Telegram

Реестр команд MVP (готовые и планируемые); обновляется вместе с `internal/app/bot`. Описание реализованных команд для пользователей — [руководство игрока](../../guide/commands.md).

## Принципы

- Всё управление игрой — слеш-команды `/name [аргументы]` (решение руководителя). Кнопки и inline-клавиатуры Telegram — пункт 18 (следующий после сквозного раунда); до него никакой логики через callback-кнопки.
- У каждой команды объявлены контексты: группа, личка или оба; наборы в группе и личке пересекаются не полностью. Команда в чужом контексте получает подсказку, где её использовать.
- Меню команд Telegram (`setMyCommands`) регистрируется по этому реестру: личка; группа для всех участников — только команды игры здесь и сейчас (`/help`, `/status`, `/act`); владелец и модераторы чата получают в своём чате меню с административными командами (`/chat /mod /owner /create /begin /pause /finish`, в dev `/next /replay /round /reset`) через область `chat_member` — при старте бота, добавлении бота в группу, регистрации чата командой, `/mod add`, `/owner`; `/mod remove` и смена владельца снимают его (B20). `/ping` и `/llm` ни в одно меню не входят. `/help` перечисляет все команды контекста. Права проверяет код при выполнении, меню — только подсказка; клиент Telegram обновляет меню с задержкой.
- Многошаговые сценарии (настройка игры, создание персонажа) — диалог в личке: бот задаёт вопрос, игрок отвечает текстом; состояние в таблице `dialogs` (ADR-0008); ответ «-» оставляет значение по умолчанию; каждый параметр также доступен отдельной командой (`/set <параметр> <значение>`).
- Лимиты входящих: 20 сообщений в минуту на пользователя, текст до 1000 символов. В группе неизвестные команды игнорируются (команды других ботов), в личке — подсказка `/help`.

| Контекст | Команда | Назначение | Статус |
|---|---|---|---|
| Любой | `/ping` | проверка: версия сборки, окружение, время сервера | готово |
| Группа | `/chat` | владелец, модераторы, статус бота, текущая игра | готово |
| Группа, владелец | `/mod add\|remove @user` | назначить или снять модератора чата (пользователь должен быть известен боту) | готово |
| Группа, владелец | `/owner @user` | передать владение чатом | готово |
| Группа, владелец или модератор | `/create` | создать мир (черновик, сезон 1, фракции жанра), запустить диалог настройки в личке админа или дать ссылку `start=setup_<код>` | готово |
| Группа, владелец или модератор | `/begin` | начать кампанию: статус `active`, стартовая сцена жанра и первый раунд через outbox (вне игрового окна — время первого раунда); нужен хотя бы один персонаж | готово |
| Группа, владелец или модератор | `/pause` | пауза / возобновление: на паузе раунды не открываются, открытый раунд ждёт и при возобновлении получает новый дедлайн; снимает и автопаузу после `pause_after_skipped` пропущенных подряд раундов (B11) | готово |
| Группа, владелец или модератор, только dev | `/next` | закрыть открытый раунд сейчас и открыть следующий независимо от окна; ответ сообщает, если игра после закрытия встала на паузу или завершилась | готово |
| Группа, владелец или модератор, только dev | `/replay <номер>` | воспроизвести разрешённый раунд по снимку, намерениям и seed и сравнить с журналом событий (S06) | готово |
| Группа, владелец или модератор, только dev | `/round [номер]` | карточка раунда для разбора: статус, попытки и причина сбоя, заявки с итогами, метрики шагов и модели; без номера — последний раунд | готово |
| Группа, владелец или модератор, только dev | `/reset` | сброс игры в черновик для повторного прогона: раунды, заявки, события, итоги и сообщения удалены, персонажи на стартовой локации с полным HP, объекты локаций из шаблона; участники и персонажи остаются | готово |
| Оба | `/status` | состояние игры: формат, режим, сезон, настройки, кворум, участники, персонажи, фракции, текущий раунд (дедлайн, заявок из кворума), предыдущий раунд (разрешён, пропущен или не разрешён с причиной), следующий раунд или причина простоя (не запущена, пауза, игровое окно, завершена); в личке — текущая игра | готово |
| Группа, администратор игры, владелец или модератор | `/finish` | завершить игру: открытый раунд закрывается и разрешается при хотя бы одной заявке без кворума, финальная хроника шаблоном (причина, раунды, итог персонажей), статус `finished`; те же действия выполняет планировщик по границам `max_rounds` и `ends_at` | готово |
| Группа, администратор игры | `/season [название]` | сериал: закрыть сезон, открыть следующий стартовой сценой | план |
| Личка | `/start [deep link]` | открыть приватный канал (`users.started_at`); `join_<код>` — войти в игру и создать персонажа, `setup_<код>` — настройка игры админом | готово |
| Оба | `/help` | команды по контексту | готово |
| Личка | `/me` | кто я, открыта ли личка, чаты с правами, игры и персонажи | готово |
| Личка | `/join <код>` | присоединиться к игре по коду; затем диалог создания персонажа (фракция → никнейм → пол → архетип → очки → описания) | готово |
| Личка | `/party`, `/party create <имя>`, `/party join <имя>`, `/party leave` | группа персонажа для общей истории (на старте до 3 групп) | план |
| Личка, администратор игры | `/set <параметр> <значение>` | параметр текущей игры: `title genre round_minutes timezone play_window ends_at max_rounds min_answers faction_good/evil`; `ends_at` только командой, в диалог настройки не входит; без аргументов — список | готово |
| Личка | `/character` | карточка: никнейм, пол, архетип, фракция, статус, HP, характеристики, навыки, инвентарь, описания | готово |
| Личка | `/create` | создать персонажа в текущей игре, если его нет | готово |
| Личка | `/cancel` | прервать диалог настройки или создания персонажа | готово |
| Личка | `/bio <текст>`, `/secret <текст>` | открытое и скрытое описание до 100 символов | готово |
| Личка, группа | `/act <текст>` | подать заявку открытого раунда (в личке — текущей игры пользователя, в группе — игры чата, текст виден всем участникам; текст без команды в личке вне диалога при активном персонаже и открытом раунде принимается так же, ответ «Принято как заявка на раунд N», журнал `implicit_act`; иначе подсказка про команды): до 500 символов, одна на раунд (повтор отклоняется; замена только при настройке разработчика `allow_resubmit`), ответ с номером раунда и дедлайном; вне раунда, на паузе или выбывшим персонажем — отказ с причиной. До пункта 08 разбираются типовые команды: `идти <выход>`, `осмотреть [объект]`, `открыть <объект> [force]`, `помочь <персонаж>`, `ждать`; свободный текст — итог «не понята». С пункта 08 все заявки через интерпретатор | готово |
| Личка | `/journal` | последние хроники игры и прошлых сезонов (пункт 16); приватные итоги исключены из плана (решение 2026-10-10) | план |
| Личка | `/goal`, `/goal set <текст>`, `/goal drop` | личная сюжетная цель и её шаги (пункт 17, поздний этап) | план |
| Личка | `/games [номер]` | мои игры; с номером — выбрать текущую (`users.current_game_id`) | готово |
| Личка, владелец бота (`BOT_OWNER_ID`) | `/llm`, `/llm use <profile> [game_id]`, `/llm reset <game_id>`, `/llm add <name> <provider> <model_interpreter> <model_narrator> [effort]`, `/llm test [profile]` | профили LLM: показать (с провайдерами и профилем текущей игры), выбрать для бота или игры, вернуть игру к глобальному, добавить, проверить живым вызовом по схеме | готово |

## Ограничения платформы

- Бот не пишет пользователю первым; доступ к игре после `/start`.
- Добавление и удаление бота в группе приходит как `my_chat_member`; команды в группе доступны и при включённом privacy mode.
- Лимит длины сообщения; длинные тексты делятся.
- Кнопки Telegram не используются до пункта 18; каждая кнопка дублирует существующую команду.
