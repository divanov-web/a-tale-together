# Massive D&D — проблемы реализации и гипотезы решений

> Дополнение к `massive_dnd_concept.md`, v0.1, 10.10.2026.  
> Исходные условия: независимые миры по Telegram-чатам, до 20 игроков, до 4 активных локаций, настраиваемые раунды и расписание, собственные RPG-механики.  
> Варианты ниже — гипотезы для прототипа, а не обязательная архитектура. **P0** — проверить в первом прототипе; **P1** — до регулярных партий; **P2** — по результатам тестов и роста.

## 1. Уделить внимание каждому игроку

| Приоритет | Проблема | Возможные решения |
|---|---|---|
| P0 | ИИ пропускает часть действий, особенно неброских. | ID каждого действия; обязательный результат на каждый ID; программная проверка полноты. |
| P0 | Красивый ответ не означает реального влияния на мир. | Хранить разрешённое действие и последствия отдельно; личный результат показывает фактический эффект. |
| P0 | Двадцать личных историй перегружают общий чат. | Краткие личные ответы каждому; общая хроника объединяет значимые события. |
| P1 | Один активный игрок постоянно становится главным героем. | Один основной ход на раунд; учёт внимания за несколько раундов; ротация сюжетных возможностей. |
| P1 | Тихие игроки выполняют проверки, но не получают интересных решений. | Персональные зацепки и роль в общей задаче; варианты следующего действия после результата. |
| P1 | Равное число упоминаний создаёт искусственную историю. | Гарантировать обработку всем; драматическое внимание распределять на протяжении сессии. |
| P1 | Нет времени на уточнение неоднозначного действия. | Уточнять до дедлайна; иначе применять заранее известное безопасное толкование. |
| P1 | Отсутствующие игроки тормозят партию или становятся лёгкими жертвами. | Раунд не ждёт всех; правила бездействия и заранее выбранные защитные автодействия. |
| P2 | Очередь 20 из 100 игроков устаревает и делает участие бессмысленным. | Отложить такую массовость; проверять актуальность заявки; связанные конфликты обрабатывать вместе. |

## 2. Пересечения и одновременность действий

| Приоритет | Проблема | Возможные решения |
|---|---|---|
| P0 | Два игрока забирают один предмет или расходуют один ресурс. | Группировать по объекту; разрешать конфликт движком; единственная запись результата. |
| P0 | Несколько действий противоречат друг другу: открыть дверь и забаррикадировать её. | Общая конфликтная группа; фиксированная инициатива, встречная проверка или явные фазы. |
| P0 | Порядок приёма сообщений случайно даёт преимущество. | Все заявки относятся к одному снимку; порядок исполнения определяется игровыми правилами. |
| P0 | Позднее действие использует последствия, ещё неизвестные персонажу. | Фиксировать знания на начало раунда; разрешать только заранее сформулированные условия. |
| P0 | Помощь, защита и совместная атака требуют общего расчёта. | Связи между action_id; согласованные групповые заявки; единое разрешение зависимой группы. |
| P1 | Игрок пишет цепочку из десяти действий за один ход. | Бюджет действий; выделение основного намерения; остальные шаги отклонить или отложить. |
| P1 | Условия образуют цикл: «делаю X, если другой сделает Y». | Ограничить условные команды; циклы разрешать отдельным правилом или запрашивать уточнение. |
| P1 | Действия в разных локациях влияют на общий объект или событие. | Строить зависимости по сущностям, а не только по локациям; общий этап разрешения. |
| P1 | Замена заявки происходит после начала исполнения. | Дедлайн и замороженный снимок; после заморозки замена относится к следующему раунду. |
| P1 | ИИ подыгрывает игрокам при конфликте и придумывает удобный исход. | Вероятности, приоритеты, ресурсы и броски определяет движок; ИИ описывает исход. |

## 3. Снять нагрузку с ИИ и перенести решения в движок

| Приоритет | Проблема | Возможные решения |
|---|---|---|
| P0 | ИИ каждый раз заново считает HP, деньги, доступность и проверки. | Чистые функции движка; серверная случайность; таблицы правил и структурированное состояние. |
| P0 | Свободный текст трудно превратить в однозначную команду. | ИИ извлекает тип, цель и параметры; движок валидирует; неоднозначность возвращается игроку. |
| P0 | Движок не знает, как разрешить творческое действие. | Небольшой каталог универсальных действий; ИИ предлагает проверку/эффект внутри разрешённых границ. |
| P0 | ИИ создаёт способности, предметы и факты прямо в повествовании. | Сначала структурированное предложение изменения, затем валидация и фиксация, затем описание. |
| P1 | Попытка закодировать весь мир превращает MVP в огромную RPG. | Минимальные характеристики и эффекты; заранее ограниченный сеттинг; расширение по реальным заявкам. |
| P1 | Простые повторяющиеся команды требуют дорогого разбора. | Кнопки и шаблоны для типовых ходов; свободный текст — дополнительный путь. |
| P1 | На каждое фоновое действие NPC вызывается ИИ. | Правила, состояния и таймеры NPC; ИИ только для важных диалогов и сюжетных решений. |
| P1 | Личные ответы расходуют токены на пересказ стандартных результатов. | Шаблоны для проверок и ресурсов; ИИ для содержательно новых последствий. |
| P1 | Одно и то же намерение приходится разбирать при каждом повторе. | Хранить структурированную команду; повторно проверять её условия в актуальном состоянии. |

**Предварительная граница ответственности:**

| Внутренний движок | ИИ |
|---|---|
| Время, лимиты, права, инвентарь, HP, броски, доступность целей | Понимание свободного текста и неоднозначностей |
| Зависимости, конфликты, применение разрешённых эффектов | Предложения для творческих действий в рамках схемы |
| Канонические факты, знания персонажей, журнал событий | Диалоги, сюжетные предложения, литературное описание |
| Проверка ID, схем, ссылок, числовых ограничений | Объединение уже рассчитанных событий в читаемую хронику |

Движок проверяет структуру и правила, но сам по себе не гарантирует смысловую корректность текста ИИ. Например, схема не обнаружит, что фраза «дверь открылась» противоречит неудачной проверке. Для критичных результатов полезны шаблоны и отдельная проверка повествования по журналу событий.

## 4. Уменьшение токенов без потери действий и фактов

| Приоритет | Проблема | Возможные решения |
|---|---|---|
| P0 | Полная история чата быстро раздувает запрос. | Текущее состояние + релевантные факты + последние события; архив отдельно. |
| P0 | Сжатие заявок теряет условия, цели и ограничения игрока. | Сохранять структурированное намерение и оригинал; уточнять неоднозначность, не стирать её. |
| P0 | Общее резюме забывает слабозаметные действия и обещания. | Хранить действия отдельно по ID; обещания и нерешённые задачи — в реестре фактов. |
| P0 | Короткий ответ ИИ обрывается до результата последнего игрока. | Бюджет выхода по числу действий; компактная схема; проверка пропусков; адресный повтор. |
| P1 | В запрос попадают все характеристики и инвентарь всех игроков. | Передавать поля, необходимые текущим действиям; остальное считать движком. |
| P1 | Локальный запрос получает весь мир и чужие секреты. | Контекст конкретной сцены и зависимости; выборка по правам знания и видимости. |
| P1 | Выборка по похожести не находит важный, но лексически далёкий факт. | Сначала связи сущностей и обязательные факты; поиск по похожести только как дополнение. |
| P1 | Многократное резюмирование постепенно искажает прошлое. | Резюме строить по каноническим событиям; факты хранить с источником, статусом и версией. |
| P1 | Одинаковые правила повторяются в нескольких запросах. | Компактные версии правил по этапам; стабильный префикс; кэширование, если доступно у провайдера. |
| P1 | Слишком короткие ID и кодировки делают контекст непонятным модели. | Короткие стабильные ID с понятными именами; измерять токены и ошибки вместе. |
| P1 | Предварительный разбор всех сообщений сам становится дорогим. | Принимать одну текущую заявку; разбор по необходимости; лимит бесплатных уточнений и длины текста. |

**Что нельзя выкидывать ради экономии:** ID и автор действия, целевая сущность, намерение, условия, существенные ограничения, версия исходного состояния, нужные знания персонажа и ссылки на зависимости. Для этапа описания — итоговый статус, фактические последствия и видимость результата. Форма этих данных может быть компактной; смысл должен сохраняться.

## 5. Несколько ИИ-запросов за раунд

Один вызов на раунд не является целью сам по себе. Важнее стоимость полного раунда, время до результата и число ошибок. Разбиение уменьшает размер отдельных запросов, но может увеличить суммарные токены из-за повторения контекста.

| Схема | Плюс | Сложность / ограничение |
|---|---|---|
| Один запрос на интерпретацию всех действий + один на описание | Простой прототип; общий контекст | Большой пакет, риск пропуска; разбор может потребовать уточнений |
| Отдельный разбор каждой заявки + общее описание | Легко уточнять и повторять отдельное действие | Много вызовов и повторяемого контекста |
| Разбор маленькими пакетами + общее описание | Компромисс по размеру и числу вызовов | Межпакетные зависимости должен собрать движок |
| Запросы по независимым конфликтным группам | Локальные контексты; возможна параллельная обработка | Скрытая зависимость разрушает независимость |
| Запросы по локациям + общая хроника | Удобно для нескольких сцен | Общие NPC, ресурсы и события требуют координации |
| Отдельные личные тексты + публичная хроника | Проще ограничить раскрытие секретов | Дополнительная стоимость и риск расхождения описаний |

### Возможный конвейер MVP

1. **Сбор:** сохранить оригиналы заявок и заморозить снимок раунда.
2. **Интерпретация:** разобрать свободный текст небольшими пакетами; типовые команды разобрать без ИИ.
3. **Разрешение:** движок проверяет условия, связывает конфликты, делает броски и получает события.
4. **Сюжетные предложения, если нужны:** ИИ предлагает новые события по уже рассчитанным итогам; движок валидирует их. Такие события обычно задают следующий раунд, а не меняют задним числом исходы текущего.
5. **Фиксация:** сохранить одно согласованное состояние и журнал результатов.
6. **Описание и доставка:** построить личные ответы и общую хронику из разрешённых для адресата событий; сохранить тексты для повторной отправки.

### Проблемы самого разбиения

| Приоритет | Проблема | Возможные решения |
|---|---|---|
| P0 | Каждый запрос придумывает свою версию общего NPC или объекта. | Один снимок с версиями и ID; общие эффекты сводит движок. |
| P0 | Локальные результаты согласованы внутри пакета, но противоречат друг другу. | Не применять локальные предложения сразу; сначала общий расчёт зависимостей. |
| P0 | Итоговый рассказ снова интерпретирует действия и меняет результат. | Передавать ему уже разрешённые события; запретить пересчёт; критичные исходы описывать шаблонами. |
| P1 | Один медленный запрос задерживает весь раунд. | Ограничение параллелизма и времени; повтор только сбойного пакета; заранее определённый режим деградации. |
| P1 | Повтор запроса повторно расходует ресурсы или меняет бросок. | Сохранённые броски и результаты; идемпотентное применение; повтор ИИ не запускает расчёт заново. |
| P1 | Несколько моделей отличаются в трактовке правил. | Общая схема и примеры; версия модели; сравнение на одном наборе сложных действий. |

## 6. Целостность мира, секреты и свобода действий

| Приоритет | Проблема | Возможные решения |
|---|---|---|
| P0 | Рассказ и база данных описывают разные миры. | Канонический журнал событий; описание после фиксации; проверка важных утверждений. |
| P0 | Публичная хроника раскрывает секретный ход или находку. | Видимость каждого факта; публичный запрос получает только разрешённые события. |
| P0 | Личный ответ знает то, чего персонаж не мог наблюдать. | Контекст знаний адресата; различать фактический исход и доступную ему информацию. |
| P0 | Игрок убеждает ИИ выдать себе предмет или переписать правила. | Текст — данные; ограниченные схемы; разрешения и эффекты проверяет сервер. |
| P1 | ИИ навязывает сюжет и обесценивает решения игроков. | Сюжетные предложения зависят от результатов; несколько путей продолжения; последствия провалов. |
| P1 | Ограничение четырёх локаций превращается в нелогичные запреты. | Маленький стартовый мир; объяснимые маршруты; фоновые путешествия; явно описанные ограничения. |
| P1 | Изобретательные игроки эксплуатируют расплывчатые проверки. | Универсальные правила эффектов и цены действий; журнал спорных случаев; расширение механик по нему. |
| P1 | PvP и тайные действия портят игру другим участникам. | Режим PvP на уровне мира; согласие на тяжёлые последствия; правила вмешательства администратора. |

## 7. Эксплуатация, Telegram и стоимость

Это проектные риски; конкретные ограничения платформы и выбранных API нужно проверить перед реализацией интеграций.

| Приоритет | Проблема | Возможные решения |
|---|---|---|
| P0 | Общая группа есть, а приватный канал с игроком ещё не готов. | Регистрация через личный чат; проверка готовности доставки до допуска к игре. |
| P0 | Один пользователь играет в нескольких мирах и отправляет ход не туда. | Явный выбор активной игры; подпись мира и раунда в ответах; подтверждение переключения. |
| P0 | Перезапуск сервера повторяет раунд или теряет заявки. | Состояния раунда, блокировка, транзакции, журнал событий и уникальные ключи обработки. |
| P0 | Результат записан, но Telegram-сообщение не доставлено. | Очередь доставки/outbox; повтор готового текста; не откатывать мир из-за доставки. |
| P1 | Повтор доставки создаёт дубли сообщений. | Хранить ID отправленного сообщения; учитывать неопределённый исход отправки; номер раунда в тексте. |
| P1 | Раунд не укладывается в интервал расписания. | Измерять весь конвейер; запрет перекрытия раундов одного мира; увеличивать интервал или упрощать обработку. |
| P1 | Ночная пауза и возобновление ломают игровые таймеры. | Отдельное логическое время мира; не догонять пропущенные раунды; правила дедлайна перед паузой. |
| P1 | Двадцать личных ответов и хроника приходят с разными задержками. | Ограниченная очередь отправки; статус обработки; деление длинных текстов; личный результат доступен по запросу. |
| P1 | Рост числа чатов резко увеличивает стоимость и конкуренцию за API. | Бюджеты на мир и сессию; глобальная очередь; справедливые лимиты между мирами. |
| P1 | Пользовательский спам расходует токены ещё до раунда. | Лимит длины и частоты; объединение замен; не отправлять каждое сообщение в ИИ автоматически. |
| P1 | Недоступность модели останавливает игру в разгар сессии. | Сохранить раунд; ограниченные повторы; пауза с объяснением; шаблонные ответы там, где расчёт завершён. |
| P1 | Обновление модели или правил меняет поведение действующей кампании. | Версии правил и промптов; закрепление версии на сессию; явная миграция состояния. |
| P1 | Секреты одного мира попадают в контекст другого. | game_id во всех выборках и задачах; изоляция доступа; тесты межмировых утечек. |
| P2 | Хранение приватных текстов и журналов становится избыточным. | Сроки хранения; минимум персональных данных; ограничение доступа к диагностике. |

## 8. Почему ИИ-разработка не снимает главную сложность

| Приоритет | Проблема | Возможные решения |
|---|---|---|
| P0 | Код быстро появляется, но правила одновременности остаются не определены. | Сначала примеры спорных ходов и ожидаемые исходы; затем реализация этих правил. |
| P0 | Нельзя оценить правильность результата без игрового эталона. | Набор сценариев: один предмет, помощь, встречные действия, секрет, устаревшая заявка, повтор раунда. |
| P1 | Проверка только JSON не замечает смысловых ошибок ИИ. | Сверка с эталонными сценариями; выборочный ручной разбор; не полагаться на ИИ-проверку как на гарантию. |
| P1 | Баг невозможно воспроизвести из-за случайности и меняющихся ответов. | Хранить снимок, броски, запросы, ответы и версии; воспроизведение движка без нового вызова модели. |
| P1 | Технически корректная игра оказывается скучной. | Ранние партии с 5, затем 20 игроками; измерять возвращаемость и субъективное влияние на историю. |

## 9. Что проверить первым

1. **Никто не потерян:** у каждой принятой заявки ровно один итоговый статус и доступный игроку результат.
2. **Конфликты разрешены:** предмет не дублируется; ресурсы не уходят в минус; взаимные действия имеют объяснимый порядок.
3. **Секреты сохранены:** публичный контекст не содержит приватных фактов; личные контексты ограничены знаниями адресата.
4. **Повтор безопасен:** сбой и повтор не меняют уже рассчитанный исход и не применяют эффект дважды.
5. **Экономия измерима:** сравнить полный контекст, выборку фактов и пакетную обработку на одинаковых раундах; считать вход/выход, стоимость, задержку и смысловые ошибки.
6. **Участие ощущается:** после 3–5 раундов спросить каждого игрока, где его решение повлияло на события и что осталось непонятным.

**Рабочая гипотеза:** на старте сложнее всего совместить свободные текстовые действия с общей причинностью мира. Экономить токены безопаснее через структурированное состояние, выборку нужных фактов и расчёт правил движком, чем через всё более короткое резюме всей партии.
