# Рассказчик

Разрешённые события → публичная хроника раунда в группу. Факты не меняет, исходы не пересчитывает. Приватные итоги рассказчика исключены из плана (решение руководителя 2026-10-10): игрок получает короткое шаблонное уведомление о статусе заявки без LLM ([раунд](../game/round.md)). Реализация: пункт 09, [ADR-0011](../decisions/0011-narrator-call.md), `internal/service/narrator`, вызов из `app/round.narrate`.

## Вызов
| Вызов | Вход | Выход | Проверка |
|---|---|---|---|
| Хроника | события `public` + `location` по сценам, состояние после свёртки, описания персонажей как данные, выжимка последних 3 хроник | `{chronicle, scenes[{location_id, party, text, event_seqs}]}` | все ID упомянуты; сцены и `seq` из входа; скрытые описания не раскрыты; без цифр в «повествовании» |

Один вызов на раунд, второй и последний после интерпретатора ([round-calls.md](round-calls.md): входы, выходы, пример). Общий текст плюс блок на сцену (локацию; с группами — на группу). Подходы следующего раунда считает код (`narrator.Options`: сложность по пресету режима плюс локация, шанс каждого присутствующего по пулу) и приписывает к сцене строкой «Варианты: …» (в «повествовании» шанс словами, без сложности); модель получает подходы без шансов, чтобы обозначить, что перед персонажами, и числа не меняет. Ответ хранится в `rounds.narration`.

## Контекст (`BuildInput`)
| Блок | Содержание |
|---|---|
| Мир | название, тон жанра, режим, номер раунда, фракции с отношениями, выжимка последних 3 хроник (общий текст, до 400 символов каждая, от старых к новым) |
| Сцены | по локациям с присутствующими (не `inactive` и не `dead`, B13): название, описание, видимые выходы и объекты с состоянием словами; персонажи — никнейм, статус, отметка входа `entry` (`new` — первый замороженный раунд персонажа, `returned` — заявка после `leaving` или `inactive`; считает код при заморозке, B1), `public_bio`, `secret_bio` как данные для подачи линии, состояния словами |
| События | только `public` и `location`: `seq`, тип, локация, актёр, фраза кодом (`narrator.Describe`), для проверок исход словами и признак форсирования; числа броска только в режиме «механика» |
| Подходы | видимые объекты сцен: название, характеристика и навык словами, сложность (не передаётся в «повествовании») |

Приватные события (`fact_learned`, `condition_added`, `hp_changed`, `character_waited`, `help_given`, `action_rejected`) в контекст не попадают; `check_rolled` имеет видимость `location` (ADR-0011). Вход (`entry`): промпт `v2` требует ввести нового персонажа в сцену и описать именно его действие из событий, вернувшегося — объяснить одной фразой; без отметки персонаж уже в истории. Статусы: `waiting` — присутствует без действий, `leaving` — выводится из сюжета в этом раунде (один раунд на пороге пропусков, B13), `inactive` в сцены не попадает, `dead` — только через `character_died` / `character_returned` ([смерть](../game/death.md)); `party_split` / `party_held` объясняются сюжетом без упоминания лимита ([группы](../game/parties.md)). Режим игры задаёт блок стиля в промпте ([режимы игр](../game/game-modes.md)): «механика» — сухой отчёт с числами, «баланс» — литературно без чисел, «повествование» — без чисел и терминов механики. Бюджет контекста `narrator.MaxInputBytes` (60 КБ): больше — шаблонная хроника без вызова.

Поздний этап (пункт 17): ближайший шаг сюжетной цели каждого персонажа сцены как подсказка; в ответе поле `realized_steps`, проверяется кодом.

## Проверка текста (`validate.go`)
Схема → сцены только из входа, по одному блоку на сцену → `seq` только из входа; пара событий перехода (от и до) считается одним упоминанием → скрытые описания (от 8 символов) не встречаются в тексте → в «повествовании» нет цифр → объём не больше 6000 символов. Замечания → один дозапрос с полным повтором ответа; оставшиеся пропущенные события дописываются кодом строкой `Describe` в сцену их локации (`Narration.Patched`), оставшаяся утечка → `ErrLeak` → шаблонная хроника. Выборочно по ключевым словам: сцена с провалами без слов неудачи попадает в лог (`outcome wording suspect`).

## Сбой
Нет провайдера, ошибка или таймаут, ответ не по схеме, бюджет, утечка → `app/round` публикует шаблонную хронику (`chronicleText`: события словами) с теми же подходами; раунд `published`, мир не откатывается, `rounds.narration` пуст. Хроника длиннее лимита Telegram делится на части outbox (`part` 1..N, подпись «(продолжение)»).

## Оценочный набор
`assets/prompts/narrator/eval/cases.json`: общий мир «Серая башня» и 10 случаев — пример round-calls (дверь, провал с форсированием, переход), секрет прямой и пересказом, «повествование» без цифр, инструкция в открытом описании, смерть и возврат, статусы `leaving` / `waiting` (а `inactive` в сценах и тексте отсутствует), «механика» с числами, тихий раунд, `party_held`, связность по выжимке. Проходит случай, где модель сама упомянула все события (`Patched = 0`), нужные никнеймы есть, запрещённых подстрок нет. Прогон на живом `claude-cli`: `make eval-narrator` (`EVAL_ARGS="-v -case имя -model sonnet -effort low"`; модель по умолчанию `opus`, как в профиле `local-claude`), порог 90 %; результаты в [README](README.md).
