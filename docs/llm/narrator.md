# Рассказчик

Разрешённые события → публичная хроника раунда в группу. Факты не меняет, исходы не пересчитывает. Приватные итоги рассказчика исключены из плана (решение руководителя 2026-10-10): игрок получает короткое шаблонное уведомление о статусе заявки без LLM ([раунд](../game/round.md)). Реализация: пункт 09, [ADR-0011](../decisions/0011-narrator-call.md), `internal/service/narrator`, вызов из `app/round.narrate`.

## Вызов
| Вызов | Вход | Выход | Проверка |
|---|---|---|---|
| Завязка и стартовый пакет | при `/begin`: название, жанр, тон, режим, фракции с отношениями, стартовая клетка шаблона (описание, местность, названия объектов как подсказка), задания на недостающих соседей по направлениям, задания на цель и сюжетный квест каждой фракции (пункт 28), ключи модели персонажа, персонажи только с открытыми данными | `{text, factions[{code, goal{text, stage}, quest{title, summary, stages[]}}], start, neighbors[]}` | текст 80–3000 символов, без цифр вне «механики», каждый персонаж упомянут по никнейму (один дозапрос, затем объём вне границ → шаблон жанра, [ADR-0018](../decisions/0018-opening-scene.md)); клетка и соседи по правилам пакета мира ([ADR-0019](../decisions/0019-world-generation.md)): без валидных объектов остаются объекты шаблона, пропущенный сосед — «Неизведанные земли»; цель и квест по правилам квестов ([ADR-0020](../decisions/0020-quests.md)): пропущенные — из шаблона жанра |
| Хроника и пакет мира | события `public` + `location` по сценам (группа в локации или персонажи без группы в локации, пункт 19), состояние после свёртки, описания персонажей как данные, выжимка последних 3 хроник; активные квесты для подсказок (`quests`, пункт 28); задания на достройку (`generate`, пункт 27) и по квестам (`generate.quests`, пункт 28) | `{chronicle, scenes[{scene_id, text, event_seqs}], world{cells[], neighbors[], quests[], stages[], goals[]}}`; код хранит `scenes[{location_id, party, text, event_seqs}]`, где `party` — подпись сцены | все ID упомянуты; сцены по `scene_id` и `seq` из входа; скрытые описания не раскрыты; без цифр в «повествовании»; пакет мира только по заданиям и лимитам, остаток — шаблон без дозапроса; квесты по заданиям, условия этапов только достижимые |

Один вызов на раунд, второй и последний после интерпретатора ([round-calls.md](round-calls.md): входы, выходы, пример). Общий текст плюс блок на сцену: группа в локации либо персонажи без группы в локации; игрокам блок подписан названием локации (внутренняя подпись «Группа (Локация)» хранит имя группы только для сопоставления сцен: названия групп игрокам и модели не показываются (решение руководителя 2026-10-13: механика групп геймдизайном не проработана)); в одной локации может быть несколько сцен, общие события локации упоминаются в одной из них ([группы](../game/parties.md), [ADR-0016](../decisions/0016-parties.md)). Подходы следующего раунда считает код (`narrator.Options`: сложность по пресету режима плюс локация, шанс каждого присутствующего по параметру; переходов среди вариантов нет — B36, ADR-0025) и приписывает к сцене строкой «Варианты: …» (в «повествовании» шанс словами, без сложности); модель получает подходы без шансов, чтобы обозначить, что перед персонажами, и числа не меняет. Ответ хранится в `rounds.narration`; ответ модели сохраняется по ключу задания в `generation_jobs` (повтор раунда берёт его без вызова, ADR-0019).

## Пакет мира (`world.go`, пункт 27)
| Что | Правило |
|---|---|
| Задания (`PlanTasks`) | занятые присутствующими клетки стадии `card` → детализация (до `model.MaxCellsPerRound` = 4, остальные шаблон без участия модели); недостающие соседи занятых клеток → карточки; сосед проверяется по всей карте игры, не только по снимку |
| Вход | блок `generate`: клетки (`location_id`, `x`, `y`, имя, местность, карточка, кто вошёл), соседи (`x`, `y`, направление, от какой клетки), лимиты, ключи характеристик и навыков модели персонажа; без заданий блока нет и ответ ждёт пустой `world` |
| Клетка (`validateCell`) | имя до 60 символов (пустое — имя карточки), описание до 600 (пустое — карточка), сложность 0–2, местность из задания; объекты до 2: ключ latin snake_case (из `key`, иначе из названия), название до 60, `state`, `hidden` → `hidden_until_revealed` |
| Подход (`validateApproach`) | `explore` или `interact`; характеристика и навык только из модели персонажа (без характеристики — без броска); сложность 1–9; `on_success`: `state`, `reveal` на скрытый объект той же клетки, `fact`; `on_fail`: `condition` из списка состояний, `damage` ≤ 2, `fact`; до 3 подходов, невалидный отброшен с замечанием |
| Сосед (`validateNeighbor`) | имя, местность одним словом, карточка одним предложением; `visible` → `hidden`, `distant_view` (до 200 символов) только у скрытого (ADR-0025); пустое имя или нет ответа — шаблон «Неизведанные земли» (видимый) |
| Шаблон (`TemplateWorld`) | сбой модели, нет провайдера, бюджет: клетка «Дорога» (имя карточки, если было) без объектов, соседи «Неизведанные земли»; `WorldPackage.Templated` считает закрытые шаблоном задания (метрика `world_templated`) |
| Запись (`app/round.applyWorld`) | строки клеток (со скрытостью и видом издалека у карточек) и объектов в транзакции раунда, события `cell_generated` (`source`: `model` / `template`) и `object_created` за событиями движка, свёртка в состояние; подписи сцен обновляются по новым именам |

## Квесты (`quests.go`, пункт 28)
| Что | Правило |
|---|---|
| Задания (`service/quest.Plan` → `Tasks.Quests`, `Stages`, `Goals`) | новый квест фракции (нет активного сюжетного — сразу; иначе по порогу от числа активных и счётчику открытых клеток, тип по свободным слотам с чередованием), размещение первого незакрытого этапа без клетки там, где персонаж фракции стоит на расстоянии ≥ `distance` от клетки предыдущего этапа, пересмотр цели после закрытого сюжетного квеста или первая версия |
| Вход | блок `quests` всегда: активные квесты (фракция, тип, название, смысл, цель, ближайший этап с клеткой и подсказкой `ConditionWordsFor`, закрытые этапы); в `generate.quests` задания и лимиты (`story_stages` 3–6, `side_stages` 2–4, `max_distance` 3, `condition_kinds`) |
| Квест (`validateQuests`) | фракция из задания (одна на задание), название ≤ 80, смысл ≤ 300, этапы не больше максимума типа (меньше минимума — замечание), ключи этапов в snake_case и уникальны, расстояние 1–3, вид условия из каталога (иначе `visited`), награда ≤ 200; без этапов — шаблон для обязательного сюжетного, иначе перенос |
| Этап (`validateStages`, `validateCondition`) | объекты по `validateObjects`, ключи не повторяют объекты клетки; условие принимается, если достижимо подходом клетки (`object_state` — подход ставит объекту состояние, `fact` — подход даёт факт слово в слово), иначе первое достижимое, иначе `visited`; пропущенное — шаблон «след» (`quest.TemplateStage`) |
| Цель (`validateGoals`) | текст ≤ 300 обязателен, стадия ≤ 200; пропущено — шаблон жанра или описание фракции |
| Шаблон (`TemplateQuests`) | обязательный сюжетный — `genres.template.story_quest` (иначе запасной трёхэтапный), побочный ждёт, этап — «след», цель — шаблон |
| Запись (`app/round.applyQuests`) | строки `quests`, `quest_stages`, `faction_goals` и объекты этапа; приватные события персонажам фракции `quest_issued`, `quest_stage_placed`, `goal_revised`; объекты — `object_created` в клетке; счётчик фракции минус порог |

## Контекст (`BuildInput`)
| Блок | Содержание |
|---|---|
| Мир | название, тон жанра, режим, номер раунда, фракции с отношениями, выжимка прошлого: завязка истории (`games.opening_scene`, до 1200 символов) первой строкой, затем общий текст последних 3 хроник (до 400 символов каждая, от старых к новым) |
| Сцены | по группам внутри локаций (`scene_id`; группы раньше одиночек; имя группы и лидер не передаются — промпт `v6` велит не придумывать названий; `v7` описывает скрытого соседа только по `distant_view`) с присутствующими (не `inactive` и не `dead`, B13): название, описание, координаты, стадия и местность, выходы по направлениям с именем соседа и карточкой неописанного соседа либо `hidden` и `distant_view` у скрытого (без имени и карточки, ADR-0025), объекты с состоянием словами; персонажи — никнейм, пол `gender` (`male`/`female`, без поля — не указан; B18), статус, отметка входа `entry` (`new` — первый замороженный раунд персонажа, `returned` — заявка после `leaving` или `inactive`; считает код при заморозке, B1), `public_bio`, `secret_bio` как данные для подачи линии, состояния словами |
| События | только `public` и `location`: `seq`, тип, локация, актёр, фраза кодом (`narrator.Describe`), для проверок исход словами и признак форсирования; числа броска только в режиме «механика»; у `party_split` и `party_held` актёр — группа, фраза называет направление и желавших иначе, лидера не называет |
| Подходы | видимые объекты сцен: название, характеристика и навык словами, сложность (не передаётся в «повествовании») |

Приватные события (`fact_learned`, `condition_added`, `hp_changed`, `character_waited`, `help_given`, `action_rejected`) в контекст не попадают; `check_rolled` имеет видимость `location` (ADR-0011). Вход (`entry`): промпт `v3` (`v2` + сцены по группам и правила `party_split` / `party_held`) требует ввести нового персонажа в сцену и описать именно его действие из событий, вернувшегося — объяснить одной фразой; без отметки персонаж уже в истории. Статусы: `waiting` — присутствует без действий, `leaving` — выводится из сюжета в этом раунде (один раунд на пороге пропусков, B13), `inactive` в сцены не попадает, `dead` — только через `character_died` / `character_returned` ([смерть](../game/death.md)); `party_split` / `party_held` объясняются сюжетом без упоминания лимита ([группы](../game/parties.md)). Режим игры задаёт блок стиля в промпте ([режимы игр](../game/game-modes.md)): «механика» — сухой отчёт с числами, «баланс» — литературно без чисел, «повествование» — без чисел и терминов механики. Бюджет контекста `narrator.MaxInputBytes` (60 КБ): больше — шаблонная хроника без вызова.

Поздний этап (пункт 17): ближайший шаг сюжетной цели каждого персонажа сцены как подсказка; в ответе поле `realized_steps`, проверяется кодом.

## Проверка текста (`validate.go`)
Схема → сцены только из входа по `scene_id`, по одному блоку на сцену → `seq` только из входа; пара событий перехода (от и до) считается одним упоминанием → скрытые описания (от 8 символов) не встречаются в тексте → в «повествовании» нет цифр → объём не больше 6000 символов. Замечания → один дозапрос с полным повтором ответа; оставшиеся пропущенные события дописываются кодом строкой `Describe` в первую сцену их локации (`Narration.Patched`), оставшаяся утечка → `ErrLeak` → шаблонная хроника. Выборочно по ключевым словам: сцена с провалами без слов неудачи попадает в лог (`outcome wording suspect`).

## Сбой
Нет провайдера, ошибка или таймаут, ответ не по схеме, бюджет, утечка → `app/round` публикует шаблонную хронику (`chronicleText`: события словами) с теми же подходами; раунд `published`, мир не откатывается, `rounds.narration` пуст. Хроника длиннее лимита Telegram делится на части outbox (`part` 1..N, подпись «(продолжение)»).

## Завязка и стартовый пакет (`Opening`)
Один вызов на игру при `/begin` ([ADR-0018](../decisions/0018-opening-scene.md), [ADR-0019](../decisions/0019-world-generation.md)): роль `opening` на модели рассказчика профиля, промпт `assets/prompts/narrator/opening-v4.md` (`v4` = `v3` + видимость соседей: `visible`, `distant_view`, ADR-0025), схема `{text, factions, start, neighbors}` (пункт 28: цель и сюжетный квест каждой фракции). Модель придумывает начало по тону жанра, названию мира, фракциям, стартовой клетке и открытым описаниям персонажей: представляет каждого в сцене, оставляет открытую угрозу, не решает за персонажей, не называет чисел вне «механики»; описывает стартовую клетку с объектами (подсказка — объекты шаблона), даёт карточки недостающих соседей по направлениям, цель и первый сюжетный квест каждой фракции (`factions[]`). Текст уходит сообщением «начало истории» в группу, хранится в `games.opening_scene` и даётся хроникам первой строкой выжимки; клетка и соседи записываются кодом (`app/round.startPackage`), цели и квесты — `startQuests` без событий. Сбой, ответ не по схеме или объём вне границ после дозапроса → стартовая сцена и клетка шаблона жанра, соседи «Неизведанные земли», цели и квесты из шаблона (`narrator.TemplateQuests`). Живая проверка: `make eval-narrator EVAL_ARGS="-opening"` (печатает завязку, клетку с объектами и соседей по миру первого случая набора, замечания кода, токены). Измерение 2026-10-11 (`opening-v1`, только текст) на `opus`/`low`: один вызов, 2 510 / 808 токенов, 12 с; `opening-v2` и `opening-v3` (с пакетом и квестами) ещё не измерялись.

## Оценочный набор
`assets/prompts/narrator/eval/cases.json`: общий мир «Серая башня» на сетке и 12 случаев — пример round-calls (дверь, провал с форсированием, переход), секрет прямой и пересказом, «повествование» без цифр, инструкция в открытом описании, смерть и возврат, статусы `leaving` / `waiting` (а `inactive` в сценах и тексте отсутствует), «механика» с числами, тихий раунд, `party_held`, связность по выжимке, достройка мира (`world_generation`: группа вошла в карточку «Опушка», задание на клетку и трёх соседей; ожидание `world`: одна клетка хотя бы с одним объектом, три соседа, без шаблонов), квесты (`quest_generation`, пункт 28: побочный квест Ордену, размещение этапа на опушке, пересмотр цели Гильдии; ожидание: квест, этап с достижимым условием, цель, в хронике нет слова «квест»). Проходит случай, где модель сама упомянула все события (`Patched = 0`), нужные никнеймы есть, запрещённых подстрок нет, пакет мира по ожиданию. Прогон на живом `claude-cli`: `make eval-narrator` (`EVAL_ARGS="-v -case имя -model sonnet -effort low"`; модель по умолчанию `opus`, как в профиле `local-claude`), порог 90 %; результаты в [README](README.md).
