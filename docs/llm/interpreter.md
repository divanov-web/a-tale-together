# Интерпретатор

Текст заявки → намерение по [каталогу действий](../game/actions.md). Не решает, не бросает, не создаёт.

## Схема ответа
Один вызов на раунд после дедлайна: вход — сцены с заявками всех персонажей, выход — массив намерений по `model.Intent` (решение руководителя 2026-10-10).
```json
{
  "intents": [
    {
      "submission_id": 41,
      "action_type": "interact",
      "target": "cellar_door",
      "approach_idx": 1,
      "push": false,
      "ambiguities": []
    },
    {
      "submission_id": 42,
      "action_type": "interact",
      "target": "",
      "attribute": "agility",
      "skill": null,
      "risk": "hard",
      "on_success": {"fact": "Ров преодолён: на другом берегу видна тропа к башне."},
      "on_fail": {"condition": "wounded"},
      "push": true,
      "ambiguities": []
    },
    {
      "submission_id": 43,
      "action_type": "explore",
      "target": "",
      "ambiguities": ["два сундука: у окна и у двери"],
      "fallback": {"action_type": "explore", "target": "chest_window"}
    }
  ]
}
```
- `action_type` только из каталога; неизвестное → `ambiguities` + `fallback`.
- `target` — ключ видимого объекта, ключ направления выхода (`north`/`south`/`west`/`east`; код принимает и имя видимого соседа, нормализуя в направление; имя скрытого соседа не сопоставляется, ADR-0025) или никнейм персонажа из переданного контекста; пустой — действие в локации.
- Подход объекта (`approach_idx`) предпочтительнее свободного испытания: сложность и эффекты берутся из данных локации.
- Свободное испытание: `attribute` и `skill` из модели персонажа, `risk` (`normal / hard / extreme` → сложность 4 / 7 / 9, назначает код), эффекты обеих ветвей заранее из списка: `fact` (знание персонажа), `condition` (состояние), `move` (выход), `reveal` (объект), `damage` (в лимите режима). Изменение состояния объектов — только через подходы из данных локации.
- `push` — игрок готов рисковать (форсировать бросок). Цепочка действий → первое действие, остальное в `ambiguities` с пометкой `extra`.
- Заявка без `attribute` и подхода, не `move`/`wait`/`help`/`explore` — безопасное толкование.

## Жизнь свободного действия
1. Игрок: `/act перепрыгиваю ров с разбега, чтобы попасть к башне` — текст лежит в заявке как данные до дедлайна.
2. Дедлайн: снимок раунда; все заявки, и выбранные из предложенных подходов, и свои, уходят в один вызов интерпретатора вместе с контекстом сцен (решение руководителя 2026-10-10); разбор кодом только при сбое модели.
3. Интерпретатор назначает до броска: `interact`, Ловкость, риск `hard`, `on_success` — факт «ров преодолён, тропа к башне», `on_fail` — состояние «ранен», `push` по тексту.
4. Код валидирует: характеристика и навык есть в модели, цель видна, риск из таблицы, эффекты из списка. Невалидно — повтор, затем `fallback` или `wait`.
5. Движок: сложность = таблица риска (7) + сложность локации; параметр по персонажу; бросок d100 по seed; форсирование по `push` и режиму. Выбирается ветвь: события `check_rolled` и `fact_learned` при успехе, `condition_added` при провале. Снимок и seed позволяют воспроизвести.
6. Рассказчик (второй и последний вызов раунда) получает события и пишет хронику; исход и факты он не меняет.
Модели не нужен отдельный вызов «после броска»: последствия обеих ветвей заданы до броска, а их описание — задача рассказчика.

## Контекст вызова
`service/interpreter.BuildInput` по снимку (пункт 08; сетка с пункта 27): модель персонажа (ключи и названия характеристик и навыков), сцены по локациям — название, описание, сложность, выходы по направлениям к существующим соседям (`to` — ключ направления, `title` — «на север: Лес»; у скрытого соседа «на восток: неизведанная территория (дым над крышами)» без имени, B36), видимые объекты с подходами (`idx`, `action`, `title`, `attribute`, `skill`; эффекты подходов не передаются), персонажи сцены (ID, никнейм, пол `gender` при наличии (B18), статус, характеристики, ненулевые навыки, состояния, последние 3 знания до 160 символов); заявки всех персонажей раунда в одном блоке `submissions` (`submission_id`, `character_id`, никнейм, текст). Скрытые объекты, имена скрытых соседей, выбывшие персонажи, описания `secret_bio` не передаются. Каталог действий, список эффектов и таблица риска — в системной части (`assets/prompts/interpreter/v3.md`; `v2` = `v1` с выходами по направлениям, `v3` = `v2` с переходом в скрытого соседа по направлению или примете, без угадывания имени).

## Валидация
Код (`validate.go`): схема → тип из каталога → цель из снимка (`move`: выход по направлению или имени видимого соседа, нормализуется в ключ направления; `explore`/`interact`: видимый объект, нормализуется в `key`; `help`: персонаж той же локации) → `approach_idx` в пределах подходов объекта → свободное испытание: характеристика и навык из модели персонажа, риск из таблицы, `on_success` (`fact`, `move` по видимому выходу, `reveal` существующего скрытого объекта; обязателен, кроме `move`), `on_fail` (`condition` из списка, `damage` 1–2, `fact`). `interact` без подхода и без испытания допустим, только если у объекта есть подход `interact`. Невалидные заявки → один повтор с перечнем ошибок → безопасное толкование: `fallback` модели (если проходит проверку и это `explore`/`wait`/`move`), иначе `wait`; пропущенная заявка → `wait`. Намерение с типом и непустыми `ambiguities` движок разрешает как обычное действие и дописывает «безопасное толкование: …» в итог; статус `ambiguous` получает только намерение без типа. Сбой модели, таймаут, ответ не по схеме, отсутствие профиля → `interpreter.Fallback` (типовые команды кодом, остальное `wait`), раунд публикуется ([ADR-0010](../decisions/0010-interpreter-call.md)). Один вызов на все заявки раунда после дедлайна; уточняющих вопросов игроку нет.

## Оценочный набор
`assets/prompts/interpreter/eval/cases.json`: общий снимок (зал и подвал башни, четыре персонажа), 17 случаев — подходы по названию и по смыслу, свободные испытания (S12, S13), переходы, осмотр, помощь, ожидание, попытка инструкций, цепочка действий, несуществующая цель, неподдержанное действие, форсирование, пакет из четырёх заявок. Прогон на живом `claude-cli`: `make eval-interpreter` (`EVAL_ARGS="-v -case имя -model haiku -effort low"`; модель по умолчанию `sonnet`, как в профиле `local-claude`), порог 90 %; результаты в [README](README.md).
