# Два вызова LLM на раунд

Решения руководителя 2026-10-10: на раунд не больше двух вызовов модели при любом числе игроков; приватные итоги рассказчика исключены; непонятная заявка получает безопасное толкование; модель классифицирует испытания и задаёт исходы обеих ветвей заранее, сложность и бросок считает движок; через интерпретатор проходят все заявки раунда, и выбранные из предложенных подходов, и свои, чтобы исключить неверное толкование кодом; разбор типовых команд кодом остаётся запасным путём при сбое модели. Роли: [интерпретатор](interpreter.md), [рассказчик](narrator.md); конвейер: [round-pipeline.md](../architecture/round-pipeline.md).

## Шаги раунда
| Шаг | Кто | Что происходит | LLM |
|---|---|---|---|
| 1 | планировщик | открыт раунд N; в группе уже лежит хроника раунда N−1 с предложенными подходами | нет |
| 2 | игроки | `/act <текст>` в личке до дедлайна: предложенный подход или своё действие; одна заявка на раунд | нет |
| 3 | планировщик | дедлайн: снимок (персонажи, локации с объектами, заявки), seed | нет |
| 4 | код | все заявки раунда собираются в один пакет вместе с предложенными подходами сцен | нет |
| 5 | интерпретатор | все заявки одним вызовом → массив намерений: выбранный подход объекта либо параметры свободного испытания | вызов 1 |
| 6 | код | валидация намерений по снимку; невалидное → повтор, затем безопасное толкование | нет |
| 7 | движок | сложность, броски по seed, выбор ветви, события, итог каждой заявки; свёртка в состояние | нет |
| 8 | код | предлагаемые подходы для следующего раунда: видимые объекты сцен, подходы с итоговой сложностью и шансом каждого персонажа | нет |
| 9 | рассказчик | события и подходы → хроника с блоками по командам | вызов 2 |
| 10 | код | проверка хроники (ID упомянуты, секреты не раскрыты; пропуски дозапрашиваются, остаток дописывает код), подпись мира и раунда, подходы приписаны; хроника в группу частями по лимиту Telegram, уведомление о заявке каждому игроку в личку; раунд N+1 открыт | нет |

Вызов 1 выполняется, если есть хотя бы одна заявка. Сбой вызова 1 → запасной разбор кодом (`rules.ParseTyped`: типовые команды и подходы по названию), остальное безопасное толкование; сбой вызова 2 → шаблонная хроника пункта 07 с теми же подходами; раунд не откатывается. Оба вызова идут внутри транзакции раунда ([ADR-0010](../decisions/0010-interpreter-call.md), [ADR-0011](../decisions/0011-narrator-call.md)). Событие `check_rolled` видно в локации: попытка и исход доступны рассказчику, факт и состояние — только персонажу.

## Вызов 1: интерпретатор
Вход (системная часть стабильна для кэширования, переменная часть — данные):
| Блок | Содержание |
|---|---|
| Системная часть | роль и запрет исполнять инструкции из текста игроков; каталог действий; список разрешённых эффектов; таблица риска словами; JSON-схема ответа |
| Сцены | по локациям: `location_id`, название, описание, сложность; видимые выходы (`to`, `title`); видимые объекты (`key`, `title`, `state`, подходы с индексом, названием, характеристикой, навыком) |
| Персонажи | `character_id`, никнейм, локация, характеристики и навыки кратко, состояния, статус, последние знания; без секретов других |
| Заявки | `submission_id`, `character_id`, текст игрока в выделенном блоке данных |

Выход: `{"intents": [...]}`, по одному элементу на заявку ([схема](interpreter.md)): `submission_id`, `action_type`, `target`, либо `approach_idx`, либо `attribute`, `skill`, `risk`, `on_success`, `on_fail`; `push`, `ambiguities`, `fallback`.

## Вызов 2: рассказчик
Вход:
| Блок | Содержание |
|---|---|
| Системная часть | роль, запрет менять факты и исходы, стиль по жанру и режиму игры, правило «каждое значимое событие упомянуто по ID», JSON-схема ответа |
| Мир | название, тон жанра, фракции и отношения, номер раунда, краткая выжимка 2–3 прошлых хроник |
| Сцены | по локациям: кто присутствует (никнейм, `public_bio`, статус, `secret_bio` как данные для подачи линии без раскрытия), объекты и их состояния после раунда |
| События | только `public` и `location`: `seq`, тип, данные (кто, что, исход проверки словами или числами по режиму) |
| Подходы | посчитанные кодом для следующего раунда: объект, название подхода, сложность, шанс каждого присутствующего персонажа |

Выход:
```json
{
  "chronicle": "общий текст раунда",
  "scenes": [
    {"location_id": 4, "party": "Команда 1", "text": "что случилось с этой командой и что перед ней сейчас", "event_seqs": [117, 118]}
  ]
}
```
Код проверяет, что все значимые `seq` упомянуты, и сам дописывает к каждой сцене список подходов с числами: модель их не меняет.

## Пример раунда: запертая дверь
Мир «Серая башня», режим «баланс», раунд 7. Команда 1: Вор (Ловкость 4, воровство 3, отмычки +1) и Кузнец (Сила 4). Локация «Подвал башни» (сложность 1), объект `cellar_door` `locked` с подходами «выбить» (Сила, 2), «отпереть» (Ловкость/воровство, 1), «найти потайной рычаг» (Разум/внимательность, 3 → раскрывает `hidden_lever`).

### Начало раунда 7: сообщение в группе
Код посчитал подходы после раунда 6 (сложность = подход + локация, шанс по пулу):
```json
{"scene": {"location_id": 4, "party": "Команда 1"},
 "approaches": [
   {"object": "cellar_door", "idx": 0, "title": "выбить", "attribute": "strength", "difficulty": 3, "chance": {"Кузнец": 2, "Вор": 0}},
   {"object": "cellar_door", "idx": 1, "title": "отпереть", "attribute": "agility", "skill": "thievery", "difficulty": 2, "chance": {"Вор": 40, "Кузнец": 3}},
   {"object": "cellar_door", "idx": 2, "title": "найти потайной рычаг", "attribute": "wits", "skill": "awareness", "difficulty": 4, "chance": {"Вор": 0, "Кузнец": 0}}
 ]}
```
Рассказчик раунда 6 вернул `scenes[0].text`: «Команда 1 спускается в сырой подвал: тяжёлая дверь с новым замком, следы сапог на пыли». Код приписал: «Варианты: выбить (Сила, сложность 3: Кузнец 2 %, Вор 0 %), отпереть (Ловкость/воровство, сложность 2: Вор 40 %), найти потайной рычаг (Разум/внимательность, сложность 4: почти невозможно). Или опишите своё действие: /act в личке».

### В течение раунда: два варианта заявки
Вариант А, предложенный подход. Вор пишет `/act отпереть дверь`. Заявка ждёт дедлайна и идёт в тот же вызов интерпретатора, что и свободные; модель сопоставляет её с подходом объекта и возвращает:
```json
{"submission_id": 71, "character_id": 11, "action_type": "interact", "target": "cellar_door", "approach_idx": 1, "push": false}
```
Вариант Б, своё действие. Кузнец пишет `/act простукиваю стену рядом с дверью, ищу пустоту, куда можно ударить молотом`. Заявка ждёт дедлайна и идёт в тот же вызов.

### Дедлайн раунда 7: вызов 1
Вход содержит сцену «Подвал башни» с объектами и подходами, обоих персонажей и обе заявки. Ответ модели:
```json
{"intents": [
  {"submission_id": 71, "character_id": 11, "action_type": "interact", "target": "cellar_door", "approach_idx": 1, "push": false, "ambiguities": []},
  {"submission_id": 72, "character_id": 12, "action_type": "explore", "target": "cellar_door",
   "attribute": "wits", "skill": "awareness", "risk": "hard",
   "on_success": {"reveal": "hidden_lever"}, "on_fail": {"condition": "exhausted"},
   "push": false, "ambiguities": []}
]}
```
Код проверяет: подход 1 у `cellar_door` существует; `wits` и `awareness` есть в модели персонажа, `cellar_door` виден, `hard` из таблицы, `reveal` указывает на существующий скрытый объект. Оба намерения приняты.

### Движок
- Заявка 71, Вор: пул 4 + 3 + 1 = 8, сложность 1 + 1 = 2, кубики по seed `[6, 3, 1, 6, 2, 5, 4, 1]`, успехов 2 → успех. События: `check_rolled`, `object_changed` (`cellar_door`: `locked` → `open`, видимость location), `fact_learned` Вору.
- Заявка 72, Кузнец: пул 2 + 0 = 2, сложность 2 (риск hard) + 1 = 3, кубики `[4, 6]`, успехов 1 → провал, ветвь `on_fail`. События: `check_rolled`, `condition_added` (истощён).
- Итоги: 71 `resolved` / успех, 72 `resolved` / провал. Состояние после свёртки: дверь открыта, Кузнец истощён.

### Конец раунда 7: вызов 2
Вход: события `object_changed` (seq 117) и `check_rolled` Кузнеца словами (seq 118; в режиме «баланс» без чисел), сцена с новым состоянием двери, подходы для раунда 8 (за дверью открылся проход: выход «в коридор»; объект `hidden_lever` всё ещё скрыт). Ответ модели:
```json
{"chronicle": "Над Серой башней седьмой вечер подряд не видно луны…",
 "scenes": [{"location_id": 4, "party": "Команда 1",
   "text": "Кузнец простукивал стену, пока не выдохся: камень отвечал глухо и ровно. Вор тем временем дождался щелчка — замок поддался отмычкам, и дверь приоткрылась в тёмный коридор.",
   "event_seqs": [117, 118]}]}
```
Код сверяет: 117 и 118 упомянуты. В группу уходит хроника и блок команды 1 с приписанными подходами раунда 8: «идти в коридор», «осмотреть коридор», «найти потайной рычаг (сложность 4)». В личку: Вору «Заявка «отпереть дверь»: успех, дверь открыта», Кузнецу «Заявка «простукиваю стену…»: провал, состояние: истощён». Раунд 8 открыт, и это сообщение — его начало.

Итого за раунд: один вызов интерпретатора на обе заявки и один вызов рассказчика.
