# Два вызова LLM на раунд

Решения руководителя 2026-10-10: на раунд не больше двух вызовов модели при любом числе игроков; приватные итоги рассказчика исключены; непонятная заявка получает безопасное толкование; модель классифицирует испытания и задаёт исходы обеих ветвей заранее, сложность и бросок считает движок; через интерпретатор проходят все заявки раунда, и выбранные из предложенных подходов, и свои, чтобы исключить неверное толкование кодом; разбор типовых команд кодом остаётся запасным путём при сбое модели. Роли: [интерпретатор](interpreter.md), [рассказчик](narrator.md); конвейер: [round-pipeline.md](../architecture/round-pipeline.md).

Вне раунда один вызов на игру: завязка истории и стартовый пакет мира при `/begin` (роль `opening`, [narrator.md](narrator.md), [ADR-0018](../decisions/0018-opening-scene.md), [ADR-0019](../decisions/0019-world-generation.md)); лимит «два вызова на раунд» она не меняет. Достройка мира (пункт 27, [динамический мир](../game/world.md)) идёт в вызове рассказчика: код планирует задания, модель возвращает пакет `world` рядом с хроникой, отдельного вызова «картограф» нет. Ответ каждого вызова сохраняется по ключу задания (`generation_jobs`): повтор раунда после отката берёт готовый ответ без второго вызова.

## Шаги раунда
| Шаг | Кто | Что происходит | LLM |
|---|---|---|---|
| 1 | планировщик | открыт раунд N; в группе уже лежит хроника раунда N−1 с предложенными подходами | нет |
| 2 | игроки | `/act <текст>` в личке до дедлайна: предложенный подход или своё действие; одна заявка на раунд | нет |
| 3 | планировщик | дедлайн: снимок (персонажи, занятые клетки и их соседи с объектами, заявки), seed | нет |
| 4 | код | все заявки раунда собираются в один пакет вместе с предложенными подходами сцен | нет |
| 5 | интерпретатор | все заявки одним вызовом → массив намерений: выбранный подход объекта либо параметры свободного испытания | вызов 1 |
| 6 | код | валидация намерений по снимку; невалидное → повтор, затем безопасное толкование | нет |
| 7 | движок | сложность, броски по seed, выбор ветви, события (переход в клетку — `character_moved` с координатами, первый вход фракции — `cell_discovered`), итог каждой заявки; свёртка в состояние | нет |
| 8 | код | предлагаемые подходы для следующего раунда: видимые объекты сцен, подходы с итоговой сложностью (шанс персонажей считается, но в группу не выводится, B6); исчерпанные подходы — объект уже в целевом состоянии, факт известен всем присутствующим — не предлагаются (B8, `docs/game/checks.md`); переходы по направлениям к соседям; задания на достройку мира: занятые карточки → детализация (до 4), недостающие соседи занятых клеток → карточки (`narrator.PlanTasks`) | нет |
| 9 | рассказчик | события, подходы и задания → хроника с блоками по группам (сцена — группа в локации, одиночки локации отдельно) и пакет мира `world` | вызов 2 |
| 10 | код | проверка хроники (ID упомянуты, секреты не раскрыты; пропуски дозапрашиваются, остаток дописывает код) и пакета мира (клетки и соседи только из заданий, лимиты, подходы по модели персонажа; невалидное отброшено, пропущенное — шаблон); клетки и объекты записаны событиями `cell_generated`, `object_created` и свёрнуты в состояние; подпись мира и раунда, подходы и переходы приписаны; хроника в группу частями по лимиту Telegram, уведомление о заявке каждому игроку в личку; раунд N+1 открыт | нет |

Вызов 1 выполняется, если есть хотя бы одна заявка. Сбой вызова 1 → запасной разбор кодом (`interpreter.Fallback`: типовые команды `rules.ParseTyped` и подходы по названию в локации персонажа), остальное безопасное толкование; сбой вызова 2 → шаблонная хроника пункта 07 с теми же подходами и шаблонные клетки («Дорога», соседи «Неизведанные земли»); раунд не откатывается. Оба вызова идут внутри транзакции раунда ([ADR-0010](../decisions/0010-interpreter-call.md), [ADR-0011](../decisions/0011-narrator-call.md)). Событие `check_rolled` видно в локации: попытка и исход доступны рассказчику, факт и состояние — только персонажу.

## Вызов 1: интерпретатор
Вход (системная часть стабильна для кэширования, переменная часть — данные):
| Блок | Содержание |
|---|---|
| Системная часть | роль и запрет исполнять инструкции из текста игроков; каталог действий; список разрешённых эффектов; таблица риска словами; JSON-схема ответа |
| Сцены | по локациям: `location_id`, название, описание, сложность; выходы по направлениям к существующим соседям (`to` — ключ направления `north`/`south`/`west`/`east`, `title` — «на север: Лес»); видимые объекты (`key`, `title`, `state`, подходы с индексом, названием, характеристикой, навыком); у персонажа отметка входа `entry` (`new`/`returned`, B1) |
| Персонажи | `character_id`, никнейм, пол (если указан), локация, характеристики и навыки кратко, состояния, статус, последние знания; без секретов других |
| Заявки | `submission_id`, `character_id`, текст игрока в выделенном блоке данных |

Выход: `{"intents": [...]}`, по одному элементу на заявку ([схема](interpreter.md)): `submission_id`, `action_type`, `target`, либо `approach_idx`, либо `attribute`, `skill`, `risk`, `on_success`, `on_fail`; `push`, `ambiguities`, `fallback`.

## Вызов 2: рассказчик
Вход:
| Блок | Содержание |
|---|---|
| Системная часть | роль, запрет менять факты и исходы, стиль по жанру и режиму игры, правило «каждое значимое событие упомянуто по ID», JSON-схема ответа |
| Мир | название, тон жанра, фракции и отношения, номер раунда, краткая выжимка 2–3 прошлых хроник |
| Сцены | по группам внутри локаций (пункт 19): `scene_id`, `location_id`, `party` (имя группы; пусто — персонажи без группы этой локации), координаты, стадия (`card` — группа только что вошла в неописанную клетку) и тип местности, выходы по направлениям с именем соседа и его карточкой, кто присутствует (никнейм, `gender` если указан, `public_bio`, статус, `secret_bio` как данные для подачи линии без раскрытия), объекты и их состояния после раунда; лидер группы не передаётся |
| Задания (`generate`) | только при наличии: клетки для детализации (`location_id`, координаты, имя, местность, карточка, кто вошёл), недостающие соседи (координаты, направление, от какой клетки), лимиты (объектов на клетку, подходов на объект, длины, ориентиры сложности), ключи характеристик и навыков модели персонажа для подходов |
| События | только `public` и `location`: `seq`, тип, данные (кто, что, исход проверки словами или числами по режиму) |
| Подходы | посчитанные кодом для следующего раунда: объект, название подхода, характеристика, навык, сложность (в «повествовании» без числа) |

Выход:
```json
{
  "chronicle": "общий текст раунда",
  "scenes": [
    {"scene_id": 1, "text": "что случилось с этой группой и что перед ней сейчас", "event_seqs": [117, 118]}
  ]
}
```
Код проверяет, что все значимые `seq` упомянуты, подставляет локацию и подпись сцены («Группа (Локация)» или название локации) и сам дописывает к каждой сцене список подходов с числами и переходов: модель их не меняет. События групп `party_split` и `party_held` приходят словами (`narrator.Describe`), промпт требует объяснить их сюжетом и не называть лидера.

Пакет мира в том же ответе (пункт 27, [world.md](../game/world.md)):
```json
{"world": {
  "cells": [{"location_id": 15, "name": "Еловый бор", "description": "Густой ельник, тропа теряется в хвое.", "difficulty": 1,
    "objects": [{"key": "old_hut", "title": "заброшенная хижина", "description": "Дверь перекошена.", "state": "closed", "hidden": false,
      "approaches": [{"action": "interact", "title": "открыть дверь", "attribute": "strength", "skill": "athletics", "difficulty": 5, "on_success": {"state": "open", "reveal": null, "fact": null}, "on_fail": {"condition": "exhausted", "damage": null, "fact": null}}]}]}],
  "neighbors": [{"x": 0, "y": 2, "name": "Болото", "terrain": "swamp", "card": "Туман над осокой."}]}}
```
Код принимает только клетки с `location_id` из заданий и соседей с координатами из заданий; ключи объектов нормализует в snake_case, объекты сверх лимита и подходы с характеристикой или навыком не из модели отбрасывает, `reveal` допускает только на скрытый объект той же клетки; пропущенное задание закрывает шаблоном. Замечания к пакету дозапроса не вызывают (приоритет генерации над точностью).

## Пример раунда: запертая дверь
Мир «Серая башня», режим «баланс», раунд 7. Команда 1: Вор (Ловкость 5, воровство 3) и Кузнец (Сила 5, атлетика 3, Разум 2). Локация «Подвал башни» (сложность 1), объект `cellar_door` `locked` с подходами «выбить» (Сила/атлетика, 4), «отпереть» (Ловкость/воровство, 4), «найти потайной рычаг» (Разум/внимательность, 4 → раскрывает `hidden_lever`).

### Начало раунда 7: сообщение в группе
Код посчитал подходы после раунда 6 (сложность = подход + локация, шанс каждого по параметру):
```json
{"scene": {"location_id": 4, "party": "Команда 1"},
 "approaches": [
   {"object": "cellar_door", "idx": 0, "title": "выбить", "attribute": "strength", "skill": "athletics", "difficulty": 5},
   {"object": "cellar_door", "idx": 1, "title": "отпереть", "attribute": "agility", "skill": "thievery", "difficulty": 5},
   {"object": "cellar_door", "idx": 2, "title": "найти потайной рычаг", "attribute": "wits", "skill": "awareness", "difficulty": 5}
 ]}
```
Рассказчик раунда 6 вернул `scenes[0].text`: «Команда 1 спускается в сырой подвал: тяжёлая дверь с новым замком, следы сапог на пыли». Код приписал: «Варианты: выбить (Сила/атлетика, сложность 5), отпереть (Ловкость/воровство, сложность 5), найти потайной рычаг (Разум/внимательность, сложность 5). Или опишите своё действие: /act в личке».

### В течение раунда: два варианта заявки
Вариант А, предложенный подход. Вор пишет `/act отпереть дверь`. Заявка ждёт дедлайна и идёт в тот же вызов интерпретатора, что и свободные; модель сопоставляет её с подходом объекта и возвращает:
```json
{"submission_id": 71, "character_id": 11, "action_type": "interact", "target": "cellar_door", "approach_idx": 1, "push": false}
```
Вариант Б, своё действие. Кузнец пишет `/act простукиваю стену рядом с дверью, ищу пустоту, куда можно ударить молотом`. Заявка ждёт дедлайна и идёт в тот же вызов.

### Дедлайн раунда 7: вызов 1
Вход содержит сцену «Подвал башни» с объектами и подходами, обоих персонажей и обе заявки. Ответ модели:
```json
{"intents": [
  {"submission_id": 71, "character_id": 11, "action_type": "interact", "target": "cellar_door", "approach_idx": 1, "push": false, "ambiguities": []},
  {"submission_id": 72, "character_id": 12, "action_type": "explore", "target": "cellar_door",
   "attribute": "wits", "skill": "awareness", "risk": "hard",
   "on_success": {"reveal": "hidden_lever"}, "on_fail": {"condition": "exhausted"},
   "push": false, "ambiguities": []}
]}
```
Код проверяет: подход 1 у `cellar_door` существует; `wits` и `awareness` есть в модели персонажа, `cellar_door` виден, `hard` из таблицы, `reveal` указывает на существующий скрытый объект. Оба намерения приняты.

### Движок
- Заявка 71, Вор: параметр 5 + 3 = 8, сложность 4 + 1 = 5, шанс 80 %, бросок по seed 37 → успех. События: `check_rolled`, `object_changed` (`cellar_door`: `locked` → `open`, видимость location), `fact_learned` Вору.
- Заявка 72, Кузнец: параметр 2 + 0 = 2, сложность 7 (риск hard) + 1 = 8, шанс 5 %, бросок 62 → провал, ветвь `on_fail`. События: `check_rolled`, `condition_added` (истощён).
- Итоги: 71 `resolved` / успех, 72 `resolved` / провал. Состояние после свёртки: дверь открыта, Кузнец истощён.

### Конец раунда 7: вызов 2
Вход: события `object_changed` (seq 117) и `check_rolled` Кузнеца словами (seq 118; в режиме «баланс» без чисел), сцена с новым состоянием двери, подходы для раунда 8 (за дверью открылся проход: выход «в коридор»; объект `hidden_lever` всё ещё скрыт). Ответ модели:
```json
{"chronicle": "Над Серой башней седьмой вечер подряд не видно луны…",
 "scenes": [{"location_id": 4, "party": "Команда 1",
   "text": "Кузнец простукивал стену, пока не выдохся: камень отвечал глухо и ровно. Вор тем временем дождался щелчка — замок поддался отмычкам, и дверь приоткрылась в тёмный коридор.",
   "event_seqs": [117, 118]}]}
```
Код сверяет: 117 и 118 упомянуты. В группу уходит хроника и блок команды 1 с приписанными подходами раунда 8: «идти в коридор», «осмотреть коридор», «найти потайной рычаг (сложность 5)». В личку: Вору «Заявка «отпереть дверь»: успех, дверь открыта», Кузнецу «Заявка «простукиваю стену…»: провал, состояние: истощён». Раунд 8 открыт, и это сообщение — его начало.

Итого за раунд: один вызов интерпретатора на обе заявки и один вызов рассказчика.
