# LLM: конвейер и бюджет

Две роли, два промпта, две схемы. Код: `internal/service/{interpreter,narrator}`, `internal/adapter/llm`; промпты `assets/prompts/<роль>/vN.md`. Провайдеры и профили: [providers.md](providers.md), [ADR-0003](../decisions/0003-llm-provider.md).

| Роль | Вход | Выход | Схема вызовов MVP |
|---|---|---|---|
| [Интерпретатор](interpreter.md) | заявка игрока + допустимый контекст (локация, цели, каталог) | намерение JSON | небольшие пакеты заявок одной локации; типовые команды без LLM |
| [Рассказчик](narrator.md) | разрешённые события по видимости адресата | текст | один вызов на хронику + по вызову на приватные итоги с шаблоном для стандартных исходов |

## Бюджет
- Лимиты: токены на вызов, раунд, игру; значения в конфиге, превышение → режим деградации (шаблоны).
- Учёт: `llm_runs` (модель, версия промпта, токены, стоимость, длительность, ошибка).
- Контекст: состояние + релевантные факты + последние события адресата; без полной истории чата.
- Стабильный префикс (правила, схема, каталог) отделён для кэширования.
