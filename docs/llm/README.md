# LLM: конвейер и бюджет

Две роли, два промпта, две схемы, не больше двух вызовов на раунд при любом числе игроков: интерпретатор после дедлайна и рассказчик после движка; пошаговая схема с входами и выходами — [round-calls.md](round-calls.md), при расхождениях с другими документами он приоритетен (решение руководителя 2026-10-10). Код: `internal/service/{interpreter,narrator}`, `internal/adapter/llm`; промпты `assets/prompts/<роль>/vN.md`. Провайдеры и профили: [providers.md](providers.md), [ADR-0003](../decisions/0003-llm-provider.md).

| Роль | Вход | Выход | Схема вызовов MVP |
|---|---|---|---|
| [Интерпретатор](interpreter.md) | все заявки раунда + контекст сцен (локации, объекты с подходами, выходы, каталог) | массив намерений JSON | один вызов на раунд после дедлайна на все заявки, включая выбранные из предложенных подходов (решение руководителя 2026-10-10); разбор типовых команд кодом — запасной путь при сбое модели |
| [Рассказчик](narrator.md) | публичные и локационные события раунда | хроника в группу | один вызов на раунд; приватные итоги рассказчика исключены из плана (решение руководителя 2026-10-10), игроку уходит шаблонное уведомление о статусе заявки |

## Бюджет
- Лимиты: токены на вызов, раунд, игру; значения в конфиге, превышение → режим деградации (шаблоны).
- Учёт: `llm_runs` (модель, версия промпта, токены, стоимость, длительность, ошибка).
- Контекст: состояние + релевантные факты + последние события адресата; без полной истории чата.
- Стабильный префикс (правила, схема, каталог) отделён для кэширования.
