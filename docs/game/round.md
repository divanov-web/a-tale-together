# Раунд

## Настройки мира
Колонки `games`: `round_minutes` (10–60, по умолчанию 15), `timezone`, `play_from` / `play_to` (игровое окно в сутках, необязательно: раунды открываются только внутри окна, чтобы все играли в одно время); `settings`: `max_players`, `max_active_locations`, `inactive_after_rounds` (3). Ручная пауза — статус `paused`. MVP: окно + ручная пауза.

## Цикл
1. Открытие: планировщик создаёт раунд `open`, публикует анонс с дедлайном.
2. Приём: `/act` создаёт или заменяет заявку персонажа; последняя до дедлайна действует.
3. Заморозка: по дедлайну проверка кворума; при кворуме `frozen`, снимок состояния и заявок, `seed`; поздние заявки → следующий раунд.
4. Разрешение и публикация: [конвейер раунда](../architecture/round-pipeline.md).
5. Следующий раунд по расписанию; в паузе не создаётся.

## Кворум раунда
| Правило | Значение |
|---|---|
| Минимум заявок | `settings.min_round_answers`; по умолчанию 2, параметр `min_answers` в `/game_set` и диалоге настройки; на время разработки 1 (`APP_ENV=dev`) |
| Заявок меньше кворума | раунд `skipped`: без разрешения, без сообщений в группу и в личку; заявки переносятся в следующий раунд; пропуск персонажам не засчитывается |
| Простой | `/status` показывает причину: «раунд N пропущен: заявок M из K», пауза, игра не запущена, вне игрового окна |
| Следующий раунд | открывается по расписанию как обычно |

## Фазы разрешения (черновик)
| Фаза | Действия | Правило порядка |
|---|---|---|
| 1. Подготовка | `help`, `wait`, `sneak` | без конфликтов, применяются первыми |
| 2. Перемещение | `move` | одновременно; конфликт за вход — встречная Ловкость |
| 3. Взаимодействие | `explore`, `interact`, `persuade`, `trade` | конфликт за объект: встречная проверка, предмет один |
| 4. Столкновение | `attack` | инициатива по Ловкости, равенство — одновременно |
| 5. Итоги | состояния, HP, знания | события фиксируются |

## Лимит локаций
`max_active_locations` (по умолчанию 4): рассказчик ведёт зацепки в существующие локации и объединяет действия внутри них. Лимит не телепортирует и не запрещает логичный уход: переход по правилам либо механическое и нарративное объяснение ограничения. MVP без дальних путешествий и больших карт.

## Бездействие и отсутствие
Персонаж без заявки: продолжает долгое занятие (позже) или `wait` с защитным положением. Раунд не ждёт никого. Пропуски копятся в `missed_rounds`: 1–2 → статус `waiting`, 3 → `inactive`, рассказчик выводит персонажа из сюжета; возврат заявкой ([персонаж](character.md), «Статус»).

## Неоднозначность
Интерпретатор вернул `ambiguities` → до дедлайна игроку уточняющий вопрос; после дедлайна безопасное толкование из каталога либо `wait`.

## Лимиты
Одна основная заявка; длина текста до 500 символов; замена не чаще раза в минуту; цепочка действий → берётся первое, остальное отклоняется с пояснением.
