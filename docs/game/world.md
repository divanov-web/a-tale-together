# Динамический мир

Мир генерируется по ходу игры, игроки своими действиями задают направление генерации (решение руководителя 2026-10-12). План: пункты [27](../plan/telegram/27-world-grid.md) (готово: сетка, стартовый пакет, достройка, [ADR-0019](../decisions/0019-world-generation.md)), [28](../plan/telegram/28-quests.md) (готово: цели и квесты фракций, [ADR-0020](../decisions/0020-quests.md))–[31](../plan/telegram/31-local-context-budgets.md). Оценка подхода: [concept](../concept/dynamic_world_review_by_chatGPT.md) (не источник правды; принятые правки — здесь). Форма данных: [модель клетки](models/location.md), [модель квеста](models/quest.md); эталоны: сценарии S16, S17.

## Принцип точности

| Строго (движок, события, БД) | Свободно (проза рассказчика) |
|---|---|
| координаты и стадия клетки, кто где находится | атмосфера, детали пейзажа, реплики |
| существование и состояние объектов, владелец предмета, состояние NPC | второстепенные описания, не привязанные к ключам |
| исходы испытаний, награды, этапы квестов, счётчики выдачи | декоративные неувязки между раундами допустимы |

Приоритет генерации над точностью: модель выдумывает много, код фиксирует только то, что влияет на механику. Принцип 2 (LLM не создаёт факты текстом) сохраняется: новые сущности приходят структурой в ответе рассказчика, код принимает их до публикации; текст, обещающий непринятую сущность, не правится.

## Карта

| Правило | Значение |
|---|---|
| Геометрия | сетка квадратов; старт `(0,0)`; четыре направления: север `(x, y+1)`, юг, запад, восток; геометрию, направления и достижимость считает код, отдельного запроса «картограф» нет |
| Идентичность клетки | `(game_id, x, y)` уникальны; имя — подпись, не ключ (одноимённые леса допустимы) |
| Стадии клетки | `none` (строки нет, только координаты) → `card` (карточка соседа: тип местности, имя, одно предложение) → `detailed` (описание, объекты, подходы; NPC и предметы — пункт 30) |
| Открытие | клетка открыта при первом входе персонажа (`visited_at`); карточка соседа открытием не считается; стартовая клетка не считается; две группы в одной клетке — одно открытие |
| Выбор стартового мира | после `/create` нулевой вызов «генерация мира» ([ADR-0028](../decisions/0028-worldgen.md), пункт [37](../plan/telegram/37-worldgen.md)): модель по описанию жанра предлагает четыре разных варианта (заголовок, название мира, описание для администратора, тон, крючок завязки, фракции с целями, стартовая клетка); администратор обязан выбрать один первым шагом настройки или `/set scenario <номер>` (кнопки «оставить как есть» нет, решение руководителя 2026-10-14), выбор переписывает название, фракции и стартовую клетку `(0,0)`; сбой модели (три попытки) или её отсутствие — шаблон жанра, шаг отпадает |
| Старт мира | при `/begin` стартовый пакет (тон и крючок `premise` — из выбранного варианта мира, промпт `opening-v5`): центр `detailed` (модель переписывает описание и объекты клетки шаблона), четыре соседа `card`, текст завязки (роль `opening`, промпт `opening-v2`, ADR-0019 заменяет [ADR-0018](../decisions/0018-opening-scene.md) в части мира); в том же вызове цель и сюжетный квест каждой фракции (`factions[]`, пункт 28, промпт `opening-v3`); сбой модели — клетка шаблона, соседи «Неизведанные земли», цель и квест из шаблона жанра |
| Достройка | при входе в клетку `card` рассказчик в вызове того же раунда (`narrator/v7`, блок `generate` → `world`) поднимает её до `detailed` и создаёт недостающих соседей `card` с видимостью; при прямом движении обычно три новых соседа; невалидное отбрасывается, пропущенное задание дозапрашивается один раз ([ADR-0035](../decisions/0035-story-momentum.md)), затем шаблон «Дорога» и «Неизведанные земли» |
| Видимость | у карточки соседа `hidden` и `distant_view` решает рассказчик (B36, [ADR-0025](../decisions/0025-cell-visibility-scout.md)): скрытый сосед известен игрокам, интерпретатору и движку только как «неизведанная территория (вид издалека)», имя не сопоставляется; переход туда — по направлению или примете; клетка становится видимой при первом входе; шаблонный сосед «Неизведанные земли» виден; открытие издалека иным способом — вопрос геймдизайну |
| Логово сил зла | у фракции `evil` опорная клетка — одна из `(3,3)`, `(3,-3)`, `(-3,3)`, `(-3,-3)`, выбирается кодом случайно при `/create` (решение руководителя 2026-10-14, B42, [ADR-0031](../decisions/0031-evil-lair.md)); при `/begin` завязка по заданию `generate.lair` даёт имя, местность, карточку и вид издалека под сеттинг (сбой — шаблон «Логово»), клетка создаётся `card` и всегда скрытой; дальше обычная клетка: `/scout` из соседней показывает вид издалека, вход открывает, рассказчик детализирует. Для рассказчика — фон (`world.lair`, у сцены направление и дальность словами): слухи, следы, тревога с той стороны; целью походов и этапом квеста не бывает (`quest.Plan` там этап не размещает); сброс мира удаляет клетку, повторный `/begin` создаёт её заново |
| Переход | только текстом заявки: направление словом или название видимого соседа; кнопок и строк «идти на север» в «Вариантах» нет; соседей показывает `/scout` (личка и группа, кнопка «Разведка») |
| Возврат | известная клетка читается из БД, повторно не генерируется; новые детали только явным событием |
| Границы | все четыре перехода доступны; непроходимые границы, реки и мосты — пункт [36](../plan/telegram/36-passability.md) (вид преграды покажет `/scout`) |
| Лимит сцен | `max_parties` ограничивает число занятых клеток, не размер карты |

## Сущности

Три таблицы объект / предмет / NPC закладываются сразу (решение руководителя 2026-10-12).

| Сущность | Таблица | Минимум | Пункт |
|---|---|---|---|
| Клетка | `locations` + `x`, `y`, `stage`, `visited_at`, `terrain` | описание, сложность, выходы по направлениям считает код ([модель](models/location.md)) | 27 (готово) |
| Объект | `world_objects` | `key`, `title`, `state`, `revealed`, `searched`, подходы в JSONB ([модель](models/location.md)) | 27 (готово) |
| Переносимый предмет | `items` | `key`, `title`, `kind`, свойства, владелец: клетка, контейнер-объект или персонаж | таблица 27, поведение 30 |
| NPC | `npcs` | `key`, `title`, клетка, фракция, состояние, отношение, знания ([модель](models/npc.md)) | таблица 27, поведение 30 |
| Цель фракции | `faction_goals` | формулировка, версия (строка на версию), стадия; без конечной точки и без срока (B43, [фракции](factions.md)); пересмотр по закрытию сюжетного квеста ([модель](models/quest.md)) | 28 (готово) |
| Квест | `quests` | тип (`story` / `side`), статус, фракция, название и смысл | 28 (готово) |
| Этап квеста | `quest_stages` | ключ, вид и конкретное условие, расстояние от предыдущего, клетка (после привязки), статус, награда | 28 (готово) |

«Ничего полезного» — флаг `searched` у объекта или клетки, не предмет: повторный осмотр без изменения состояния не генерирует находку.

## Квесты

| Правило | Значение |
|---|---|
| Типы | сюжетный: связан с целью фракции, 3–6 этапов; побочный: 2–4 этапа |
| Лимит | на фракцию: 2 сюжетных + 1 побочный (`settings.max_story_quests` = 2, `max_side_quests` = 1; решение руководителя 2026-10-12); считается по активным квестам фракции, включая ещё не раскрытые игрокам; при двух фракциях в мире до 6 квестов |
| Состав | цепочка этапов до финального; у этапа условие-результат, не способ: «печать у участника», а не «сундук открыт» |
| Условия этапа (код) | `object_state` — объект клетки этапа в состоянии, `fact` — факт у персонажа фракции, `visited` — клетка посещена (закрывается в раунде входа); предмет у персонажа и состояние NPC — пункт 30; выражений от модели нет; при размещении условие принимается, только если его даёт подход клетки, иначе первое достижимое, иначе `visited` |
| Ленивая привязка | заранее известны только смысл, вид условия и расстояние этапа; первый незакрытый этап без клетки материализуется там, где стоит персонаж фракции на расстоянии ≥ заданного от клетки предыдущего этапа (первый — от стартовой): рассказчик получает задание «разместить этап», возвращает до 2 объектов с подходами и условие; маршрут не планируется и не проверяется; пропущенное размещение дозапрашивается, затем шаблон: этап `visited` — без объекта, иначе объект «след» с подходом без броска (B45) |
| Выдача | кнопки «взять квест» нет: квест существует в мире, рассказчик намекает (блок `quests` в его контексте: ближайший этап и подсказка); просмотр — `/quests` в личке (цель, квесты, этапы со статусами) |
| Отказ | не предусмотрен; тупик (единственный объект разрушен, NPC убит) лечится новым подходом или объектом к тому же этапу (пункт 29) |
| Обязательный сюжетный | у каждой фракции всегда есть активный сюжетный квест: при нуле новый создаётся сразу, вне счётчика; при сбое модели — из шаблона жанра |
| Завершение | только код по условиям этапа (`service/quest.Check`, до вызова рассказчика и после привязки) → приватные события `quest_stage_done` (награда `fact` → знания персонажей фракции), `quest_done`; предмет-награда — пункт 30 |
| Цель фракции | формулировка, стадия и версия; при `/begin` первая версия от завязки; пересмотр новой версией по закрытию сюжетного квеста (`goal_revised`); выполненные этапы не переписываются; пересмотр по другим значимым событиям — пункт 29 |

## Выдача по исследованию

Счётчик и лимит считаются на фракцию (решение руководителя 2026-10-12): открытие засчитывается фракции персонажа, вошедшего в клетку первым из своей фракции; одна клетка может быть открытием для каждой фракции. После выдачи квеста счётчик фракции уменьшается на порог (лишние открытия раунда переходят в следующий интервал), после завершения любого её квеста обнуляется; закрытие этапа счётчик не трогает; запас при полном лимите не копится (обнулится завершением).

| Активных квестов фракции | Новых клеток, открытых фракцией, для следующего |
|---:|---:|
| 1 | 1 |
| 2 | 4 |
| 3 | выдача закрыта лимитом (2 сюжетных + 1 побочный) |

Старт: у каждой фракции один сюжетный квест; при открытии по одной клетке второй квест фракции (побочный) приходит после 1 клетки, третий (сюжетный) после ещё 4.

- Тип нового квеста — по свободным слотам фракции, чередование сюжетный → побочный → сюжетный.
- Не более одного нового квеста на фракцию за раунд; порог отмечается заданием на генерацию, списывается после принятия ответа.
- Открытие по шаблону (сбой модели) возможно для сюжетного, побочный при сбое просто ждёт следующего раунда.

## Влияние игроков

| Действие игроков | Реакция |
|---|---|
| Выбор направления | игрок пишет направление или место (после `/scout`); код создаёт адреса, рассказчик достраивает эту сторону и решает, что из соседей видно |
| Что пытались сделать | рассказчик получает краткие итоги заявок раунда (`Summary`, не сырой текст) и направление движения; соседи и следующий этап генерируются под интерес группы |
| Новый способ решить этап | свободное испытание интерпретатора с эффектом `{"objective": ключ этапа}` или `{"take": ключ предмета}`; код проверяет, что этап активен в клетке, считает бросок, применяет |
| Разрушили путь | задание рассказчику «восстановить путь»: новый подход или объект к незакрытому этапу |
| Противоречащие предложения групп | принимается первое по порядку сцен; остальное отбрасывается без повтора вызова |
| Известная сущность | игроки меняют неизвестные детали, не переписывают известные текстом заявки |

Новые сущности рождаются только в вызове рассказчика, который сырого текста игрока не видит; интерпретатор предлагает лишь испытание с эффектами по уже существующим ключам (связь с пунктом [25](../plan/telegram/25-prompt-injection.md)).

## Лимиты генерации за раунд

| Что | Лимит |
|---|---|
| Клетки `detailed` | до 4 (по числу групп); сверх лимита — шаблонная клетка «дорога» до следующего раунда |
| В клетке | до 2 объектов, до 1 NPC, до 2 предметов |
| Карточки соседей | все недостающие соседи клеток групп, по одному предложению |
| Квесты | не более 1 нового на фракцию; размещение этапов — по одному на незакрытый этап без клетки; цели — по одной версии на фракцию |
| Ответ модели | отдельный бюджет выхода; вход — локальный контекст ([31](../plan/telegram/31-local-context-budgets.md)) |

Сохранение результата вызова по ключу задания (`generation_jobs`, ADR-0019): повтор раунда после отката ([ADR-0013](../decisions/0013-round-resilience.md)) берёт готовый ответ, не платит дважды и не порождает другой мир; распространяется на все вызовы раунда и завязку.
