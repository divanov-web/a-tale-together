# Модель квеста, этапа и цели фракции

Поведение: [динамический мир](../world.md) («Квесты», «Выдача по исследованию»), [ADR-0020](../../decisions/0020-quests.md); эталон — сценарий S17. Таблицы `quests`, `quest_stages`, `faction_goals` (миграция `00024`), `model.Quest`, `model.QuestStage`, `model.FactionGoal`, `model.QuestTemplate`.

## Квест (`quests`)
| Поле | Значение |
|---|---|
| `faction_id` | фракция-владелец; у фракции активных сюжетных ≤ `settings.max_story_quests` (2), побочных ≤ `max_side_quests` (1) |
| `kind` | `story` — связан с целью фракции, 3–6 этапов; `side` — местная история, 2–4 этапа |
| `status` | `active` → `done` (последний этап закрыт) |
| `title`, `summary` | название ≤ 80 символов, смысл ≤ 300 |
| `created_round_id`, `done_round_id` | раунд выдачи (пусто у квеста завязки) и завершения |

## Этап (`quest_stages`)
| Поле | Значение |
|---|---|
| `stage_no`, `key` | порядок и ключ латиницей в snake_case, уникальны внутри квеста |
| `title`, `summary` | название (2–4 слова) и результат, не способ («печать у своих», а не «открыть сундук») |
| `distance` | 1–3: через сколько клеток от клетки предыдущего этапа (первый — от стартовой) этап может проявиться |
| `condition` | JSONB `{kind, object, state, fact}`: при создании квеста только `kind` из каталога, после привязки конкретика |
| `reward` | JSONB `{fact}` — одно предложение в знания персонажей фракции; предмет — пункт 30 |
| `location_id`, `status` | `pending` (без клетки) → `bound` (привязан, объекты созданы) → `done` |

Каталог условий (проверяет код, выражений от модели нет):

| `kind` | Выполнено, когда | Достижимость при размещении |
|---|---|---|
| `object_state` | объект `object` клетки этапа в состоянии `state` | подход клетки ставит объекту это состояние (`on_success.state`) |
| `fact` | факт `fact` знает хотя бы один персонаж фракции | подход клетки даёт этот факт (`on_success.fact`) |
| `visited` | клетка этапа посещена (закрывается в раунде входа) | всегда |

Недостижимое условие заменяется первым достижимым, без подходов — `visited`; при сбое модели этап размещается объектом «след» с подходом без броска и условием `fact`.

## Цель фракции (`faction_goals`)
| Поле | Значение |
|---|---|
| `version` | номер версии; строка на версию, текущая — последняя |
| `text`, `stage` | формулировка (≤ 300, без конечной точки) и стадия (одна фраза) |
| `quest_id` | сюжетный квест, по закрытию которого цель пересмотрена; пусто у первой версии (завязка) |

## Шаблон жанра
`genres.template.factions[].goal` — цель по умолчанию; `genres.template.story_quest` — сюжетный квест при сбое модели: `{title, summary, stages[{key, title, summary, distance, condition, reward}]}`.
