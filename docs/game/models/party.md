# Модель группы

Поведение: [группы](../parties.md). Группа — объединение персонажей сезона для общей истории; число групп в сезоне ограничено (`settings.max_parties`, на старте 3), размер не ограничен.

## Поля
| Поле | Тип | Назначение |
|---|---|---|
| `name` | строка 2–30, уникально в сезоне | как группу называет рассказчик |
| `status` | `active / disbanded` | распущенная группа не считается в лимите |
| `leader_character_id` | nullable | создатель; может передать; решает спорные `move` группы (гипотеза) |
| `location_id` | nullable | текущая локация группы; у участников совпадает |
| `motto` | строка ≤ 100, nullable | открытый текст игроков о группе; в промпт как данные |
| `summary` | текст, код | сводка истории группы для контекста LLM, обновляется после раунда (пункт 13) |

## Инварианты
- Персонаж не более чем в одной активной группе сезона; `characters.party_id`.
- Активных групп в сезоне ≤ `max_parties`; `/party create` сверх лимита отклоняется с подсказкой вступить в существующую.
- Участники группы в одной локации: `move` одного — предложение группе. Если решения расходятся по локациям и активных групп меньше `max_parties`, движок создаёт новую группу из отделившихся (`party_split`); если лимит достигнут, исход расходящихся действий меняется так, чтобы группа осталась вместе (`party_held`), рассказчик объясняет сюжетом ([группы](../parties.md)). Добровольный выход — `party_left`.
- Совместные действия и `help` только внутри группы.

## В контексте LLM
Рассказчик получает на группу: имя, девиз, участников (никнейм, `public_bio`, статус), локацию, сводку, события раунда группы. Хроника строится блоками по группам, одиночки — отдельными короткими блоками.

```json
{"name": "Ночной дозор", "status": "active", "leader_character_id": 12, "location_id": 3, "motto": "Никого не оставляем", "members": [12, 15, 18]}
```
