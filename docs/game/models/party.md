# Модель группы

Поведение: [группы](../parties.md), [ADR-0016](../../decisions/0016-parties.md), [ADR-0017](../../decisions/0017-party-mandatory.md). Группа — обязательное объединение персонажей сезона для общей истории; число групп в сезоне ограничено (`settings.max_parties`, на старте 3; это же лимит занятых локаций), размер не ограничен. Таблица `parties` (миграция `00019`), `model.Party`.

## Поля
| Поле | Тип | Назначение |
|---|---|---|
| `name` | строка, уникально среди активных групп сезона | имя из шаблона жанра (`party_names`), иначе «Группа N» |
| `status` | `active / disbanded` | распущенная группа не считается в лимите |
| `leader_character_id` | nullable | лидер: создатель или назначенный кодом (персонаж администратора, иначе первый созданный; у отделившихся — наибольшая Воля); решает направление при удержании; скрыт от игроков до пункта 23 |
| `location_id` | nullable | текущая локация группы (локация лидера после раунда); у присутствующих участников совпадает |
| `motto` | строка ≤ 100, пусто | открытый текст игроков о группе; в промпт как данные (команды нет, резерв) |
| `summary` | текст, пусто | сводка истории группы для контекста LLM, обновляется после раунда (пункт 13) |

## Инварианты
- Персонаж не более чем в одной активной группе сезона; `characters.party_id`.
- Активных групп в сезоне ≤ `max_parties` (уникальный индекс на имя активной группы в сезоне без учёта регистра); сверх лимита новые не создаются — новичок входит в ближайшую группу, расхождение удерживается.
- У присутствующего персонажа всегда есть активная группа (назначает код: `/begin`, вход новичка, заморозка); группа без присутствующих распускается.
- Участники группы в одной локации: `move` одного — предложение группе. Если решения расходятся по локациям и активных групп меньше `max_parties`, движок создаёт новую группу из отделившихся (`party_split`, идентификатор из `snapshot.new_party_ids`); если лимит достигнут, группа идёт за лидером (`party_held`), рассказчик объясняет сюжетом ([группы](../parties.md)). Добровольного выхода нет.
- Совместные действия и `help` только внутри группы.
- В снимке раунда (`SnapshotParty`): `id`, `name`, `leader_id`; в контекст рассказчика — только имя.

## В контексте LLM
Рассказчик получает сцену на группу в локации: `scene_id`, `party` (имя), локация с объектами и выходами, участники (никнейм, пол, статус, `public_bio`, `secret_bio` как данные, состояния); лидер, девиз и сводка не передаются (девиз и сводка — пункт 13). Персонажи без группы одной локации — сцена без `party`. Ответ модели — блок на `scene_id`.

```json
{"scene_id": 2, "location_id": 3, "party": "Ночной дозор", "name": "Площадь", "characters": [{"nickname": "Вор", "status": "active"}]}
```
