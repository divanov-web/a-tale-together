# Группы

Группа (party) — логическое объединение персонажей, для которых рассказчик пишет общую историю. Не путать с Telegram-группой (чат) и с конфликтной группой движка.

| Правило | Черновик |
|---|---|
| Число групп | до 3 групп в сезоне (`settings.max_parties`): рассказчику проще вести историю по трём группам, чем по 20 персонажам; лимит растёт по мере понимания ограничений промптов |
| Размер группы | не ограничен |
| Состав | персонаж не более чем в одной группе сезона; группа привязана к сезону; участие без группы допустимо (одиночная линия) |
| Создание и вход | `/party create <имя>`, `/party join <имя>`, `/party leave` в личке; вход по согласию группы не требуется на этапе 1 |
| Испытания | совместные действия и помощь — только внутри группы ([испытания](checks.md)); пересечение групп в одном испытании — только по сюжету рассказчика (встречные проверки между группами допустимы) |
| Хроника | рассказчик пишет историю по группам: блок на группу плюс общие события локации; одиночки — отдельные короткие блоки |
| Локация | участники группы держатся одной локации; `move` одного участника — предложение группе; если решения участников расходятся, работают правила разделения ниже |
| Разделение группы | решение руководителя 2026-10-10: если участники группы приняли слишком разные решения, ведущие в разные локации, рассказчик создаёт новую группу из отделившихся — только если лимит `max_parties` не достигнут; событие `party_split`, имя новой группы предлагает рассказчик, код проверяет уникальность |
| Лимит достигнут | если активных групп уже `max_parties`, рассказчик умышленно меняет результат действий так, чтобы группу нельзя было разделить: расходящиеся действия получают исход, оставляющий персонажей вместе (путь перекрыт, попутчик удерживает, обстоятельства меняются); событие `party_held`, в хронике объясняется сюжетом |
| Лидер группы | у каждой группы один лидер (`parties.leader_character_id`), на этапе пункта 19 скрыт от игроков: не называется в `/party`, хронике и уведомлениях (решение руководителя 2026-10-11). Назначается кодом: при `/begin` персонаж администратора, иначе первый созданный; при разделении — инициатор с наибольшей Волей; при выходе, `inactive` или `dead` лидера — следующий по тем же правилам |
| Приоритет лидера | когда лимит групп (`party_held`) или локаций не даёт участникам разойтись, движок засчитывает перемещение лидера: группа идёт туда, куда заявил лидер, или остаётся, если он не двигался; остальные заявки на перемещение получают исход «удержан», рассказчик обыгрывает это сюжетом, не раскрывая лидера |
| Выбор лидера | поздний этап (пункт [23](../plan/23-party-leader-vote.md)): участники голосуют в любой момент раунда, итог записывается при смене раунда; ничья и отсутствие голосов оставляют прежнего лидера |
| Кто решает | «рассказчик» здесь — ИИ-мастер в целом; технически расхождение локаций и свободные места в лимите определяет движок после интерпретатора (принцип 1: факты считает код), рассказчик получает событие и пишет объяснение, исходы не меняет ([два вызова LLM](../llm/round-calls.md)) |
