# Группы

Группа (party) — логическое объединение персонажей, для которых рассказчик пишет общую историю. Не путать с Telegram-группой (чат) и с конфликтной группой движка.

Реализация: пункт 19, [ADR-0016](../decisions/0016-parties.md); таблица `parties`, `characters.party_id` (миграция `00019`), движок `service/engine.settleMoves` (сценарий S14), правила `service/party`, команды `/party` в личке.

| Правило | Реализовано |
|---|---|
| Число групп | до 3 групп в сезоне (`settings.max_parties`): рассказчику проще вести историю по трём группам, чем по 20 персонажам; лимит растёт по мере понимания ограничений промптов |
| Размер группы | не ограничен |
| Состав | персонаж не более чем в одной группе сезона; группа привязана к сезону; участие без группы допустимо (одиночная линия: без помощи и совместных действий, перемещение свободно) |
| Группа по умолчанию | при `/begin` все персонажи без группы входят в одну группу с именем из шаблона жанра (`party_names`: «Ночной дозор», …); новичок в идущей игре — в группу своей стартовой локации, иначе в новую группу в пределах лимита, иначе в ближайшую по выходам группу и появляется в её локации |
| Создание и вход | `/party create <имя>`, `/party join <имя или #id>`, `/party leave` в личке, кнопки «Вступить: …» и «Покинуть группу»; вход по согласию группы не требуется на этапе 1; в идущей игре вступить можно только в группу своей локации; выход единственного участника распускает группу и освобождает место в лимите |
| Испытания | помощь (`help`) — только внутри группы, иначе отказ с объяснением ([испытания](checks.md)); совместные действия по тому же правилу с пункта 12; пересечение групп в одном испытании — только по сюжету рассказчика (встречные проверки между группами допустимы) |
| Хроника | рассказчик пишет историю по группам: сцена — группа в локации («Группа (Локация)»), общие события локации упоминаются в сценах этой локации; персонажи без группы одной локации — отдельная сцена с названием локации; «Варианты» приписываются к каждой сцене по её локации |
| Локация | участники группы держатся одной локации; `move` одного участника — предложение группе; если решения участников расходятся, работают правила разделения ниже |
| Разделение группы | решение руководителя 2026-10-10: если заявки участников ведут в разные локации, движок после фазы перемещения создаёт новую группу из отделившихся — только если лимит `max_parties` (и `max_active_locations`) не достигнут; большинство остаётся исходной группой (при равенстве — оставшиеся на месте, затем группа лидера); событие `party_split` с именем новой группы из шаблона жанра (имя от рассказчика — расширение пункта 13), идентификатор зарезервирован в снимке для воспроизводимости |
| Лимит достигнут | если активных групп уже `max_parties` (или разделение заняло бы больше `max_active_locations` локаций), группа удерживается: все участники идут туда, куда заявил лидер (без лидера — большинство), заявки на другое направление получают исход «удержан» («остаётся с группой «…»: группа идёт в «…», а не в «…»»), участники без заявки на переход уходят вместе с группой; одно событие `party_held` на группу за раунд с причиной `party_limit` или `location_limit`, рассказчик объясняет сюжетом (путь перекрыт, попутчик удерживает, уговорили) |
| Лидер группы | у каждой группы один лидер (`parties.leader_character_id`), на этапе пункта 19 скрыт от игроков: не называется в `/party`, `/status`, `/character`, хронике и уведомлениях, в контекст рассказчика не передаётся (решение руководителя 2026-10-11). Назначается кодом (`service/party.Leader`): при `/begin` персонаж администратора игры, иначе первый созданный; при разделении лидер новой группы — отделившийся с наибольшей Волей; при выходе лидера из группы, его `inactive` или `dead`, уходе с отделившимися — преемник по тому же правилу после раунда или команды |
| Приоритет лидера | когда лимит групп или локаций не даёт участникам разойтись, движок засчитывает перемещение лидера: группа идёт туда, куда заявил лидер, или остаётся, если он не двигался; остальные заявки на перемещение получают исход «удержан», рассказчик обыгрывает это сюжетом, не раскрывая лидера (сценарий S14, `TestScenario_S14_LeaderDirection`) |
| Выбор лидера | поздний этап (пункт [23](../plan/23-party-leader-vote.md)): участники голосуют в любой момент раунда, итог записывается при смене раунда; ничья и отсутствие голосов оставляют прежнего лидера. С этого пункта лидер открыт игрокам: виден в `/party`, `/status`, `/character`, смена объявляется в хронике (решение руководителя 2026-10-11) |
| Кто решает | расхождение локаций, свободные места в лимите, имя и лидер новой группы определяет движок после интерпретатора (принцип 1: факты считает код), рассказчик получает события `party_split` / `party_held` словами и пишет объяснение, исходы не меняет ([два вызова LLM](../llm/round-calls.md)) |
| Локация группы | `parties.location_id` — локация лидера после каждого раунда (`app/round.syncParties`); у участников совпадает, кроме выбывших (`inactive`, `dead`), которые остаются на месте |
