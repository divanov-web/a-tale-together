# Персонаж (rules_version: 1)

Часть [правил](rules.md). Проверки и параметр: [испытания](checks.md); автораспределение и черты по режиму: [режимы игр](game-modes.md). Числа предварительные.

## Поля
| Поле | Черновик |
|---|---|
| Привязка | сезон игры (в рассказе сезон один); у пользователя один персонаж на сезон |
| Никнейм | имя персонажа в этой игре, 2–30 символов, уникально в сезоне |
| Пол | `male`, `female` или не указан (пусто), выбирается при создании и не меняется (B18, миграция `00017`); попадает в снимок раунда и в контекст интерпретатора и рассказчика как данные (род глаголов и местоимений в хронике); не указан — рассказчик ориентируется на никнейм и описание; показывается в `/character` и `/status` |
| Архетип | из модели персонажа жанра (пример фэнтези: воин, плут, маг, дипломат, следопыт) |
| Открытое описание | до 100 символов; попадает в промпт интерпретатора и рассказчика как данные; видно другим игрокам |
| Скрытое описание | до 100 символов; попадает в контекст рассказчика как данные для подачи линии этого персонажа и в хронике не раскрывается; игрок скрыто влияет на подачу своей линии; фактов мира не создаёт |
| Фракция | одна из фракций игры ([фракции](factions.md)); выбирается при входе |
| Группа | ровно одна группа сезона у присутствующего персонажа ([группы](parties.md), `characters.party_id`, ADR-0017): при `/begin` все в одной группе, новичок — в группу своей локации, иначе в новую или ближайшую; игрок группу не выбирает; показывается в `/character`, `/status`, `/party`; лидер группы скрыт |
| Модель персонажа | справочник `character_models`: список характеристик, навыков, архетипов, стартовые очки и формула HP; задаётся жанром; значения персонажа хранятся по ключам модели |
| Характеристики | по модели; базовая модель: Сила, Ловкость, Разум, Воля от 2 до 5 на старте, сумма 14 |
| Навыки | по модели, 0–3; на старте 6 очков по архетипу, не более 3 в один (базовая модель: атлетика, бой, воровство, скрытность, внимательность, выживание, убеждение) |
| HP | 4 + Сила; при 0 «выведен из строя»; дальнейшее по режиму [смерти персонажа](death.md): по умолчанию «ненастоящая смерть» — выбытие на срок со счётчиком `death_rounds_left` |
| Состояния | ранен (−1 к параметру всех проверок), истощён (−1 к параметру, снимается отдыхом), скрыт, задержан; пока выключены флагом правил (B27, [проверки](checks.md)) |
| Инвентарь | до 6 предметов; предметы — записи с тегами, не свободный текст; предмет может давать +1…+2 к параметру подходящей проверки (стартовые предметы бонуса не дают) |
| Знания | факты, доступные персонажу; события `fact_learned` (осмотр, подходы с `fact`), хранятся в `characters.knowledge`; число в `/character`, полный список в `/knowledge` (B28) |

## Статус
| Статус | Условие | Рассказчик | Испытания |
|---|---|---|---|
| `active` | заявка в последнем раунде или пропусков меньше 3 | упоминает, ведёт линию | доступны |
| `waiting` | 1–2 раунда подряд без заявки | ещё упоминает как присутствующего (занят, ждёт) | недоступны, защитное положение |
| `leaving` | ровно `inactive_after_rounds` (3) пропусков подряд, один раунд | придумывает, что случилось с персонажем, и выводит его из повествования; это последний раунд, когда он упоминается (B13) | недоступны; не цель для PvP |
| `inactive` | больше `inactive_after_rounds` пропусков подряд | в сцены контекста не попадает, как `dead`; не упоминается | недоступны; не цель для PvP |
| `dead` | HP 0 в режиме «ненастоящая смерть» ([смерть](death.md)) | объясняет выбытие (`character_died`), по истечении `death_rounds_left` возвращает (`character_returned`) | недоступны; заявки не принимаются; пропуски не копятся |

Вход в историю (B1): персонаж, созданный в идущей игре, попадает в ближайший замороженный раунд; его первая заявка — это и есть вход в сцену: код помечает его в снимке `entry = new`, рассказчик вводит его (по `public_bio`, без новых фактов о мире) и описывает именно это действие, а не подменяет своим. Заявка не обязательна: без неё персонаж войдёт как присутствующий (`wait`) при следующей заморозке.

Возврат: заявка в любом раунде → `active`; после `leaving` или `inactive` код помечает персонажа в снимке `entry = returned`, рассказчик одной фразой объясняет возвращение и описывает действие (событие `character_returned` — только для смерти). Числа (3 раунда) — настройка `settings.inactive_after_rounds`. Переходы считает `app/round` при заморозке раунда (`activity`); отдельного события ухода нет: уход описывается по статусу `leaving` в снимке (B13), пропущенный без кворума раунд статусы не меняет, поэтому `leaving` держится до ближайшего замороженного раунда.

## Награды и прогрессия
Минимум в MVP: опыт за раунд с результатом; каждые 5 опыта +1 к одной характеристике (до +4). Пересмотр после этапа 3.
