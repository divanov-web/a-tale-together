# Глоссарий проекта

Технические термины: сущности, конвейер раунда, LLM, процесс разработки. Игровые термины (роли, мир, цикл игры): [глоссарий игры](game/glossary.md).

Термины вводит руководитель и может ошибаться в выборе слова. Если термин неточен, конфликтует с другим или есть общепринятый аналог (в Go, PostgreSQL, Telegram Bot API, архитектуре), Claude заменяет его на более подходящий во всех документах, промптах и коде, указывает замену в отчёте по задаче и в колонке «Было». Значение термина без руководителя не меняется.

| Термин | Англ. в коде | Значение | Было |
|---|---|---|---|
| Пользователь | user | Уникальный пользователь Telegram (`users.telegram_id`), писавший боту или добавивший его в чат | |
| Основные сущности | — | Чат, Игра, Пользователь, Персонаж: названы руководителем ([модель данных](architecture/data-model.md)); вспомогательные сущности Claude заводит сам | |
| Снимок раунда | round snapshot | Состояние на дедлайн: персонажи с характеристиками, локации с объектами, заявки, режим и версия правил; вход движка и интерпретатора, основа воспроизведения | |
| Намерение | intent | Структурированный разбор заявки: тип из каталога, цель, подход объекта либо параметры свободного испытания (характеристика, навык, риск, исходы обеих ветвей), форсирование, неоднозначности, запасное толкование ([round-calls.md](llm/round-calls.md)) | |
| Разрешённое действие | resolved action | Итог намерения: статус `resolved / rejected / deferred / ambiguous`, проверки, ссылки на события | |
| Событие мира | world event | Атомарное изменение состояния с видимостью; журнал только добавляется | |
| Свёртка событий | event fold | `engine.Apply`: применение событий раунда к снимку; состояние в БД равно свёртке | |
| Типовая команда | typed command | Заявка вида «глагол цель», которую умеет разобрать код без LLM (`rules.ParseTyped`); с пункта 08 это запасной путь при сбое интерпретатора, до него — основной | |
| Движок | engine | Детерминированный код правил: проверки, конфликты, применение событий | |
| Интерпретатор | interpreter | Вызов 1 из 2 на раунд, после дедлайна: все заявки раунда и контекст сцен → массив намерений JSON; сложность и бросок не назначает | |
| Рассказчик | narrator | Вызов 2 из 2 на раунд, после движка: публичные и локационные события → хроника (общий текст и блоки по командам) в группу; факты и исходы не меняет | |
| Художник | artist | Третья роль модели: вызов вне раунда, асинхронно через очередь `image_jobs` → картинка (локация, карта, аватар) в чат через outbox; факты не создаёт, секреты в промпт не получает; [план изображений](plan/images/README.md) | |
| Безопасное толкование | safe fallback | Намерение для непонятной или невалидной заявки без уточнений у игрока: `fallback` из ответа модели, иначе `wait` (G3) | |
| Свободное испытание | free check | Проверка для действия без подхода объекта: модель назначает характеристику, навык, риск и исходы обеих ветвей из списка эффектов, движок — сложность и бросок | «кастомное испытание» |
| Оценочный набор | eval set | Случаи «заявки → ожидаемые поля намерений» (`assets/prompts/interpreter/eval/cases.json`) для прогона промпта на живой модели: `make eval-interpreter`, порог 90 %; новая версия промпта — новый прогон | |
| Outbox | messages outbox | Таблица исходящих сообщений для надёжной доставки | |
| Провайдер LLM | llm provider | Реализация `Complete`: `claude-cli`, `anthropic-api`, `openai-api`, `fake`; ключ провайдера хранится в профиле | |
| Владелец бота | bot owner | Пользователь Telegram из `BOT_OWNER_ID`; единственный, кому доступны команды `/llm` | |
| Профиль LLM | llm profile | Запись в БД: провайдер, модели для ролей, параметры; выбирается для бота или игры | |
| Прогон LLM | llm run | Запись одного вызова модели: модель, версия промпта, токены, стоимость, ошибка | |
| Версия правил | rules version | Версия каталога действий и таблиц проверок, закреплённая за игрой | |
| ADR | ADR | Запись архитектурного решения в `docs/decisions/` | |
| Пункт плана | plan item | Крупный шаг `docs/plan/NN-*.md` со статусом `план / в работе / готово` | |
| Хотелка | — | Пожелание руководителя, озвученное в чате; Claude раскладывает его по документам, плану и глоссариям | |
