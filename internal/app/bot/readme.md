# app/bot
- Назначение: сценарий входящих Telegram: дедупликация по `update_id`, лимит частоты (`ratelimit.go`), учёт пользователя, реестр команд с контекстами и подсказкой в чужом контексте (`router.go`), регистрация чата по `my_chat_member`, диалоги в личке (`dialog*.go`: настройка игры — первый шаг «Стартовый мир» (`scenarioQuestion`, ADR-0028): варианты с кнопками `@scenario N` из `round.SetupOptionsText` / `SetupOptionsKeyboard`, пока их нет — ожидание без кнопок, «-» не пропускает шаг (выбор обязателен), шаг отпадает без модели или после неудачной генерации (`nextParam`, `scenarioStep`); завершение переводит мир из `setup` в `draft`, `/cancel` откладывает, `startGameSetup` возвращает к текущему шагу по `/set` без аргументов, ссылке `setup_<код>` и кнопке «Продолжить настройку» в `/status`, ADR-0023; создание персонажа — фракция, никнейм, пол (B18), архетип, очки только при флаге правил `settings.manual_attributes` (B30, иначе по архетипу), внешность (B41, необязательно), описания; состояние в таблице `dialogs`; вопрос с кнопками ответов `question` (текст `model.FormattedText`, обычный — `ask`, вступление — `prefixed`), данные кнопки `@шаг ответ` применяются только на текущем шаге), нажатия inline-кнопок как команды или ответы диалога (ADR-0015: `dispatch`, снятие клавиатуры `ClearKeyboard` кроме отказа в правах `isRightsError`), reply-клавиатура лички по статусу игрока (`keyboard.go`: `statusKeyboard` при каждом ответе в личку без inline-кнопок, подпись нажатия → команда `buttonCommand` в `dispatch`; B29, ADR-0021), ответы шаблонами `templates/` или `model.TextBuilder` (карточки с ключами жирным, B40, ADR-0030: `characterCard` по строкам `cardRows` для `/character` и `/status`).
- Публичный вход: `New(Settings, Store, Dialogs, Telegram, *chat.Service, *game.Service, *round.Service, *llm.Service, Clock, logger)` (`Settings.OwnerID` — владелец бота для `/llm`, `Settings.GuideURL` — ссылки руководства под `/help`, `Settings.AutoFaction` — фракция без вопроса при создании персонажа, шаг выбора пропускается; сейчас `good` на время тестовых прогонов), `Service.Handle`, `Service.HandleChatMember`, `Service.RegisterMenu` (меню лички, группы для всех и владельцев с модераторами всех активных чатов, B20), `Service.Commands` (всё для `/help`), `Service.Menu` (меню Telegram по контексту и правам).
- Интерфейсы потребителя: `Store`, `Dialogs` (`adapter/postgres`), `Telegram` = `Messenger` (`SendText`, `SendKeyboard`, `SendReplyKeyboard` с `model.FormattedText` — разметка entities, ADR-0029; `ClearKeyboard`) + `ChatAPI` (`IsChatAdmin`, `CreateInviteLink`, меню) (`adapter/telegram`), `Clock`, `Journal` (поле; входящие с пометкой дублей, `my_chat_member`, ответы и сбои сценариев в журнал чата, ADR-0012).
- Файлы: `cmd_basic.go` (`/start /help /me /ping /cancel`), `cmd_chat.go` (`/chat /mod /owner`), `cmd_game.go` (`/create /status /set /join /games`; в `setup` `/join` записывает участника без диалога персонажа), `cmd_hint.go` (`/hint` в личке и группе и кнопка «Подсказка»: `round.Hint`, ответ «подсказка появится в тексте рассказчика в следующем раунде (по итогам раунда N)», в группе с ником; отказы `ErrHintPending` и `HintCooldownError` текстом игроку; пункт 35, ADR-0038), `cmd_character.go` (`/character /create /bio /secret /appearance /knowledge`; `/bio` и `/secret` с текстом — через `game.SetBio` с перезарядкой 10 раундов, отказ `CooldownError` текстом игроку, `/bio` без текста — строка «Перезарядка» с остатком из `game.Cooldowns` (пункт 34, ADR-0033); краткая карточка со спутниками по группе (без её названия), статус словами `model.CharacterStatus.Word` с уточнением в скобках (B47), внешностью (если задана, B41) и числом знаний, описания и внешность — `/bio`, `/secret` или `/appearance` без текста, знания полным списком частями `knowledgeMessages`, B28), `cmd_party.go` (`/party`: карточка группы без названия и лидера — клетка и участники со статусом словами (B47), остальные группы составом; команд управления нет — группы назначает код, ADR-0017), `cmd_scout.go` (`/scout` в личке и группе: клетка персонажа и четыре направления через `round.ScoutText`, B36, ADR-0025), `cmd_away.go` (`/away` с подтверждением кнопками `yes|no` и кнопкой «Вернуться», `/back` — `round.Away` / `round.Back`; пункт 20, ADR-0026), `cmd_quests.go` (`/quests`: цель и квесты фракции персонажа, этапы ✓ / ▶ клетка и подсказка / ○; кнопок нет, пункт 28), `cmd_round.go` (`/begin /pause /finish /act` — `/begin` без подтверждения (B38; `yes` — псевдоним), `/finish` с подтверждением кнопками (`yes|no`), ответ сразу, старт и завершение делает тик планировщика (ADR-0024), `/pause` с кнопкой «Возобновить», `/act` в личке и в группе, по ссылке варианта `#…` через `round.SubmitOption`, `/say` в личке и в группе — реплика через `round.Say` (пункт 32, ADR-0027), в карточке `/round` реплики списком, `implicitAct` для текста без команды в личке вне диалога; `/next /replay /round /reset` только при `Env == dev`; строки о раундах в `/status`), `cmd_llm.go` (`/llm` с подкомандами `use reset add test`, только владелец бота).
- Итог создания персонажа (`dialog_character.go`): карточка, «что дальше» по статусу игры (B23), перед итогом подсказка с reply-клавиатурой игрока (B29), под итогом ссылка «Перейти в чат игры» (`gameChatLink` через `chat.InviteLink`; отказ Telegram — без кнопки, B24, ADR-0022).
- Ошибки сценариев из списка `userErrors` уходят игроку текстом; остальные — «Что-то пошло не так» и возврат ошибки в лог.
- Правило: обработчики тонкие, игровой логики и SQL нет; ответы на команды синхронные (ADR-0006), игровые тексты через outbox. Реестр: [telegram-commands.md](../../../docs/architecture/telegram-commands.md).
- Тесты: сквозные сценарии на `adapter/postgres/fake` (`service_test.go`; кнопки — `TestButtons_*` через `harness.press`; группы — `TestParty_*`; квесты — `TestQuests_Card`; reply-клавиатура — `TestReplyKeyboard_PlayerStatus` (7 кнопок: третий ряд «Подсказка» → `/hint`, пункт 35; «Разведка» = `/scout`); разведка — `TestScout_Card` (направления жирным, B39); реплики — `TestSay_Command`; уход и возвращение — `TestAway_Command`; карточка по строкам — `cards_test.go`; статус `setup` — `TestGame_CreateSetupAndStatus`, `TestGame_SetupPostponeAndResume`; стартовый мир — `TestGame_SetupScenario`; запуск и завершение — `harness.begin`, `harness.finish` с тиком `harness.tick`).
