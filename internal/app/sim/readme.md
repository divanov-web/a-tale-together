# app/sim
- Назначение: имитатор партии с ИИ-игроками (пункт 40, ADR-0034): оркестратор ведёт игроков по фазам (личка → создание мира администратором → вход по коду → диалог персонажа → ходы в раундах), закрывает раунд командой `/next` после хода всех присутствующих, останавливается по финальной хронике (`max_rounds`), ошибке стека или бюджету; собирает транскрипт и сводку. Бот получает входящие через подмену транспорта (`adapter/telegram/fake`) и неотличим от боевого.
- Публичный вход: `Load(path)` (сценарий `sim/runs/*.json`, `Scenario.Validate`), `New(Scenario, Settings, Transport, Handler, Store, LLM, *Journal, logger)`, `Runner.Run(ctx) (Report, error)` — отчёт возвращается и при ошибке; `Journal` (отвод журнала чатов в память: размеры промптов и ошибки для сводки), `ModelOverride` и `RoleModels` (разовая подмена модели по роли флагами; `Settings.Models` — те же подмены для модели игрока и отметки в сводке), `Runner.loadProfile` (профиль прогона из БД до старта: `sim-haiku`, `sim-sonnet`, `sim-opus-narrator`; модель игрока — флаг → `params.player_model` → `player_model` сценария; неизвестный профиль — ошибка), `Features` (каталог фич расписания: ключ, команда бота, задание; `hint` — просьба о подсказке одним игроком в раунде 5 сценария `basic`, пункт 35), `PromptVersion` (`player/v2`: `v1` + адресные ответы бота в группе, B50).
- Интерфейсы потребителя: `Handler` (`app/bot.Service`), `Transport` (`adapter/telegram/fake.Transport`), `Store` (`adapter/postgres`, `postgres/fake`), `LLM` (`app/llm.Service`).
- Сценарий: персоны (имя, username, раунд входа, характер, замысел персонажа; первый — администратор), `rounds`, `endless` (бесконечная игра, ADR-0037: `max_rounds 0`, после раунда `rounds` вместо `/next` администратор шлёт `/finish yes`; флаг `-endless`; отметка в сводке), `round_minutes` (страховочный дедлайн), `profile` (модели ролей, включая игрока), `player_model` (запасная модель игрока для профиля без `params.player_model`), `max_actions` за ход, `auto_faction`, `setup` (параметры `/set` после диалога; `round_minutes`, `max_rounds` и `min_answers 1` ставятся всегда), `features` (раунд → фичи каталога; `фича@username` — только этому игроку), `budget`.
- ИИ-игрок (`player.go`): роль LLM `player`, вход — персона, фаза, задания раунда, непрочитанные сообщения группы и лички с кнопками как данные, действия хода; выход — JSON `{action: command|button|text|done, chat, text, message_id, button, thought}`; невалидный ответ или сбой — `done`. Игрок без заявки за ход (персонаж активен и не уходит) получает запасной ход оркестратора `/act Осматриваюсь…`. Лимит частоты бота (20/мин) моделируется ведром на единицу меньше (`pace`).
- Состояние игры оркестратор читает из БД (игра, открытый раунд, заявки, персонажи, outbox), игрок видит только ящики своих чатов после доставки outbox (`drain`). Идентификаторы группы и игроков уникальны по времени запуска.
- Отчёт (`report.go`): `transcript.md` — партия по раундам (сообщения бота, действия и мысли игроков, заметки оркестратора); `summary.md` — профиль, провайдер и фактические модели ролей, раунды с метриками, вызовы по ролям из `llm_runs`, рост контекста по раундам (токены и символы из журнала), карта (клетки, посещённые), квесты и цели фракций, ошибки outbox, раундов и вызовов.
- Правило: новая команда или механика игрока → фича в `Features` (с командой бота: тест `TestFeatures_CommandsKnown` шлёт её боту и отвергает «Неизвестная команда», B52) и в расписании `sim/runs/*.json` (решение руководителя В3); промпт игрока версионируется как остальные (`assets/prompts/player/vN.md`).
- Тесты: `scenario_test.go` (сценарий репозитория, проверка, адресные фичи), `service_test.go` (сквозной прогон на `postgres/fake`, `telegram/fake` и сценарном фейке игрока без сети: три игрока, три раунда, финал; команды фич в реестре бота; `SIM_DUMP=1` печатает отчёт).
- Связи: `cmd/simulate`, `cmd/internal/stack`, [docs/dev/simulation.md](../../../docs/dev/simulation.md), `/tale-sim`, `.claude/rules/sim.md`.
- Фичи окраски действия (пункт 38, [ADR-0039](../../../docs/decisions/0039-action-flavor.md)): `flavor` — заявка с безмеханической деталью, `ask_narrator` — просьба к спутникам или рассказчику без действия; в `basic.json` по одному игроку (раунды 3 и 7).
