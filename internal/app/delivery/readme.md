# app/delivery
- Назначение: воркер outbox (ADR-0006, ADR-0009, ADR-0013): раз в интервал (`OUTBOX_TICK`, по умолчанию 3с) берёт ожидающие сообщения под `SKIP LOCKED` по порядку `id` (части длинной хроники идут подряд), отправляет в Telegram вместе с клавиатурой сообщения (`OutboxMessage.Keyboard`, ADR-0015), хранит `telegram_message_id`. Исход ошибки: окончательный отказ (`model.ErrSendRejected`: бот заблокирован, чат не найден, некорректный запрос) — `failed` сразу; просьба подождать (`model.RetryAfterError`, 429) — это и остальные сообщения прохода откладываются на `retry_after` без отправки; временная ошибка — повтор через 5с, 10с, 20с… до 5 минут, после `MaxAttempts` (30, около двух часов) — `failed`; застрявшее `sending` дольше 5 минут → `unknown` без переотправки.
- Публичный вход: `New(Store, Sender, Clock, Settings, logger)`, `Service.Run(ctx)`, `Service.Deliver(ctx)` (один проход, для тестов).
- Интерфейсы потребителя: `Store` (`adapter/postgres`: `ClaimOutbox`, `FinishOutbox`), `Sender` (`adapter/telegram.Send` с клавиатурой, классифицирует ошибки), `Clock`, `Journal` (поле; каждая попытка отправки с `outbox_id`, `part`, `attempt`, `telegram_message_id` или `error` в журнал чата получателя, ADR-0012).
- Тесты: `service_test.go` на `adapter/postgres/fake` (повтор и успех, лимит попыток, отказ, отсрочка прохода, журнал).
