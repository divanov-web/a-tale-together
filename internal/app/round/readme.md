# app/round
- Назначение: жизненный цикл раунда (пункты 05, 07–09, [ADR-0009](../../../docs/decisions/0009-round-scheduler.md)): `/begin` (стартовая сцена, первый раунд), открытие раундов по игровому окну (`window.go`), приём заявок, заморозка со снимком v2 и seed или пропуск без кворума с переносом заявок, статусы персонажей по пропускам и счётчик ненастоящей смерти, разрешение в той же транзакции (`resolve.go`: интерпретатор одним вызовом через `LLM` (`service/interpreter`, [ADR-0010](../../../docs/decisions/0010-interpreter-call.md)) или запасной разбор кодом `interpreter.Fallback` → `engine.Resolve` → `world_events`, `resolved_actions`, свёртка `engine.Apply` в состояние персонажей и объектов → рассказчик одним вызовом (`service/narrator`, [ADR-0011](../../../docs/decisions/0011-narrator-call.md)) или шаблон → `rounds.narration`, статус `published`, хроника с подходами следующего раунда частями (`chronicle.go`: `chronicleMessage`, `splitParts`) и уведомления о заявке в outbox), пауза, dev-команды `/next` и `/replay`; игровые тексты (`texts.go`) только через outbox.
- Публичный вход: `New(Store, Rights, Clock, logger)`; поля `AnnounceSkipped` (сообщение о пропуске в группу, `cmd` включает в dev) и `LLM` (`app/llm.Service`; nil — заявки разбираются кодом, хроника шаблоном); `Begin`, `Pause`, `Next`, `Submit`, `Info`, `Replay`, `Tick(ctx, now)` для планировщика; `FormatTime`, `SkippedText`.
- Интерфейсы потребителя: `Store` (`adapter/postgres`: игры под `LockGame`, раунды и `RecentNarrations`, заявки, персонажи, outbox), `Rights` (`app/game.CanAdmin`), `Clock`, `LLM` (`Complete(ctx, llm.Call, req)` для ролей `interpreter` и `narrator`; вызовы идут внутри транзакции заморозки, `/act` и `/status` их не ждут).
- Ошибки для ответа игроку: `ErrForbidden`, `ErrAlreadyStarted`, `ErrNotActive`, `ErrPaused`, `ErrFinished`, `ErrNoCharacters`, `ErrNoOpenRound`, `ErrEmpty`, `ErrTooLong`, `ErrAlreadyActed`, `ErrTooFrequent` (замена только при `settings.allow_resubmit`), `ErrDead`, `ErrNoRound`, `ErrNotResolved`.
- Правило: каждая игра обрабатывается в своей транзакции под блокировкой строки; состояние только в БД; `games.next_round_at` — единственный таймер; при сбое рассказчика хроника шаблонная, раунд не откатывается.
- Тесты: сценарии на `adapter/postgres/fake` с управляемыми часами (`service_test.go`).
