# app/round
- Назначение: жизненный цикл раунда (пункты 05, 07–10, [ADR-0009](../../../docs/decisions/0009-round-scheduler.md), [ADR-0013](../../../docs/decisions/0013-round-resilience.md)): `/begin` (завязка истории от рассказчика `opening.go` — роль `opening`, при сбое стартовая сцена шаблона жанра `openingTemplate`; текст в `games.opening_scene`; [ADR-0018](../../../docs/decisions/0018-opening-scene.md); первый раунд), открытие раундов по игровому окну (`window.go`), приём заявок, заморозка со снимком v2 и seed или пропуск без кворума с переносом заявок, статусы персонажей по пропускам (`activity`: `waiting` → `leaving` на один раунд на пороге → `inactive`, B13) и счётчик ненастоящей смерти, разрешение в той же транзакции (`resolve.go`: интерпретатор одним вызовом через `LLM` (`service/interpreter`, [ADR-0010](../../../docs/decisions/0010-interpreter-call.md)) или запасной разбор кодом `interpreter.Fallback` → `engine.Resolve` → `world_events`, `resolved_actions`, свёртка `engine.Apply` в состояние персонажей и объектов → рассказчик одним вызовом (`service/narrator`, [ADR-0011](../../../docs/decisions/0011-narrator-call.md)) или шаблон → `rounds.narration`, метрики `rounds.metrics`, статус `published`, хроника с подходами следующего раунда частями (`chronicle.go`: `chronicleMessage`, `splitParts`) и уведомления о заявке в outbox), устойчивость (`Tick` → `tickGame` с `recover` → при ошибке `noteFailure`: `rounds.attempts`, после `MaxAttempts` раунд `failed` с сообщением и переносом заявок), границы рассказа (`afterClose` → `boundary` → `finish`), автопауза после `settings.pause_after_skipped` пропущенных подряд раундов (`games.skipped_streak`, `afterClose` → `pauseAfterSkipped`; B11), личное «раунд открыт» с вариантами по локации персонажам без уведомления о заявке (`notifyOpen`, `optionsFor`; B15) и кнопками вариантов под ним и под уведомлением о заявке (`options.go`: `optionsKeyboard`, ссылка `OptionRef`, заявка по кнопке `SubmitOption`; ADR-0015), `/finish`, пауза, сброс игры в dev (`finish.go`: `Finish`, `Reset`, `Detail`), dev-команды `/next`, `/replay`, `/round`; игровые тексты (`texts.go`) только через outbox.
- Группы (`parties.go`, пункт 19, [ADR-0016](../../../docs/decisions/0016-parties.md)): `ensureDefaultParty` при `/begin` (все без группы в одну группу с именем из шаблона жанра, лидер — персонаж администратора или первый созданный, `service/party.Leader`); `ensureParties` при заморозке (присутствующие без активной группы получают её по `party.Assign`, группы без присутствующих распускаются; ADR-0017), `snapshotParties` (группы с лидером, лимит, резерв `ReservePartyIDs` на свободные места и имена шаблона → снимок v3); после свёртки `saveParties` создаёт группы из `party_split` по зарезервированным id, `saveState` пишет `party_id`, `syncParties` выравнивает лидера (преемник по тому же правилу, когда лидер выбыл), локацию группы (локация лидера) и распускает группы без присутствующих. Хроника: сцена на группу («Группа (Локация)»), одиночки локации отдельно, шаблонная хроника так же.
- Публичный вход: `New(Store, Rights, Clock, logger)`; поля `AnnounceSkipped` (сообщение о пропуске в группу, `cmd` включает в dev; идёт в одном сообщении с анонсом следующего раунда, отдельно — если раунд не открывается сразу), `LLM` (`app/llm.Service`; nil — заявки разбираются кодом, хроника шаблоном), `Journal`, `MaxAttempts` (по умолчанию `model.MaxRoundAttempts`); `Begin`, `Pause`, `Next`, `Submit`, `SubmitOption`, `Info`, `Replay`, `Finish`, `Reset`, `Detail`, `Tick(ctx, now)` для планировщика; `FormatTime`, `SkippedText`, `ParseOptionRef`.
- Интерфейсы потребителя: `Store` (`adapter/postgres`: игры под `LockGame`, раунды и `RecentNarrations`, заявки, персонажи, outbox, `DeleteGameProgress`), `Rights` (`app/game.CanAdmin`), `Clock`, `LLM` (`Complete(ctx, llm.Call, req)` для ролей `interpreter`, `narrator` и `opening`; вызовы идут внутри транзакций заморозки и старта, `/act` и `/status` их не ждут), `Journal` (поле; события `opening`, `opened`, `submission`, `skipped`, `frozen`, `interpreted`, `narrated`, `resolved`, `published`, `metrics`, `attempt_failed`, `failed`, `paused`, `resumed`, `finished`, `reset` с номером попытки в журнал группы игры, ADR-0012).
- Заморозка помечает в снимке вход персонажа (`Entry`: `new` — не было в последнем снимке, `seenCharacters`; `returned` — заявка после `leaving` или `inactive`), публикация дописывает `(@username)` после первого упоминания ника в хронике (`tagMentions`, `mentions`; B1, B2).
- Ошибки для ответа игроку: `ErrForbidden`, `ErrAlreadyStarted`, `ErrNotActive`, `ErrPaused`, `ErrFinished`, `ErrNoCharacters`, `ErrNoOpenRound`, `ErrEmpty`, `ErrTooLong`, `ErrAlreadyActed`, `ErrTooFrequent` (замена только при `settings.allow_resubmit`), `ErrDead`, `ErrNoRound`, `ErrNotResolved`, `ErrRoundClosed` и `ErrOptionGone` (кнопка варианта после закрытия раунда или исчезнувшего подхода).
- Правило: каждая игра обрабатывается в своей транзакции под блокировкой строки; состояние только в БД; `games.next_round_at` — единственный таймер; откат закрытия раунда безопасен (повтор следующим тиком), следующий раунд открывается от момента после разрешения; при сбое рассказчика хроника шаблонная, раунд не откатывается.
- Тексты игроку (`texts.go`, `chronicle.go`): заголовок отдельной строкой, пустая строка между частями, списки через «•» (B16); эталоны в `texts_test.go`.
- Тесты: сценарии на `adapter/postgres/fake` с управляемыми часами (`service_test.go`, `opening_test.go`: завязка и шаблон при сбое; `resilience_test.go`: откат и повтор, `failed`, `/finish`, границы, сброс, карточка; `pause_test.go`: автопауза; `notify_test.go`: личные варианты; `parties_test.go`: группа по умолчанию, разделение с преемником лидера и воспроизводимость, удержание; `autonomy_test.go`: 10 раундов с 5 персонажами, сбоями LLM, конвейера и Telegram, ночной паузой и `max_rounds`); интеграционные на Postgres (`integration_test.go`, `make test-integration`): остановка во время вызова модели, перекрытие тиков.
