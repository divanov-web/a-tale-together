# service/narrator
- Назначение: вызов 2 из 2 на раунд ([round-calls.md](../../../docs/llm/round-calls.md), [narrator.md](../../../docs/llm/narrator.md), [ADR-0011](../../../docs/decisions/0011-narrator-call.md)): контекст из состояния после свёртки и событий `public`/`location` (`context.go`: сцены по группам внутри локаций — `scene_id`, `party` (пусто у персонажей без группы), лидер не передаётся (пункт 19, [ADR-0016](../../../docs/decisions/0016-parties.md)); присутствующие, описания как данные, события словами, выжимка последних хроник; числа броска только в «механике»), системный промпт `assets/prompts/narrator/v3.md`, схема ответа (`schema.go`: `{chronicle, scenes[{scene_id, text, event_seqs}]}`; код подставляет локацию и подпись «Группа (Локация)» в `NarrationScene.Party`), проверка (`validate.go`: сцены по `scene_id` и `seq` из входа, пара перехода — одно упоминание, секреты не в тексте, без цифр в «повествовании», объём) → один дозапрос с замечаниями → дописывание пропусков кодом (`Narration.Patched`); утечка → `ErrLeak`, бюджет → `ErrBudget`.
- Подходы следующего раунда: `Options(state, def, mode)` (сложность по пресету режима плюс локация, шанс каждого присутствующего по параметру — для личных подсказок) и `OptionsText` — блок «Варианты» в группу: пункт на подход с новой строки, характеристика и сложность, без шансов (B6), в «повествовании» сложность словами (`rules.DifficultyWords`) и `OptionsText` для сообщения; слова событий `Describe` (у `party_split` и `party_held` актёр — группа, направление и желавшие иначе названы, лидер нет), `StateWords`, `ConditionWords`, `OutcomeWords`, `StatusWords` — общие с шаблонами `app/round`. Исчерпанные подходы (`engine.ApproachDone`, B8) не предлагаются.
- Публичный вход: `New(LLM, logger)`, `Service.Narrate(ctx, Params) (Result, error)`, `BuildInput`, `Options`, `OptionsText`, `Describe`, `Schema`, `PromptVersion`, `SystemPrompt`; интерфейс `LLM` (`Complete(ctx, model.LLMRequest)`), у вызывающего — обёртка над `app/llm.Complete` с ролью `narrator`.
- Контекст сцены несёт отметку входа персонажа `entry` (`new`/`returned`, из снимка, B1); промпт `narrator/v3` (`assets/prompts/narrator/v3.md`: `v2` + сцены по группам, `party_split` / `party_held` сюжетом без лидера и лимитов) требует ввести нового и вернуть отсутствовавшего, описав его действие.
- Правило: модель описывает, факты и исходы не меняет; текст игрока и описания персонажей — данные; при любой ошибке вызывающий публикует шаблонную хронику.
- Тесты: `narrator_test.go` на фейковом LLM; живой прогон `make eval-narrator` (`cmd/eval-narrator`, `assets/prompts/narrator/eval/cases.json`).
