# service/interpreter
- Назначение: вызов 1 из 2 на раунд ([round-calls.md](../../../docs/llm/round-calls.md), [interpreter.md](../../../docs/llm/interpreter.md), [ADR-0010](../../../docs/decisions/0010-interpreter-call.md)): свободный текст всех заявок снимка → намерения `model.Intent` одним вызовом после дедлайна. Сложность, бросок и исход — у движка; интерпретатор сущностей не создаёт.
- Устройство: `context.go` — `BuildInput(snap, def)` собирает переменную часть (`Input`: модель персонажа, сцены по локациям с выходами по направлениям и карточками видимых соседей, скрытый сосед без имени (ADR-0025), объекты с подходами, присутствующие, последние факты персонажа; заявки — данные игроков отдельным блоком) и `Encode()` в JSON; `schema.go` — `PromptVersion`, `Schema` ответа (`intents[]` с `submission_id`, `action_type`, `target`, `approach_idx` либо `attribute`/`skill`/`risk`/`on_success`/`on_fail`, `push`, `ambiguities`, `fallback`); `validate.go` — `validator` по снимку и модели персонажа: тип действия, цель (`findExit` нормализует переход в ключ направления, имя скрытого соседа не сопоставляется; `findObject`, `findCharacter`), подход, эффекты свободного испытания из каталога, `help` только рядом; `safe` — безопасное толкование (G3): запасное действие модели, если проходит проверку, иначе `wait` с причиной.
- Поток `Service.Interpret(ctx, snap, def) (Result, error)`: вызов → валидация → при ошибках один повтор с их перечнем (`Retries`) → оставшиеся заявки получают безопасное толкование (`Result.Invalid`). Ошибка только при сбое первого вызова или ответе не по схеме: тогда вызывающий разбирает заявки кодом — `Fallback(snap, reason)`: типовые команды через `rules.ParseTyped`, текст, равный названию подхода видимого объекта (кнопка варианта, ADR-0015), — этот подход, остальное `wait`.
- Публичный вход: `New(LLM, logger)`, `Service.Interpret`, `Fallback`, `BuildInput`, `Schema`, `SystemPrompt`, `PromptVersion`; интерфейс `LLM` (`Complete(ctx, model.LLMRequest)`) и адаптер `Func`; `ErrNoLLM`. Вызывающий — `app/round.interpret` внутри транзакции заморозки через `app/llm.Complete` (роль `interpreter`, запись `llm_runs`); второй потребитель — `cmd/eval-interpreter`.
- Зависимости: `model`, `service/rules` (типовые команды, каталог), `assets/prompts` (`interpreter/vN.md`, стабильный префикс для кэширования). Без I/O и времени.
- Тесты: `interpreter_test.go` — валидный ответ, повтор и безопасное толкование, отказы валидатора по таблице, сбой и `Fallback`, `TestBuildInput_NoLeaks` (секреты и чужие факты не попадают в контекст), `TestBuildInput_HiddenExit`; живой прогон `make eval-interpreter` (`cmd/eval-interpreter`, `assets/prompts/interpreter/eval/cases.json`).
