# service/engine
- Назначение: детерминированное разрешение раунда (пункт 07): `Resolve(snapshot, intents, seed)` — фазы (помощь и ожидание → перемещение → взаимодействие → итоги), проверки пулом d6 из `rand.NewPCG(seed)`, форсирование, пресеты режимов, события с видимостью, ровно один статус на заявку (`resolved | rejected | deferred | ambiguous`); `Apply(snapshot, events)` — свёртка событий в состояние; `Clone` — глубокая копия снимка (движок исходные данные не меняет).
- Поддержано: `move` (с испытанием-«воротами», если задана характеристика), `explore`, `interact` (подходы объектов: `state`, `object`+`state`, `reveal`, `fact`; `on_fail`: `condition`, `damage`, `fact`), свободное испытание без подхода (`Intent.FreeCheck`: сложность по таблице риска плюс локация, `on_success`: `fact`, `reveal`, `move` по видимому выходу; состояние объектов не меняет), `wait`, `help` (+1 кубик цели, не более +2, пока без ограничения группой); `attack`, `persuade`, `sneak`, `trade` → `rejected` с пунктом плана. HP 0 → `character_died`; счётчик 0 у `dead` → `character_returned` (docs/game/death.md).
- `ApproachDone(loc, objIdx, approach, chars)` — исчерпан ли подход для присутствующих (B8): целевое состояние или раскрытие уже достигнуто; факт (явный или описание объекта) известен каждому; `move` не исчерпывается. Использует `narrator.Options`.
- Статус `ambiguous` — только у намерения без типа; намерение с типом и `Ambiguities` (безопасное толкование интерпретатора) разрешается как обычное действие с пометкой «примечание: …» в итоге.
- Цель сравнивается с названиями по основе слова (`matches`) — для запасного разбора кодом; интерпретатор отдаёт ключи и имена из снимка.
- Правило: чистые функции без I/O и времени; новое правило — сначала сценарий в `docs/game/scenarios.md`, затем тест (`TestScenario_SNN_*`), затем код.
- Тесты: `engine_test.go` — S06, S07, S10–S13, помощь, переход с испытанием и безопасное толкование.
