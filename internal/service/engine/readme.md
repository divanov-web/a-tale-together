# service/engine
- Назначение: детерминированное разрешение раунда (пункт 07): `Resolve(snapshot, intents, seed)` — фазы (помощь и ожидание → перемещение → взаимодействие → итоги), проверки «Прямой шанс» одним броском d100 из `rand.NewPCG(seed)` (ADR-0014), форсирование повторным броском, пресеты режимов, события с видимостью, ровно один статус на заявку (`resolved | rejected | deferred | ambiguous`); `Apply(snapshot, events)` — свёртка событий в состояние; `Clone` — глубокая копия снимка (движок исходные данные не меняет).
- Поддержано: `move` (с испытанием-«воротами», если задана характеристика), `explore`, `interact` (подходы объектов: `state`, `object`+`state`, `reveal`, `fact`; `on_fail`: `condition`, `damage`, `fact`), свободное испытание без подхода (`Intent.FreeCheck`: сложность по таблице риска плюс локация, `on_success`: `fact`, `reveal`, `move` по видимому выходу; состояние объектов не меняет), `wait`, `help` (+1 к параметру цели, не более +2, только внутри группы и в той же локации); `attack`, `persuade`, `sneak`, `trade` → `rejected` с пунктом плана. HP 0 → `character_died`; счётчик 0 у `dead` → `character_returned` (docs/game/death.md).
- Группы (`parties.go`, пункт 19, [ADR-0016](../../../docs/decisions/0016-parties.md), S14): переходы копятся в `proposals` и сверяются `settleMoves` после фазы перемещения (и ещё раз в конце для переходов по эффектам испытаний): расхождение участников группы → большинство остаётся исходной группой (при равенстве — оставшиеся на месте, затем группа лидера), остальные по локациям назначения становятся новыми группами `party_split` (id из `snapshot.new_party_ids`, имя `party.NextName`, лидер `party.SplitLeader`) в пределах `max_parties` и `max_active_locations`; первая блокировка → одно `party_held` на группу с причиной `party_limit` / `location_limit`: все идут за лидером (без лидера — за большинством), заявки на другое направление получают `Outcome = held` и итог «остаётся с группой…», участники без заявки уходят с группой событиями `character_moved` без итога. `Apply` воспроизводит `party_split` (`applySplit`). Персонаж без группы перемещается свободно.
- `ApproachDone(loc, objIdx, approach, chars)` — исчерпан ли подход для присутствующих (B8): целевое состояние или раскрытие уже достигнуто; факт (явный или описание объекта) известен каждому; `move` не исчерпывается. Использует `narrator.Options`.
- Статус `ambiguous` — только у намерения без типа; намерение с типом и `Ambiguities` (безопасное толкование интерпретатора) разрешается как обычное действие с пометкой «примечание: …» в итоге.
- Цель сравнивается с названиями по основе слова (`matches`) — для запасного разбора кодом; интерпретатор отдаёт ключи и имена из снимка.
- Правило: чистые функции без I/O и времени; новое правило — сначала сценарий в `docs/game/scenarios.md`, затем тест (`TestScenario_SNN_*`), затем код.
- Тесты: `engine_test.go` — S06, S07, S10–S13, помощь внутри группы, переход с испытанием и безопасное толкование; `parties_test.go` — S14 (разделение, удержание, направление лидера, лимит локаций).
